# 这是什么

mini-canvas 是一块**画布**：能放大缩小、能用鼠标拖着走的白板，上面可以摆一张张卡片
（叫做**节点**），卡片和卡片之间能拉线连起来。

它最大的特点是：**画布本身几乎什么都不做，功能全都靠插件装上去。**

打两个比方，记住一个就行：

- **像一块乐高底板**：底板只负责把插块卡住。要房子、要小车、要飞机，插块说了算。
- **像一部手机**：手机买来只是块屏幕加个系统，能干什么取决于你装了哪些 App。

画布自己只干三件事：**装插件、让插件互相借能力、记住谁往哪儿放了什么。**
你在画布上看到的一切 —— 文本节点、图片节点、右键菜单、小地图、AI 对话面板 ——
全是插件放上去的。

## 前台和后台

这是 mini-canvas 和一般画布最不一样的地方：插件**两边都能写**，用的是同一套写法。

| | 前端插件 | 后台插件 |
| --- | --- | --- |
| 跑在哪 | 浏览器（画布界面里） | Node（cloud-server 进程里） |
| 能干什么 | 节点、UI、命令、配置、服务 | HTTP 接口、定时任务、私有存储、给 AI 加工具 |
| `ctx` 上有什么 | `nodes` / `slots` / `commands` / `theme` / `settings` | `routes` / `store` / `jobs` / `mcp` / `agent` |
| 举例 | 「给节点底栏加个按钮」 | 「给后台加一个查询接口」 |

两边写法完全一致（`export const name / inject / apply`），只是 `ctx` 上的插座不同。
极简实战会带你两边各写一个，让它们互相配合：
