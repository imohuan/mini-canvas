# 常见坑（复盘沉淀）

> 插件：可视化节点 node-ui · [返回总览](/plugins/parsed/node-ui/)

**一句话**：这一页是 AI 写界面时最容易踩的几条，都是真机上撞出来的。

## 给 AI 的七条

1. **别去翻项目源码**。手册给的是**稳定契约**，源码是**实现**、随时会变。
   要"有哪些脚本 / 动作"用运行时接口（`{type:"list"}`、`generation_actions`），或直接看手册尾部那两节（都现读）。
2. **看到"可视化节点 / ui 节点 / 面板"第一个动作是 `canvas_ui_guide`**，
   别和"生成图片"（`generation_*`）混起来：那是调模型出媒体，这是画界面，**两条轨道**。
3. **产物一律走宿主通道**（`CanvasUI.save` / `ctx.save`），
   别自己跨源 `POST /api/canvas/nodes` 当主路 —— 沙箱是不透明源，会**静默失败**。
   **2026-10-20 起**：界面里读画布 / 下单 / 改节点也要走 `CanvasUI.api(path, init)`，
   不要直接 `fetch` —— 后台的请求边界会拒绝 `Origin: null`，而管理令牌不该交给沙箱页面。
4. **新建带后台能力的节点，主动写 `data.uiScripts`**，别指望自动补。
5. **一个节点一份产物**（槽位覆盖）；上游产物会同时出现在"注入素材"和"节点字段"两条路上，
   展示端必须按**干净 URL** 合并去重、按**扩展名**判类型。
6. **改一小块用 `canvas_ui_update`**（old → new），不要整段重写。
7. **长任务把 `runId` 写进节点字段**，刷新后还能接上订阅。

## 开发期撞出来的坑（写实现时别重踩）

| 坑 | 现象 | 修法 |
| --- | --- | --- |
| 虚拟画布提示写错 | 说"它会自己开一张虚拟画布取数据" —— **是错的** | 虚拟画布只有 `canvas_fn_call` 用；建收藏节点走的是真实目标画布 |
| 依赖声明没并进同一次写盘 | 界面照写、返回值正常，但**声明空着**（之后一点就 403） | 声明必须与 `uiHtml` **同一次写盘**交上去 |
| `canvas_ui_write` 第一版不带 `extra` | 带数据建节点（导入包）**静默丢字段**，节点建出来是空的 | `create(position, extra)` 必须带上 `extra` |
| 轮询中删节点 | 页内 `PAGEERROR [nodeStore] no node` | `writeRuntime` 对不存在的节点**静默跳过**（任务还在跑，只是没地方写进度） |
| 等待比脚本超时短 | 报出来的是"等超时了"，把脚本自己的报错盖掉 | 等待比脚本超时**多留 5 秒** |

## 注意事项

1. **报错要带"可用的有哪些"**：例如"脚本 scale 里没有导出函数 run（可用的：run2、debug）" ——
   否则调用方只能猜自己写错了哪个字母。
2. **别把能力藏起来**：函数没写说明书**照样列出来**（标一句"没写说明书"），不因为作者偷懒就整个不可见。
