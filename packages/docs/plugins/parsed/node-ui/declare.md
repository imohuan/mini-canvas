# 依赖声明与 403

> 插件：可视化节点 node-ui · [返回总览](/plugins/parsed/node-ui/)

**一句话**：界面想调某个脚本，节点上必须**先声明依赖**（`data.uiScripts`）—— 不声明，后台直接 `403`，连进程都不起。

## 声明长什么样

```json
data.uiScripts = { "scale": {}, "video-grid": {} }
```

键是脚本名，值是它的内容摘要（`sha256` / `at`，打包与诊断用）。

## 为什么要有这一关

`nodeId` 是调用方自己填的 —— 不核对等于**谁都能调这台机器上的任何脚本**。
所以 `/api/task/call` 会按 `canvasId + nodeId` 把节点读出来核对声明，没有就 403。

## 两个来路（都要过同一份合并逻辑）

1. **AI 自己写的**（经 `canvas_batch_nodes` 直接写 `data.uiScripts`）—— **优先，不覆盖**；
2. **后台顺手扫的**：`canvas_ui_write` / `canvas_ui_update` 写完界面，
   扫一遍 HTML，把调到的脚本名补进声明 —— **兜底**。

### 为什么必须有第 2 条

**AI 会忘。** 而忘了的后果不是"少写一行"这么轻 —— 是界面画出来了、用户点一下**403**，
而 AI 从画面上完全看不出哪里错（2026-10-13 用户确认的"双保险"）。

扫的时候**只认这台机器上真实存在的脚本名**：界面里到处是 `name: "xxx"`（给 input 起名、给变量起名…），
不过滤会收进一堆噪音。

## 合并规则：已有的不丢，新发现的补上

- AI 自己写的那份更可信（它知道界面真正依赖什么），后台扫出来的只是"猜"，**扫漏了不该把 AI 写的冲掉**；
- `sha256` 同理：已有值优先，避免每次改界面都把哈希刷成"当时那份"。

## 长任务：建议把 runId 写进节点字段

调用时**建议带上 `runId` 写进节点字段**（长任务）—— 页面刷新后还能接上订阅。

## 注意事项

1. **自己写上更稳**：虽然 `canvas_ui_write/update` 会自动补，但那是兜底，不是让你偷懒。
2. **声明是"授权"不是"配置"**：不加声明 ≠ 少个字段，而是这道调用会被硬拒。
