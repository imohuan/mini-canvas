# 注册场演示：点一点就懂

**左边是场**（按「种类」放一串条目），**右边是画布上看到的结果**（一张卡片）。

下面这一台是**能动手玩的**：点按钮就往场里真的加一条 / 删一条 / 改 order，右边的卡片会跟着平滑地动。
而且它用的**不是假表** —— 是项目内核里那个真的注册场（`RegistryImpl`），跟画布自己用的是同一个。

## 怎么玩

想看懂四条规矩，按下面顺序点一遍最快：

1. **加一条** —— 换个颜色、把 order 填小一点（比如 5），它会跑到卡片最上面、盖住别人。
   这就是「**order 越小 = 越靠外**」。
2. **改 order** —— 在表格里把某一条的 order 改小，或者点「顶到最外」。同一批条目会原地重排，
   谁在最外面会换人。
3. **同 id 再加一次** —— 条数**不变**，只是那条被换了个颜色。这是「**同 id 再放 = 换掉那条，不是新增**」。
4. **包一层（wrap）** —— 新来的层会**包住**下面那层，卡片下面那行 `resolve` 会显示「套完之后是什么」。
5. **删掉 / 清空** —— 把最外面那条删掉，**底下的层还在**（不会一起没）。这就是「永不覆盖，只往栈上叠」。

看表格：它按 order 从小到大排，**排第一行的就是最外面那条**（写着「赢家」），
颜色也跟卡片上最上面那层对得上。

## 四条规矩，一句话一条

- **order 越小 = 越在外层 = 优先级越高。** 谁「赢」就看它。
- **同 id 再放 = 替换。** 同一个人（同一个放置方）放同一个 id，是换掉自己那条，不是叠一层。
- **不同 id 放同一个种类，互不覆盖。** 底层永远还在，删掉上面的就露出来。
- **wrap 是「包住」而不是「盖住」。** 它拿到下面那层，包一层再交出去；`resolve` 给你套完的结果。

## 这一页背后调的就是这几行

点每个按钮时，跑的都是下面这些真方法（不是示意图，是照着这一页的代码抄的）：

```ts
import { RegistryImpl } from '@mini-canvas/kernel'

const field = new RegistryImpl<东西>()          // 一个场

// 加一条：同 id 再放 = 换掉那条
field.add('over:inset', 值, { id: '角标-云盘', order: 10 })

// 按 id 删一条
field.remove('over:inset', '角标-云盘')

// 读：整摞按 order 升序（第一条 = 最外面那条）
field.list('over:inset')      // → [{ id, value, order, source }, …]
field.top('over:inset')       // → order 最小的那一条（赢家）

// 包一层：不写 order 就默认放最外（当前最小 - 1）
field.wrap('over:inset', (inner) => 把 inner 包起来)

// 逐层套完的结果；场里一条都没有时给的就是那个兜底值
field.resolve('over:inset', 场外兜底值)

// 变了通知我（这一页就是靠它重画的）
field.subscribe(() => 重画())
```

真实插件里，`field` 是从 `ctx.registryOf<东西>('种类名')` 拿的；
这里直接 `new RegistryImpl()`，是因为演示页没有画布宿主，但**表和条目完全一样**。
