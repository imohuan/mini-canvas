# 这个项目是什么

mini-canvas 是一块**画布**：能放大缩小、能用鼠标拖着走的白板，上面可以摆一张张卡片
（叫做**节点**），卡片和卡片之间能拉线连起来。

它最大的特点是：**画布本身几乎什么都不做，功能全都靠插件装上去。**

打两个比方，记住一个就行：

- **像一块乐高底板**：底板只负责把插块卡住。要房子、要小车、要飞机，插块说了算。
- **像一部手机**：手机买来只是块屏幕加个系统，能干什么取决于你装了哪些 App。

画布自己只干三件事：

1. **把插件装起来、卸下去**（装载）。
2. **让插件之间互相借能力**（服务）。
3. **记住谁往哪儿放了什么**（注册场）。

除此之外，你在画布上看到的一切 —— 文本节点、图片节点、右键菜单、小地图、
默认皮肤、AI 对话面板 —— 全都是插件放上去的。**一个都不是画布硬写的。**

## 为什么要这么设计

作者的原话：

> 当前的问题就是没有一个很好的底子，功能全是堆砌上去，最开始是想分工明确，
> 可越是做到后面越是混乱，因为很多功能都需要其他的地方支持，这就又需要我提供新的 api 功能。

病根有两条：

- **位置是数出来的，不是开放出来的。** 想给节点加个按钮，只有固定的几个位置能加，
  加不了就得去改节点的核心组件。
- **新功能只能靠加服务。** 手上没有通用的"放东西"机制，于是每加一类东西，
  就再写一个新服务、再写一套 API。

这套系统给出的解法是三个词：

| 词 | 一句话 | 效果 |
| --- | --- | --- |
| **三根轴** | 装载轴 / 服务轴 / 注册轴 | 混乱的来源被收成三类，能记全了 |
| **七个原语** | 插件作者只用学 7 样东西 | 学的东西少了 |
| **注册场** | 按"种类"放一串条目，不新增服务 | **加功能不用改核心、不用加 API** |
