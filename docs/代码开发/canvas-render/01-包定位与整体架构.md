# canvas-render 开发手册 · 包定位与整体架构

> 来源：`packages/canvas-render/src/`（index.ts、host/*、contracts/*、components/*、vueFlowBridge.ts、utils/coalesce.ts），
> 以及内核 `packages/canvas-core-v2/src/`（core/index.ts、services/index.ts、Context.ts、capabilities.ts、registry/*、settingsStore.ts）
> 与插件 `packages/plugins/plugin-*` 的 src。

本手册写给开发 mini-canvas 画布的开发者。目标是：**你照着文档就能把一个能用的画布应用搭起来**，并且知道每个功能点是怎么来的、为什么这么做。会先讲概念，再给结论和可跑的代码。

---

## 一句话：canvas-render 是什么

`canvas-render` 是把"画布内核"接到 **Vue + VueFlow 浏览器画布**上的那层桥。

分三层理解：

1. **内核 `@mini-canvas/canvas-core-v2`**：纯逻辑、零 Vue、零浏览器。管节点数据、边数据、撤销历史、选中、命令、持久化、插件装载。它不知道"屏幕上怎么画"。
2. **渲染层 `@mini-canvas/canvas-render`（本包）**：把内核装进 Vue。它负责——建内核宿主、把内核里存的节点/边翻译成 VueFlow 要的格式、提供 6 个"注入令牌"让插件的内容组件能拿到内核上下文、渲染画布组件 `CanvasHost`、以及设置面板/通用槽这些 UI 宿主。
3. **插件 `packages/plugins/*`**：真正的内容与外观。如 `plugin-node-text`（文本节点）、`plugin-node-image`（图片节点）、`plugin-theme-default`（默认皮肤：节点壳/连线/背景/设置面板）。

依赖方向（只有一条单向链，没有循环）：

```
@mini-canvas/canvas-core-v2   （纯内核，谁都不依赖）
        ▲
@mini-canvas/canvas-render    （runtime 依赖内核；把内核接到 Vue/VueFlow）
        ▲
plugins/* （node-text/node-image/theme-default）
```

> 关键点：**渲染插件（theme-default 的节点壳/连线）不直接 import `@vue-flow/core`**，而是从 `canvas-render` 的 `vueFlowBridge` 拿 VueFlow 原语（Handle、Position、useVueFlow、EdgeProps 等）。这么做的原因见下面 `vueFlowBridge` 一节——能避免"一份 @vue-flow 被两份依赖装出双实例"的 Bug。

## index.ts 导出了什么（功能清点总表）

`index.ts` 是包的唯一出口，逐类看它导出的东西，就基本知道这个包的全部功能点：

| 分类 | 导出 | 一句话用途 |
|------|------|-----------|
| 渲染注入令牌（contracts） | `HOST_KEY` | 拿宿主句柄引用（旧写法，新代码用 `useCanvasRender`） |
| | `NODE_REGISTRY_KEY` / `NODE_WRITE_KEY` / `NodeWrite` | 节点展示注册表 + 标题写回回调 |
| | `CANVAS_PARAMS_KEY` / `CanvasParams` | 浮动端口外观参数 |
| | `EDGE_VISUAL_KEY` / `EDGE_SELECTION_KEY` / `EdgeVisual` / `EdgeSelection` | 边外观 + 选中态 |
| | `RENDER_CONTEXT_KEY` / `useCanvasRender` / `CanvasRenderContext` | **新代码首选**的统一渲染上下文 |
| VueFlow 精选出口 | `vueFlowBridge`（`export *`） | Handle/Position/getBezierPath/useVueFlow/EdgeProps/NodeProps |
| 渲染宿主组件 | `CanvasHost`（默认导出） | 一行渲染的官方宿主组件 |
| 设置面板类型与宿主 | `SettingsPanelSource`/`SettingSchema`/`SettingEntry`、`SettingsHost`、`settingsSourceFrom` | 设置面板数据契约 + 可替换设置面板宿主 + 适配入口 |
| 通用槽宿主 | `SlotHost` | 给槽名就渲染该槽全部 occupant |
| store→flow 纯逻辑 | `FlowNode`/`ThemeAssembly`、`nodesFromStore`/`pruneDanglingEdges`/`assembleTheme`/`edgeId`/`DEFAULT_EDGE_VISUAL`/`DEFAULT_HANDLE_VISUAL` | 把内核节点灌成 VueFlow 数组、主题装配、默认外观 |
| 宿主门面 | `createMiniCanvasHost`/`MiniCanvasOptions`/`MiniCanvasApi`/`CanvasHostHandle` | 建宿主 + window.MiniCanvas 装配门面 |
| 插件管理器 | `createPluginManager`/`PluginManager`/`PluginEntrySource`/`PluginManifest`/`PluginManifestEntry`/`InstalledPluginInfo` | 统一安装句柄（热装/热卸/重载/manifest） |
| 合帧工具 | `createCoalescer`/`rafScheduler`/`manualScheduler`/`CoalesceScheduler` | 高频值合并成一帧再应用 |

## 两大入口，怎么选

**① 声明式（推荐给 Vue 应用）**：用 `<CanvasHost>` 组件。
你只要告诉它"装哪些插件"和"要不要默认种子"，剩下的内核装配、VueFlow 渲染、令牌提供、交互、落盘它全包了。典型用法见《02》和《09》。

**② 命令式（推荐给非 Vue 环境 / 你要完全掌控）**：用 `createMiniCanvasHost()`。
它返回一个内核宿主 `host` + 插件门面 `api`，你可以脱离 VueFlow 自己操作内核（做测试、做服务端、或自己手写渲染）。`<CanvasHost>` 内部其实也是调它。

> 通常：想让屏幕上有画布 → 用 `<CanvasHost>`；想在 Node 里建宿主测试逻辑、或想拿到内核句柄手动建节点 → 用 `createMiniCanvasHost`。

## 内核暴露的"服务"（render 层依赖的东西）

`CanvasHost`/`createMiniCanvasHost` 启动时往内核 `Context` 里 `ctx.inject` 了这些服务（名字是固定字符串）。插件与内容组件可以用 `ctx.get('名字')` 或 `ctx.名字` 取到（后者靠类型增强，见 plugin 源码的 `declare module`）。

| ctx 服务名 | 类型 | 职责 |
|-----------|------|------|
| `save` | `SaveServiceImpl` | 持久化（落盘/恢复） |
| `nodeStore` | `NodeStore` | 节点数据：增删改、订阅 |
| `edgeStore` | `EdgeStore` | 边数据：增删、删节点清边（边下沉内核后的唯一数据源） |
| `nodeRegistry` | `NodeRegistry` | 展示注册表：type → content/title/… 段组件 |
| `themeRegistry` | `ThemeRegistry` | 主题注册表：nodeShell/edge/background/… |
| `selection` | `Selection` | 节点选中态（单源） |
| `history` | `History` | 撤销/重做（全图快照，含边） |
| `command` | `CommandRegistry` | 命令（`command:delete`/`command:create-node`/`command:undo`/`command:redo` 等） |
| `nodeFactory` | `NodeFactory` | 按 type 建节点的实现（来自插件 `create`） |
| `slots` | `SlotRegistry` | 通用 UI 槽容器（ctx.slots 写这里） |
| `settings` | `SettingsStore` | 分组配置单一数据源（ctx.settings 写这里） |

另外 `Context` 上还挂了几个"能力段"（注册自动回收，卸载即清）：
- `ctx.nodes.register(def)` —— 注册一个节点类型（数据+展示+可选 create，见 capabilities.ts 的 `NodeRegisterDef`）
- `ctx.theme.register(slot, comp, opts)` —— 往主题槽放一个 occupant
- `ctx.commands.register(def)` —— 注册命令
- `ctx.slots.register(slot, req)` —— 往通用 UI 槽放 occupant
- `ctx.settings.set/get/onChange/groups()` —— 读写已装配配置

> 细节：`canvas-core-v2` 的 `core/index.ts` 与 `services/index.ts` 把内核全部能力导出。插件写 `Service 子类`时用的 `Service`/`PluginModule`/`Context` 类型来自 `@mini-canvas/canvas-base`（它 re-export 内核 core 部分）。

## 一个"把内核接上 Vue"的最小心智模型

```
你的 Vue 组件
   └─ <CanvasHost :plugins="[theme, text, image, commands]" />
         │ ① onMounted 时调 createMiniCanvasHost 建内核宿主 host
         │ ② host.ctx 里已 inject 好上面那张服务表
         │ ③ boot 完成后挂载内层 <CanvasSurface>
         │        ├─ provide RENDER_CONTEXT_KEY（裸 ctx + host + 外观）
         │        ├─ provide 旧 6 个 *_KEY（兼容）
         │        └─ 渲染一个 <VueFlow>
         │              ├─ node-types：themeRegistry 的 nodeShell（如 BaseNode）铺满每个业务 type
         │              ├─ edge-types：themeRegistry 的 edge（如 CustomEdge）
         │              └─ 背景/默认边 type 也从 themeRegistry 取
         └─ CanvasHost 订阅 nodeStore/edgeStore/selection 变化 → 自动重灌 VueFlow 渲染态
```

插件侧（比如 text 插件 `apply(ctx)` 里）会：
1. `new TextService(ctx)` 上架 `ctx.text` 服务（建/改文本节点的逻辑）；
2. `ctx.nodes.register({ type:'text', size, content: TextContent.vue, create })` —— 数据侧注册进 nodeStore，展示侧把 `TextContent.vue` 塞进 nodeRegistry；
3. `TextContent.vue` 在 setup 里 `useCanvasRender()` 拿到裸 `ctx`，然后 `ctx.text.editText(id, text)` 把编辑写回内核并落盘。

这样"数据在内核、怎么画在插件、桥在 render、装配在 CanvasHost"，各管一段。

## 潜在坑（先给结论）

1. **别在生产代码里逐个 `inject(HOST_KEY)!`**。HOST_KEY 是 `Ref` 形态，读值要 `.value` 还可能要判空。新组件一律 `useCanvasRender()`，返回的是裸 ctx/host，零判空。
2. **nodeTypes 的组件句柄要用 `markRaw`/`shallowRef`**，否则 Vue 会把 .vue 组件对象深代理，触发"组件被 reactive 化"警告。（CanvasHost 已处理，你手写渲染时才要注意。）
3. **content 组件拿 `props`**：BaseNode 给 content 段传 `{ id, data }`（见 TextContent/ImageContent）。content 只用展示 + 调服务写回，连接点 Handle 由 BaseNode（nodeShell）统一提供，content 不画 Handle。
4. **`ctx.get('xxx')` 取不到会返回 undefined**（P6 语义），别再当成必然存在用。服务缺失会静默，要用插件的 `inject` 硬依赖声明（见 nodeTextPlugin 顶部 `inject:['nodeStore','save']`）。
