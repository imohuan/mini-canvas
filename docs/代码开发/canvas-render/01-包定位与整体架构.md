# canvas-render 开发手册 · 包定位与整体架构

> 来源：`packages/canvas-render/src/`（`index.ts`、`host/*`、`contracts/*`、`components/*`、`vueFlowBridge.ts`、`utils/coalesce.ts`、`layout/nodeLayout.ts`、`viewport/viewportService.ts`），
> 数据层 `packages/canvas-data/src/`，插件框架 `packages/kernel/src/`，以及插件 `packages/plugins/*` 的 src。

本手册写给开发 mini-canvas 画布的开发者。目标是：**你照着文档就能把一个能用的画布应用搭起来**，并且知道每个功能点是怎么来的、为什么这么做。会先讲概念，再给结论和可跑的代码。

---

## 一句话：canvas-render 是什么

`canvas-render` 是把"画布数据层"接到 **Vue + VueFlow 浏览器画布**上的那层渲染宿主。

分四层理解（依赖方向单向）：

1. **插件框架 `@mini-canvas/kernel`**：纯插件框架。管插件装载、依赖编排、事件、作用域回收（副作用自动清理）、注册场原语、配置。零画布概念、零 Vue。
2. **数据层 + 画布语义 `@mini-canvas/canvas-data`**：管节点数据、边数据、事务与撤销、选中、持久化、连线校验、节点/主题注册表，以及 `ctx.nodes/theme/commands/slots/settings` 这几段糖。零 Vue。
3. **渲染层 `@mini-canvas/canvas-render`（本包）**：把上面两层装进 Vue。它负责——建宿主（`createMiniCanvasHost`）、把数据里的节点/边翻译成 VueFlow 要的格式、通过**统一渲染上下文**让插件的内容组件拿到内核能力、渲染画布组件 `CanvasHost`、以及设置面板/通用槽这些 UI 宿主。它额外注入两个只有渲染层才做得到的服务：`nodeLayout`（要量 DOM）与 `viewport`（要挂 VueFlow 后端）。
4. **插件 `packages/plugins/*`**：真正的内容与外观。如 `plugin-node-text`（文本节点）、`plugin-node-image`（图片节点）、`plugin-theme-default`（默认皮肤：节点壳/连线/背景/设置面板）。

作者写插件只认一个薄入口 `@mini-canvas/canvas-base`：它重导出 kernel 与 canvas-data 的类型和 `define*` 助手。
成品应用出口是 `@mini-canvas/ui`（一行 `mountCanvasApp()` 或 `<CanvasApp/>` 出整套画布应用）。

依赖方向（只有一条单向链，没有循环）：

```
@mini-canvas/kernel       （纯插件框架，不依赖任何 @mini-canvas 包、零 Vue）
        ▲
@mini-canvas/canvas-data  （数据 + 画布语义；把插件框架长成画布引擎）
        ▲
@mini-canvas/canvas-render（渲染宿主；把内核接到 Vue/VueFlow）
        ▲
packages/plugins/*        （业务节点 / 主题皮 / 交互工具）
        ▲
@mini-canvas/ui           （成品应用出口）
```

> 关键点：**渲染插件（theme-default 的节点壳/连线）不直接 import `@vue-flow/core`**，而是从 `canvas-render` 的 `vueFlowBridge` 拿 VueFlow 原语（`Handle`、`Position`、`useVueFlow`、`useConnection`、`EdgeProps` 等）。这样做能避免"一份 @vue-flow 被两份依赖装出双实例"的 Bug——详见《08 vueFlowBridge 与 coalesce》。

## 两大入口，怎么选

**① 声明式（推荐给 Vue 应用）**：用 `<CanvasHost>` 组件。
你只要告诉它"装哪些插件"和"要不要默认种子"，剩下的内核装配、VueFlow 渲染、上下文提供、交互、落盘它全包了。典型用法见《02》和《09》。

**② 命令式（推荐给非 Vue 环境 / 你要完全掌控）**：用 `createMiniCanvasHost()`。
它返回一个宿主 `host` + 插件门面 `api` + 统一安装句柄 `manager`，你可以脱离 VueFlow 自己操作数据（做测试、做服务端、或自己手写渲染）。`<CanvasHost>` 内部其实也是调它。

> 通常：想让屏幕上有画布 → 用 `<CanvasHost>`；想在 Node 里建宿主测试逻辑、或想拿到宿主句柄手动建节点 → 用 `createMiniCanvasHost`。

## 渲染层注入/新增的"服务"（`ctx.get`）

`createMiniCanvasHost` 启动时建 `Context`，装 `canvas-base`（画布基础插件，它自带画布数据与语义服务），再补渲染层两件，最后冷启动业务插件。装完 `ctx.get('名字')` 能拿到的服务如下：

| ctx 服务名 | 谁提供 | 职责 |
|-----------|------|------|
| `doc` | canvas-data | **数据唯一门面**：节点 + 边 + 事务/撤销/快照/订阅一个名字 |
| `save` | canvas-data | 持久化（落盘/恢复） |
| `resources` | canvas-data | Blob / objectURL 生命周期（引用登记与回收） |
| `nodeRegistry` | canvas-data | 节点展示注册表：type → 各区域组件 |
| `themeRegistry` | canvas-data | 主题槽注册表：nodeShell/edge/background/… |
| `selection` | canvas-data | 选中态（节点桶 + 边桶） |
| `command` | canvas-data | 命令注册表（快捷键由渲染层统一分发） |
| `nodeFactory` | canvas-data | 按 type 建节点的实现表 |
| `settingsPersist` | canvas-data（条件注入） | 配置落盘桥；`persistSettings` 关掉时不存在 |
| `tools` | kernel 自带 | 生成工具注册表（文生图/文生文等外部能力，按名调用） |
| `slots` / `settings` | canvas-data 能力层内置 | 通用 UI 槽容器 / 分组配置单一数据源 |
| `nodeLayout` | **canvas-render（本包）** | 节点实测尺寸 + 绝对坐标（只读） |
| `viewport` | **canvas-render（本包）** | 视口读/控 + 屏幕坐标 ↔ 画布坐标换算 |

> **注意：老服务名 `nodeStore` / `edgeStore` / `graph` / `history` 已下线**——数据统一收口到 `doc` 一个服务；拿这些老名去 `ctx.get` 取不到东西（返回 `undefined`）。
> 但那四个**实例**并没有消失：它们由 `canvas-base` 建好后（1）交给 `doc` 门面持有、（2）**直接挂在宿主句柄 `host` 上**。
> 所以 `host.nodeStore.getNodes()` 合法（那是宿主句柄的字段）；而用老名去 `ctx.get` 取不合法（那不再是服务名）。两者是两回事。

**宿主句柄 `CanvasHostHandle`（`host`）上的字段**（`host/createMiniCanvasHost.ts`）：

```ts
ctx / save / doc / nodeStore / edgeStore / nodeRegistry / themeRegistry /
selection / command / history / nodeFactory / graph / nodeLayout / viewport /
settingsPersist? / resources / stop()
```

`stop()` 会先 `save.flush()` 把脏数据推进落盘流程，再回收全部插件副作用。

另外 `Context` 上还挂了几个"能力段"（注册自动回收，卸载即清）：

- `ctx.nodes.register(def)` —— 注册一个节点类型（数据 + 展示 + 可选 `create`）
- `ctx.nodes.attach(type, req)` / `ctx.nodes.contribute(...)` —— 往节点的十个区域词挂组件（见《05》与总览的"区域词"）
- `ctx.theme.register(slot, comp, opts)` —— 往主题槽放一个 occupant
- `ctx.commands.register(def)` —— 注册命令
- `ctx.slots.register(slot, req)` —— 往通用 UI 槽放 occupant
- `ctx.settings.get/set/onChange/groups()` —— 读写已装配配置
- `ctx.registryOf(kind)` —— 取注册场（`ui` / `capability` / `node/shell` / …）

> 细节：插件写 `Service` 子类时用的 `Service` / `PluginModule` / `Context` 类型来自 `@mini-canvas/canvas-base`（它重导出 kernel 与 canvas-data 的相应部分）。

## 一个"把数据层接上 Vue"的最小心智模型

```
你的 Vue 组件
   └─ <CanvasHost :plugins="[theme, text, image]" />
         │ ① onMounted 时调 createMiniCanvasHost 建宿主 host
         │ ② host.ctx 里已装好上面那张服务表
         │ ③ boot 完成后挂载内层 <CanvasSurface>
         │        ├─ provide RENDER_CONTEXT_KEY（裸 ctx + host + 外观 + 只读数据源）
         │        ├─ provide 旧 6 个 *_KEY（兼容未迁移组件）
         │        └─ 渲染一个 <VueFlow>
         │              ├─ node-types：assembleTheme 解析出的每个 type 的节点壳
         │              ├─ edge-types：themeRegistry 的 edge（如 CustomEdge）
         │              └─ 背景 / 默认线 / 拖线临时线也从 themeRegistry 取
         └─ CanvasHost 订阅 nodeStore/edgeStore/selection 变化 → 自动重灌 VueFlow 渲染态
```

插件侧（比如 text 插件 `apply(ctx)` 里）会：

1. `new TextService(ctx)` 上架 `ctx.text` 服务（建/改文本节点的逻辑）；
2. `ctx.nodes.register({ type:'text', size, in: TextContent.vue, create })` —— 数据侧注册进 `doc` 的类型表，展示侧把 `TextContent.vue` 放进 nodeRegistry（区域词是 `in`，老字段名 `content` 已下线，写它会报错）；
3. `TextContent.vue` 在 setup 里 `useCanvasRender()` 拿到裸 `ctx`，然后 `ctx.get('text').editText(id, text)` 把编辑写回内核并落盘。

这样"数据在 canvas-data、怎么画在插件、桥在 canvas-render、装配在 CanvasHost"，各管一段。

## 潜在坑（先给结论）

1. **插件组件一律 `useCanvasRender()`**：返回裸 ctx/host 与 `flow` 能力面，零判空。旧的六个 `*_KEY` 注入令牌（含 `HOST_KEY`）已全部删除，不要再 inject。
2. **nodeTypes 的组件句柄要用 `markRaw`/`shallowRef`**，否则 Vue 会把 .vue 组件对象深代理，触发"组件被 reactive 化"警告。（CanvasHost 已处理，你手写渲染时才要注意。）
3. **content 组件拿 `props`**：BaseNode 给内容段传 `{ id, data }`（见 TextContent/ImageContent）。content 只用展示 + 调服务写回，连接点 Handle 由 BaseNode（nodeShell）统一提供，content 不画 Handle。
4. **`ctx.get('xxx')` 取不到会返回 `undefined`**，别再当成必然存在用。服务缺失会静默，要用插件顶部的 `export const inject = ['doc']` 硬依赖声明。`nodeStore`/`edgeStore`/`graph`/`history` 四个老名已下线，数据统一走 `doc`。
5. **`nodeLayout` / `viewport` 的服务类型由 canvas-data 集中登记**（`packages/canvas-data/src/canvas/renderServiceContracts.ts` + `serviceTypes.ts`），只依赖 canvas-base 也能 `ctx.get('viewport')` 按名推导；插件作者**不要**重复 declare，否则会冲突。
