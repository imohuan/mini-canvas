# mini-canvas v2 —— 开发总览与架构

> 来源：packages/canvas-core-v2、packages/canvas-render、packages/plugins 的源码与注释
> 这套文档讲的是 **v2（Cordis 风格插件内核）** 怎么用。它是老版 v1 之后重写的第二套架构，
> 设计思路记录在 `docs/plan/canvas-core-v2-api.md`、`docs/adr/0001-canvas-core-v2-plugin-kernel.md`。

## 一、先回答一个问题：这两个包是干嘛的？

把一张"能拖节点、能连线、能撤销、刷新不丢"的画布，拆成了两层：

| 层 | 包名 | 职责 | 依赖 |
|---|---|---|---|
| **内核（纯逻辑，零 Vue）** | `@mini-canvas/canvas-core-v2` | 插件怎么加载、服务怎么互相调用、事件怎么发、节点/主题怎么注册、图数据怎么存 | 不依赖 Vue / vue-flow |
| **渲染层（浏览器 + Vue + VueFlow）** | `@mini-canvas/canvas-render` | 把内核接到真实的 Vue / VueFlow 画布上，一行 `<CanvasHost>` 出画布 | runtime 依赖内核 |

**为什么拆两层？** 内核想完全脱离 DOM，可以在 Node 里直接单测（`vitest` 跑通、不启动浏览器）；
渲染层才碰浏览器。依赖方向是**单向的**：渲染层 → 内核，插件 → 内核，内核永远不反向 import 任何人。

### 还有一个"底座"包 `@mini-canvas/canvas-base`
它只是把 `canvas-core-v2` 重新导出了一遍，给插件作者一个更短的入口（少打几个字）：
插件里写 `import { Service, type Context } from '@mini-canvas/canvas-base'`，等价于从
`@mini-canvas/canvas-core-v2` 拿同样的东西。功能上没有区别。

### 与 plugins 的关系
`packages/plugins/` 里放的是**成品插件**（主题、text 节点、image 节点、画布命令），
它们是"内核 API + 渲染层令牌"的最真实用例，也是本套文档案例的主要来源。

## 二、一张图看懂整套架构（从里到外）

```
┌─────────────────────────────────────────────────────────────┐
│  你的 Vue App（App.vue）                                      │
│    <CanvasHost :plugins :adapter :seed @ready/>             │  ← 渲染层入口
│    <SettingsHost/>  <SlotHost slot="overlay"/>             │
├─────────────────────────────────────────────────────────────┤
│  canvas-render（渲染层）                                     │
│    CanvasHost.vue —— 建内核宿主/装配 VueFlow/provide 令牌      │
│    CanvasSurface.vue —— 渲染子树，provide 统一上下文           │
│    canvasHostCore.ts —— store→VueFlow 映射/主题装配(纯函数)    │
│    createMiniCanvasHost.ts —— 建 Context+注入服务+冷启插件门面 │
│    pluginManager.ts —— 插件统一安装句柄(manifest/外部来源)      │
│    contracts/* —— 注入令牌 HOST_KEY/RENDER_CONTEXT_KEY/…      │
├─────────────────────────────────────────────────────────────┤
│  canvas-core-v2（纯 TS 内核）                                │
│    Context —— 生命周期/服务注入/事件/作用域                     │
│    Scope/Fiber —— 副作用自动回收/插件状态机                    │
│    capabilities —— ctx.nodes/theme/commands/slots/settings   │
│    registries —— nodeRegistry/themeRegistry/slotRegistry      │
│    services —— nodeStore/edgeStore/save/history/command/…    │
│    configSchema/settingsStore —— 配置校验与单一数据源           │
└─────────────────────────────────────────────────────────────┘
```

**数据流一句话**：插件经 `ctx` 注册"我能做什么"；内核存"图数据（节点/边）"；
CanvasHost 订阅数据变化，自动把 store 灌成 VueFlow 的 nodes/edges 渲染出来，再经 `provide`
令牌把内核能力递给 content 组件。**改 store 就自动重画**，开发者不用手动同步。

## 三、四个核心概念（看文档前先懂这些词）

1. **插件（Plugin）** —— 一个带 `name` + `apply(ctx, config)` 的对象，或一个 `extends Service`
   的类。装进内核后它会激活并干自己的事。节点类型、主题、命令都是插件干的。
   （写插件叫"插件作者"，拼画布叫"宿主/装配者"。）

2. **Context（内核根上下文，简称 ctx）** —— 插件 `apply` 拿到的对象。它上面有：
   `ctx.on/emit`（事件）、`ctx.get/inject`（服务）、`ctx.nodes/theme/commands/slots/settings`
   （注册能力）、`ctx.effect`（副作用）。**ctx 就是插件的全部世界。**

3. **Scope 作用域 / Fiber 纤维** —— 每个插件一个。所有"要清理的东西"（监听、定时器、注册的
   组件）都自动挂到插件自己的 scope 上，插件卸载时一次清光。**这是 v2 最核心的卖点：
   插件永远不用写 `uninstall`。**

4. **服务（Service）** —— 一个插件向别人公开的能力。A 插件把"自己"以某名字上架
   （`ctx.provide('text', service)`），B 插件就能 `ctx.get('text')` 拿到来调用。
   这是插件之间互相调用的标准方式。

## 四、最快跑起来：一条全链最小案例

下面把"内核 + text/image 节点 + 默认主题 + 命令"拼成一张能拖能连能撤销、刷新不丢的画布。
这是 **`packages/ui/src/App.vue` 的浓缩版**（那是最权威的成品样板，可直接抄）。

```ts
// App.vue（骨架）
<script setup lang="ts">
import { CanvasHost } from '@mini-canvas/canvas-render'                       // 渲染层宿主组件
import { LocalStorageAdapter } from '@mini-canvas/canvas-core-v2'            // 持久化后端
import { themeDefaultPlugin } from '@mini-canvas/plugin-theme-default'       // 默认皮：节点壳/边/背景
import { nodeTextPlugin } from '@mini-canvas/plugin-node-text'               // text 节点
import { nodeImagePlugin } from '@mini-canvas/plugin-node-image'             // image 节点
import { canvasCommandsPlugin } from '@mini-canvas/plugin-canvas-commands'   // 建/删/撤销命令

// ① 冷启动要装的插件（顺序即装载顺序）
const plugins = [
  themeDefaultPlugin,
  nodeTextPlugin,
  nodeImagePlugin,
  canvasCommandsPlugin,
]
const adapter = new LocalStorageAdapter()   // 存 localStorage，刷新不丢

// ② 首次打开(存储为空)时的默认画布
function seedDefault() {
  return [
    { id: '1', type: 'text', position: { x: 120, y: 120 }, data: { text: '双击我输入' } },
    { id: '2', type: 'image', position: { x: 500, y: 160 }, data: { imageUrl: 'data:image/...' } },
  ]
}
</script>

<template>
  <CanvasHost
    :plugins="plugins"
    :adapter="adapter"
    :seed="seedDefault"
    window-key="MiniCanvasDemo"
    @ready="ready = true"
  />
</template>
```

就这些：一个组件把内核启动、插件装配、VueFlow 挂载、数据恢复全做了。
拖动会落盘、拉线自动校验 + 存边、Delete 删选中、Ctrl+Z 撤销，全都内置好了。

> 要更深一层，看本目录下 `canvas-core-v2/`（内核每个 API 怎么用）和 `canvas-render/`
> （渲染层每个组件/令牌怎么用）两套细文档。

## 六、装插件/加载的三种方式

内核给了三条路，场景不同用不同条：

1. **冷启动**（页面一开始就要）：`createMiniCanvasHost({ coldPlugins: [...] })` 或
   `<CanvasHost :plugins="[...]" />`。顺序即装载顺序。
2. **热装**（运行时想加插件）：`ctx.installPlugin(mod)` 或门面 `api.installPlugin(mod)`。
   依赖满足立刻生效，副作用自动回收。
3. **装配清单 manifest**（想要 disabled/每个插件单独配置/同 id 换版本）：
   `createMiniCanvasHost({ manifest })` 或 `manager.applyManifest(manifest)`。
   用 manifest 时 `plugins` 就忽略（manifest 优先）。

> 插件里再想装子插件，用 `ctx.plugin(mod)`（运行时会自动转成热装）。

## 七、为什么插件"不用写清理代码"——十秒讲清 Scope

老架构里，插件卸载要自己挨个 `off` 掉监听、`clearInterval`、注销注册——总会漏。
v2 换了个思路：**每个插件挂一个"垃圾袋"（Scope）**。你在 `apply` 里做的所有带副作用的动作
（`ctx.on`、`ctx.effect`、`ctx.nodes.register`、`ctx.inject`、`ctx.slots.register`…）
都自动把"如何撤销"扔进这个垃圾袋。插件被卸载 → 垃圾袋一次性倒空，按倒序执行，一个都不漏。

```ts
ctx.on('ctx:ready', handler)      // 卸载时自动取消监听
ctx.effect(() => {
  const t = setInterval(...)      // 卸载时自动 clearInterval
  return () => clearInterval(t)   // 想更精细还能手动返回清理函数
})
ctx.nodes.register({ type: 'x', ... })  // 卸载时自动注销该节点类型
```

所以插件作者只需写 `apply`，永远不用写 `uninstall`。这是理解整套内核的关键。

## 八、依赖方向红线（写代码别违反）

- 内核 **不 import** 任何插件、不 import 任何 `.vue` content 组件（content 是"不透明句柄"）。
- 插件 / 渲染层 → 内核，方向恒为单向。
- content 组件要调服务：先 `inject(HOST_KEY)` 或 `useCanvasRender()` 拿 host/ctx，再 `ctx.get('...')`，
  **不要反向依赖宿主 demo、不要直接 import 别的插件**（依赖用 `inject: ['text']` 声明，让内核编排）。

## 九、约定与命名速查

- **服务名**（插件互相调用、`ctx.get` 用）：`save` / `nodeStore` / `edgeStore` / `nodeRegistry` /
  `themeRegistry` / `selection` / `history` / `command` / `nodeFactory`，以及宿主注入的渲染层服务

- **节点段位**（NodeSegment）：`content` / `title` / `top-toolbar` / `bottom-toolbar`。
- **内置事件**：`ctx:ready` / `ctx:plugin-installed` / `ctx:plugin-uninstalled` / `ctx:lifecycle-change`。

## 十、渲染层为插件补的服务 / 上下文（2026-09 复刻插件时新增，插件作者面）

内核 ctx 上除了内核自带服务，宿主（createMiniCanvasHost）还会注入以下**渲染层服务**——插件直接声明 `inject: [...]` 硬依赖、或 `ctx.get<T>('name')` 可选读取；不需要 import canvas-render 就能用（服务名是稳定字符串）：

| ctx 服务名 | 类型 | 谁能给 | 做什么（插件常用） |
|---|---|---|---|
| `nodeLayout` | NodeLayoutService | 宿主（canvas-render） | 节点几何只读：nodeSize / absolutePosition / getNodeRect / getAllRects / childrenOf；多选/对齐/归组/小地图都靠它拿绝对坐标+实测尺寸 |
| `viewport` | ViewportService | 宿主（canvas-render） | 视口读写：getViewport / screenToFlow / flowToScreen / setCenter / setViewport / fitView / zoomTo；服务缺失时调用即 no-op |
| `command` | CommandService | 宿主（canvas-core-v2） | 命令注册表：register({id,title,keys,run,...}) + findCommandByKeys；快捷键由渲染层 CanvasHost 统一分发（插件不绑 window） |

> 插件作者**不要**对这些服务重复 declare module Context { nodeLayout?: ... }——canvas-render 的 index.ts 已统一 declare（nodeLayout: NodeLayoutService、viewport: ViewportService），重复 declare 且类型不一致会编译冲突。纯逻辑包（没依赖 canvas-render）想读布局，用 ctx.get<T>('nodeLayout') 即可。

渲染层浮层/UI 组件（.vue，渲染在 CanvasSurface 子树内）用 useCanvasRender() 拿到：

```ts
const { ctx, viewport, paneRect, pane, renderNodes, renderEdges,
        screenToFlow, flowToScreen, updateNodeVisual } = useCanvasRender()
```

- viewport（Readonly<Ref<ViewportState>>）：实时视口变换，浮层定位/坐标换算用
- paneRect / pane：pane 的 DOM 矩形 / DOM 元素（自绘框选、手势监听挂载点）
- renderNodes / renderEdges：当前渲染节点/边只读快照（宿主订阅 store 自动重灌）
- screenToFlow / flowToScreen：屏幕 client 坐标与画布 flow 坐标互转
- updateNodeVisual(id, position)：拖拽中把视觉位置写到渲染层节点（不落盘、不整组替换；对齐吸附等实时微调用）
- registry / nodeWrite / edgeVisual / handleParams / interaction / debug / snapZone / connectionState：展示/外观/交互态，给壳、边、content 组件

### 渲染层广播事件（RenderEvents，插件 ctx.on 订阅）

| 事件名 | payload | 时机 |
|---|---|---|
| canvas:node:drag-start / canvas:node:drag / canvas:node:drag-end | { nodeId, position } | 节点拖动开始/逐帧(rAF 节流)/结束 |
| canvas:viewport:move-start / canvas:viewport:move-end | { viewport } | 画布 pan/缩放开始/结束 |
| canvas:node:click / canvas:edge:click / canvas:pane:click | { nodeId?/edgeId?, shiftKey } | 点选（宿主已写内核 Selection，这里只做广播） |
| canvas:selection:change | { nodeIds, edgeIds } | 选中集合变化（节点/边任一桶） |
| canvas:context-menu:pane / node / edge | { clientX, clientY, flowPosition, nodeId?/edgeId?, nodeType? } | 右键（已 preventDefault，插件自己弹菜单） |
