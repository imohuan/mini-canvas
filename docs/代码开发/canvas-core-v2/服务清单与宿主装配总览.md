> 来源：packages/canvas-core-v2/src/index.ts、services/index.ts、Context.ts、core/index.ts

## 2. 服务分类表

### 2.1 内核"恒在"服务（不用注入，`ctx.get` 一定有）

| ctx.get 名 | 类型 | 说明 |
| --- | --- | --- |
| `'slots'` | `SlotRegistry` | 通用 UI 槽（ctx.slots 写这里） |
| `'settings'` | `SettingsStore` | 配置单一数据源（ctx.settings 写这里） |

> 这俩是 Context 构造里 `new SlotRegistry()` / `new SettingsStore()` 出来的，宿主与插件共享同一实例。

### 2.2 内核约定名（**需宿主手动 `ctx.inject`**，内核不自动注）

| ctx.get 名 | 通常类型 | 用在哪篇 |
| --- | --- | --- |
| `'nodeStore'` | `NodeStore` | ctx.nodes / 节点数据 |
| `'nodeRegistry'` | `NodeRegistry` | ctx.nodes 展示 / nodeRenderer |
| `'themeRegistry'` | `ThemeRegistry` | ctx.theme / registerThemeSlot |
| `'command'` | `CommandRegistry` | ctx.commands / command |
| `'nodeFactory'` | `NodeFactory` | ctx.nodes 建节点 / nodeFactory |
| `'edgeStore'` | `EdgeStore` | 边数据 |
| `'selection'` | `Selection` | 选中集 |
| `'history'` | `History` | 撤销/重做 |
| `'save'` | `SaveServiceImpl` | 持久化 |

> 注意：宿主也可以**不**全注入，只注入当前功能需要的；缺的服务 `ctx.get` 返回 undefined（不抛）。但用 ctx.nodes/theme/commands 这些能力段时，其底层服务若缺失会导致注册失败/跳过，务必先注入。

## 3. 宿主装配完整 ctx（骨架）

```ts
import {
  Context,
  NodeStore, NodeRegistry, ThemeRegistry,
  CommandRegistry, NodeFactory, EdgeStore, Selection, History,
  SaveServiceImpl, LocalStorageAdapter, MemoryStorageAdapter,
  type PluginModule,
} from '@mini-canvas/canvas-core-v2'

// 1) 建底盘 + 注入数据/能力服务
const ctx = new Context({ dev: true })   // dev 开 events 白名单警告
const nodeStore = new NodeStore()
const edgeStore = new EdgeStore()
ctx.inject('nodeStore', nodeStore)
ctx.inject('nodeRegistry', new NodeRegistry())
ctx.inject('themeRegistry', new ThemeRegistry())
ctx.inject('command', new CommandRegistry())
ctx.inject('nodeFactory', new NodeFactory())
ctx.inject('edgeStore', edgeStore)
ctx.inject('selection', new Selection())
ctx.inject('history', new History({
  snapshot: () => JSON.stringify({ nodes: nodeStore.getNodes(), edges: edgeStore.getEdges() }),
  restore: (s) => { const g = JSON.parse(s); nodeStore.replaceAll(g.nodes); edgeStore.replaceAll(g.edges) },
}))
const save = new SaveServiceImpl(new LocalStorageAdapter())
ctx.inject('save', save)

// 2) 装插件（可对象/类/函数形态），第二个参是装配 config
ctx.plugin(myTextPlugin)                       // { name, Config, apply(ctx, config) }
ctx.plugin(myThemePlugin, { edgeColor: '#0af' })

// 3) 启动（按依赖激活全部插件）
await ctx.start()
save.flush()   // 兜底落盘

// 运行时热装/热卸
ctx.installPlugin({ name: 'hot', apply() {} })
ctx.uninstallPlugin('hot')

// 停机（可重新 plugin+start）
ctx.stop()
```

插件侧拿到的是一个自动装配好能力段的 `ctx`（PluginScope）：
- 内置可用：`ctx.on/once/emit/parallel/serial/bail/waterfall/effect/inject/provide/get/plugin/registry`
- 能力段：`ctx.nodes.register`、`ctx.theme.*`、`ctx.commands.*`、`ctx.slots.*`、`ctx.settings.*`
- Proxy 属性读：`inject:['greeter']` 后可直接 `ctx.greeter`

## 4. 一个"插件作者视角"的最小全集示例

```ts
// my-feature.ts —— 一个把上面全都串起来演示的插件
import { F, type PluginScope } from '@mini-canvas/canvas-core-v2'

export const name = 'my-feature'
export const inject = ['nodeStore', 'nodeRegistry', 'themeRegistry', 'nodeFactory', 'selection']
export const Config = {
  edgeColor: F.color('#3b82f6'),
  glow: F.boolean(true),
}

export function apply(ctx: PluginScope, config: { edgeColor: string; glow: boolean }) {
  // 注册节点类型（数据+展示+建节点）
  ctx.nodes.register({
    type: 'my-block', label: '我的块', size: { w: 160, h: 90 },
    content: MyBlockContent,               // 你的 .vue 组件（opaque）
    create: (pos) => ctx.get('nodeStore').addNode('my-block', pos),
  })

  // 换肤
  ctx.theme.register('background', MyBackground)

  // 注册命令
  ctx.commands.register({
    id: 'my:clear', when: () => ctx.get('selection').size > 0,
    run: () => { /* ... */ },
  })

  // 订阅自己的配置，实时就地生效
  ctx.settings.onChange('my-feature', (key, value) => console.log('配置变了', key, value))

  // 事件（自动回收）
  ctx.on('ctx:ready', () => console.log('就绪'))
}
```

## 5. 坑与速记

1. **`slots` / `settings` 恒在**，`nodeStore`/`themeRegistry`/`command` 等**要宿主注入**——别默认内核啥都有。
2. `dev: true` 只影响 EventBus 的未声明事件 warn，不影响功能；建议开发期开、生产关。
3. 装配顺序无所谓（start 按依赖激活），但**注入必须在 start 前**（服务要在插件需要它之前上架）。
4. 插件 `apply(ctx)` 里能力段、事件、副作用全自动回收，作者专注写业务逻辑。
