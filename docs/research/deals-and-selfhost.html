能并发，但不是「一张卡变十张卡」

ComfyUI 的并发本质是排队制，不是真并行。三层递进：单进程 batch → 单卡多实例 → 多卡多实例才是真扩展。

三层并发

层级做法实测数据
单进程 batch一次喂多张Z-Image 在 4090 上 batch=4 安全，实测 0.65 张/秒
单卡多实例一张卡开多个 ComfyUI 进程第三方数据：单实例并发 3–4、单卡约 3 个实例（可信度中等）
多卡多实例一卡一个进程：--cuda-device N --port 8188+N，外层 Python 队列按 /queue 长度分发这才是真横向扩展

三条红线

  • MiniMax-H3 的 2K 管线没开源——HF README 明确写 H3-Context-IR「not yet open-sourced」，2K 需走官方 API。本地只能稳定出 768P。license 是 minimax-h3-community-license-agreement（不是 Apache），商用需单独确认授权。
  • Z-Image 的「官方速度」要打折看——官方论文说的是企业级 H800 上亚秒级，不是你手上那张 4090。4090 上实测跨度 0.8s～7.2s，取中位数更稳。
  • 自建的隐性成本不是钱，是时间——Medium 一位跑了 1000 张对比实测的作者给出：ComfyUI 机器每月 2–4 小时维护。很多人算漏这个。
