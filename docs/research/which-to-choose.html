到底选哪个：按时长计费，还是直接调 API？

结论页　|　汇率 1 USD ≈ ¥6.73　|　数据抓取 2026-09-27　|　配套：价格表 · 活动与自建
一句话结论：先调 API，别急着自建。等真实用量跑出来再决定。只有当图片每月超过约 1 万张，或视频每月超过约 600 条时，按执行时长计费（RunningHub 那类）才真正开始省钱；在此之前，两者的差价不够覆盖你折腾的时间。

一、两种方式的本质区别

方式怎么收钱你要做的事适合谁
直接调 API
（按次 / 按张 / 按秒视频）		出一张图扣一次钱，出 1 秒视频扣 1 秒的钱。不跑不扣钱只要一个 Key，写几行代码用量不稳定、刚起步、不想管机器
按执行时长计费
（GPU 秒 / ComfyUI 执行秒）		只按任务真正跑的那几秒扣钱，空闲不扣要准备 ComfyUI 工作流，调一次能跑通就能一直用用的是开源模型（Z-Image、MiniMax-H3），且用量稳定
租卡按小时
（AutoDL、算家云、RunPod）		开机就烧钱，不管有没有在跑装机、下模型、调环境、记得关机每天连续跑好几个小时、能塞满显卡

关键一句话：「按执行时长」和「租卡按小时」不是一回事。前者是"跑 3 秒扣 3 秒"，后者是"开机 1 小时扣 1 小时，哪怕只跑了 3 秒"。很多人把这两件事混着说，账就完全算错了。

但视频自建有硬限制，别忽略：
  • 2K 管线没开源。HuggingFace 官方 README 写明 H3-Context-IR "not yet open-sourced"，2K 必须走官方 API。本地只能稳定出 768P（4090 上 1344×768 会直接卡死，1280×704 是 24GB 安全上限）。

  • 速度慢。4090 上一条 5 秒视频要 5～6 分钟（含模型加载约 10 分钟）。不是"点一下就出"。

六、我的推荐路径（照着做就行）

  • 第 1 步：先用 API 跑两周。图片用硅基流动的 Z-Image-Turbo（¥0.034/张），视频用 EvoLink 或 MiniMax 官方。目的不是省钱，是拿到你自己的真实用量曲线。
  • 第 2 步：看数字。图片过了 1 万张/月、视频过了 600 条/月，再上 RunningHub 的按执行时长计费（Standard ¥4/小时，100 并发，并发按累计时长算不重复扣钱）。
  • 第 3 步：还嫌贵再考虑租卡，而且必须"用完即关"。买卡是最后一步：按 ¥2/小时折算，4090 要跑满约 6500 小时才打平 —— 每天不到 4 小时就别买。

七、并发这个事，别抱幻想

层级做法能到多少
单进程批处理ComfyUI 一次出 N 张4090 上 Z-Image batch=4 安全（512² 峰值 15.3GB）；1024² 建议 batch=1
单卡多实例一张卡起多个 ComfyUI 进程第三方数据：单实例并发 3～4，单卡约 3 个实例（可信度中等）
多卡多实例一卡一个实例 + 外层队列调度8 卡 = 8 实例，线性扩展。这才是真并发

ComfyUI 的并发本质是排队制，不是真并行。--cuda-device 指定多卡，不等于一个工作流会自动拆到多卡上。想要吞吐就是"一卡一实例 + 外层队列"。吞吐参照：单卡 4090 约 0.65 张/秒，理论日上限约 5.6 万张（实际打 3～5 折）。网上"单卡日产 10 万张"没找到官方出处，当宣传看。

本页数字来自 2026-09-27 抓取的官方定价页与第三方实测文章。按执行时长计费的单张成本按 2 GPU 秒/张（1.5 秒生成 + 0.5 秒冷启动摊销）估算，实测耗时在 4090 上从 0.8 秒到 7.2 秒都有（跨度 9 倍），建议自己实测一次再套公式。另需计入每月 2～4 小时的维护时间（海外 1000 张实测作者给出的值）。
