# 自建 GPU 部署 vs 调 API：成本对比分析（F 组）

> 调研日期：2026-09-27　目标模型：**Z-Image / Z-Image-Turbo（阿里通义，6B）**、**MiniMax-H3（开源视频模型）**
> 原则：每个数字带来源；实测与官方宣传分开标注；查不到的地方明确写"查不到"，不编造。

---

## 一、结论速览（先看这段）

| 问题 | 结论 |
|---|---|
| **有没有按执行时间扣费的 GPU 平台？** | **有，而且是一条成熟产品线**。分两类：①「按 GPU 秒计」的 serverless（Replicate、fal.ai、RunPod Serverless、ComfyDeploy、Comfy Cloud 官方 API、ViewComfy、ComfyICU）；②「按任务运行时长计」的国内 ComfyUI 托管（**RunningHub 企业共享 API 按秒计费，¥0.4～9/小时，不跑不扣钱**）。 |
| **自建和调 API 哪个划算？** | **取决于你有没有稳定大批量需求**。Z-Image 这种快模型（单张 1～2 秒），**只要用量超过每月约 5000 张，自建/租卡就明显便宜**；10 万张时自建成本约为 API 的 **1/30**。但**前提是你能把闲置压下去**——如果常驻开机不关，盈亏点会推高到 **约 4.3 万张/月**。 |
| **租 GPU 能不能并发？** | **能，但一张卡只能跑有限路**。单卡并发靠"多 ComfyUI 实例 + 队列调度"是社区成熟做法；Z-Image 在 24GB 卡上实测**单实例并发 3～4、单卡约 3 个实例**（第三方文章数据，可信度中等）。真正的横向并发是**多卡多实例**，一张卡一个进程。 |
| **视频（H3）值不值得自建？** | **值得算一算，而且比图片更划算**。H3 在 4090 上跑一条 5 秒 768P 约 **5～6 分钟**（第三方实测），GPU 成本约 **¥0.18/条**；官方 API **¥0.50/秒（768P）**，5 秒一条 = **¥2.5/条**。差 **13 倍以上**。但 H3 有硬限制（见下）。 |

### 三条最重要的红线

1. **MiniMax-H3 的 2K 管线没开源**——HuggingFace README 明确写：H3-Context-IR 模块 "not yet open-sourced"，H3-Regenerate-2K 需走官方 API。**本地只能稳定出 768P**。且 license 是 `minimax-h3-community-license-agreement`（不是 Apache），**商用需单独确认授权**。这条已确认（来源：HF README，2026-09-27 读取）。
2. **Z-Image 的"官方速度"要打折看**。官方论文说的是"企业级 **H800** 上亚秒级"，不是你手上那张 4090。第三方在 4090 上实测跨度很大（0.8s～7.2s），取中位数更稳。
3. **自建的隐性成本不是"钱"，是"时间"**。Medium 上一位跑了 1000 张对比实测的作者给出：ComfyUI 机器**每月 2～4 小时维护**。这是很多人算漏的。

## 三、按执行时间计费平台专题（用户最关心的）

### 3.1 最贴近需求的三家

**① RunningHub（国内，首选验证对象）**
- 计费原文："所有机型均按秒计费，**多任务并发时，按所有任务的累计运行时长总和计费**，而非按并发时长统一计费。"
- 这句话很重要：**并发时不重复扣钱**。开 10 路并发跑 10 个 5 秒任务 = 扣 50 GPU 秒，不是 500 GPU 秒。
- 价位（¥/小时）：Lite **0.4**、Standard **4**（24GB）、Plus **6**（48GB）、Ultra **9**（84GB）。
- 共享型默认 **100 并发**；另有"独占型"预付订阅（买断卡时长，订阅期内不限调用）。
- 还有 retainSeconds（10～180 秒）参数：任务完成后保留实例减少冷启动，**保留期也计费**——容易漏算的成本点。

**② Comfy Cloud（ComfyUI 官方）**
- 订阅送 credits + 按 GPU 秒扣费。API 并发上限 **Standard 1 / Creator 3 / Pro 5**，排队最多 100。
- 官方参考值："**一段 5 秒视频约消耗 11 积分**"。
- 开发者平台按 GPU 秒：$3.49/hr（RTX PRO 6000）～ $8.64/hr（B200）。

**③ ComfyICU / ViewComfy（海外轻量）**
- ComfyICU：L4 $0.0009/s（约 **¥0.0065/秒**，按 7.2 汇率）。$10/月含 10 万 credits ≈ 3 小时 L4。
- 官网引用的 Discord 用户证言："我在 RunPod 上烧了 $50 折腾 ComfyUI，太浪费了——我把大卡按小时预留着，实际只用了 1%。"精准命中用户担心的痛点。

## 四、模型显存与耗时实测

### 4.1 Z-Image / Z-Image-Turbo（6B，8～9 NFEs）

| 项目 | 数值 | 来源 | 类型 |
|---|---|---|---|
| 参数量 / 架构 | 6B，S3-DiT 单流 | arXiv 2511.22699 | 官方论文 |
| 官方推理延迟 | **H800 上亚秒级**；兼容 **<16GB VRAM** | arXiv 摘要 | **官方宣传（H800，不是消费卡）** |
| 1024² 峰值显存 | **13.7 GB（bfloat16）**；官方示例 <14G | 高效码农 2025-11-27；夜雨飘零 2025-12-19 | 第三方实测 |
| 1024² 生成耗时（RTX 4090） | **0.8～0.9 秒**（开 FlashAttention + compile） | 夜雨飘零 2025-12-19（自称实测） | 第三方（偏乐观） |
| 1024² 生成耗时（RTX 4090） | **2.1 秒** | CSDN 文库测试文 2026-03-18 | 第三方（偏保守） |
| 1024²（4090 / A100） | **7.2 秒 / 5.1 秒** | CSDN 文库 2026-02-26 | **数据存疑，明显偏离其它来源** |
| 512² / 768²（4090 单图） | 0.8s / 1.2s | CSDN 文库 2026-03-18 | 第三方 |
| 训练成本参照 | 314K H800 GPU·小时 ≈ $628K（按 $2/GPU·h） | arXiv 论文 Table 1 | 官方 |

> 数据冲突警示：4090 上 1024² 的实测值从 **0.8s 到 7.2s 都有**，跨度 9 倍。差异可能来自：是否开 FlashAttention / torch.compile、是否含模型加载、步数 8 vs 9、是否走 ComfyUI（有节点开销）。**本文测算取 0.9s（乐观）/ 1.5s（中性）/ 2.5s（保守）三档，不押注单一数字。**

**显存结论**：1024² 峰值 ~14GB → **16GB 卡可跑，24GB 卡（4090）有约 10GB 余量**，理论可开 2 个实例但余量不大。**32GB 的 5090 或 48GB 的 L40S/A6000 更适合多实例并发。**

### 4.2 MiniMax-H3（开源视频）

| 项目 | 数值 | 来源 | 类型 |

## 五、成本测算与盈亏平衡点

### 5.1 假设条件（可自行改参数重算）

| 参数 | 取值 | 说明 |
|---|---|---|
| 显卡 | RTX 4090 24GB | 主力测算卡 |
| 租金 | **¥2.0/小时** | AutoDL 按需 ¥1.81～2.14、算家云 ¥1.24 的中位偏保守值 |
| 启动/运维损耗 | **2.5 小时/月** | 开机、拉镜像、下模型、调工作流、关机（保守） |
| 存储 | **¥15/月** | 模型盘 + 输出盘 |
| 电费（自有卡） | ¥0.6/度，4090 平均 **280～320W** | CSDN 实测功耗 |
| 汇率 | 1 USD = 7.2 CNY | 用于折算 |
| API 基准价 | **¥0.034/张**（Z-Image 类） | **需以 A 组最终价为准** |

### 5.2 模式一：按需启停（跑完就关机，最省）

**单张 GPU 成本 = 租金 ÷ 3600 × 单张耗时**

| 单张耗时 | 单张 GPU 成本 | 对比 API ¥0.034/张 |
|---|---|---|
| 0.9 秒（乐观） | **¥0.00050** | 便宜 **68 倍** |
| 1.5 秒（中性） | **¥0.00083** | 便宜 **41 倍** |
| 2.5 秒（保守） | **¥0.00139** | 便宜 **24 倍** |

**月度总成本（含启动损耗 2.5h + 存储 ¥15）：**

| 月用量 | 0.9s 档 | 1.5s 档 | 2.5s 档 | API（¥0.034/张） |
|---|---|---|---|---|
| 1,000 张 | ¥20.5 | ¥20.8 | ¥21.4 | **¥34** |
| 5,000 张 | ¥22.5 | ¥24.2 | ¥26.9 | **¥170** |
| **10,000 张** | ¥25.0 | ¥28.3 | ¥33.9 | **¥340** |
| 100,000 张 | ¥70.0 | ¥103.3 | ¥158.9 | **¥3,400** |
| 1,000,000 张 | ¥520 | ¥853 | ¥1,409 | **¥34,000** |

**盈亏平衡点：约 1,000～2,000 张/月**（固定成本仅 ¥20，纯 GPU 成本极低，几乎一开始就赢）。

> 注意：这个"一开始就赢"是**数学真实但工程不真实**的——它假设你每次都能"开机→跑完→关机"，且不计你自己的操作时间。真实场景下你至少要开机一次，而 AutoDL 开机即计费。

### 5.3 模式二：常驻开机（7×24 不关，最费）

月固定成本 = 730h × ¥2.0 + ¥15 = **¥1,455/月**（不含 GPU 计算）

**盈亏平衡点 = ¥1,455 ÷ ¥0.034 ≈ 42,800 张/月**

也就是说：**如果你的 4090 常驻开机，每月跑不到 4.3 万张，还不如直接调 API。**

反过来看 4090 的产能上限（按 1.5s/张、100% 打满）：730h × 3600 ÷ 1.5 ≈ **175 万张/月**。所以**只要你能让卡持续有活干，常驻也是划算的**——关键在于有没有活。

### 5.4 模式三：B 类按执行计费（零闲置，最贴近"不想管机器"的人）

| 平台 | 单张成本（含冷启动摊销） | 月 1 万张 | 月 10 万张 |
|---|---|---|---|
| RunningHub Standard (24G) ¥4/h | ¥0.0022 | ¥22 | ¥220 |
| RunPod Serverless 4090 | ¥0.0063 | ¥63 | ¥630 |
| ComfyICU L4 | ¥0.013 | ¥130 | ¥1,300 |
| Comfy Cloud RTX PRO 6000 | ¥0.014 | ¥140 | ¥1,400 |
| **API 直调** | **¥0.034** | **¥340** | **¥3,400** |

**结论：B 类按执行计费在 1 万张/月就能省 5～15 倍，且完全不用运维。**这是"想要自建的低价但不想管机器"的最优解。

### 5.5 视频：H3 自建 vs 官方 API

→ 一条 5 秒 768P = **¥2.5**（国内价）或 $0.4 ≈ ¥2.88（国际价）

**自建（4090，¥2/h）**：按腾讯云开发者社区实测 **5.5 分钟/条（330 秒）**
- 纯 GPU 成本 = 2.0 × 330 ÷ 3600 = **¥0.183/条**
- 若含模型加载摊到每段（9.9 分钟/段，即 594 秒）= **¥0.33/条**
- 若用 B 类 RunningHub Standard（¥4/h，330 秒）= **¥0.367/条**

| 方案 | 单条（5s 768P）成本 | vs API ¥2.5 |
|---|---|---|

> 但 4090 跑 H3 只能到 **1280×704**，官方 API 能到 2K。**这不是同一种商品**，比价时要打折。

## 六、并发能力分析（用户特别问的）

### 6.1 结论先行

**能并发，但并发不是"一张卡同时算很多"，而是"排队 + 多实例"。**三种层级：

| 层级 | 做法 | 能到多少 |
|---|---|---|
| **① 单进程批处理（batch）** | ComfyUI / diffusers 一次出 N 张 | 4090 上 Z-Image **batch=4 安全**（512² 峰值 15.3GB）；1024² 建议 batch=1 |
| **② 单卡多实例** | 一张卡起多个 ComfyUI/worker 进程 | Z-Image 在 4090 上第三方给的是**单实例并发 3～4、单卡 3 个实例**（可信度中等） |
| **③ 多卡多实例（真横向扩展）** | **每卡一个 ComfyUI 实例**（--cuda-device N --port 8188+N）+ 外层 Python 队列调度 | 8 卡 = 8 实例，线性扩展 |

**关键机制**：ComfyUI 服务端自带 /prompt、/queue、/history 接口，外层调度器查各实例队列长度，把任务丢给最闲的那张卡。社区已有完整的多实例启动脚本（每实例独立 --cuda-device / --port / 输出目录，共享模型目录省磁盘）。

> 注意：ComfyUI 的并发是**排队制**，不是真并行。--cuda-device 指定多卡 ≠ 单个工作流自动拆分到多卡。**想要吞吐，就一卡一实例 + 外层队列。**

### 6.2 平台侧并发

| 平台 | 并发能力 |
|---|---|
| **RunningHub 共享 API** | **默认 100 并发**；并发时按**累计运行时长**计费（不重复收费） |
| **Comfy Cloud** | API 并发 1 / 3 / 5（Standard/Creator/Pro），排队 100 |
| **ViewComfy** | 1 / 2 / 5 / 无限（按套餐） |
| **RunPod Serverless** | 自动扩缩，Flex 可缩到 0 |
| **fal.ai** | 多 GPU 按 卡数 × 时长 计费，可横向扩 |
| **V2EX 社区共识**（LLM 场景，道理通用） | "并发的成本很高……业内通用做法是**只支持特定并发 + 队列控制**，并发满了就排队或提示稍后再试" |

### 6.3 吞吐参照（Z-Image，单卡 4090）

按 1.5s/张、单卡并发 3～4 路估算：
- 单卡理论吞吐 ≈ **0.6～0.7 张/秒**（batch=4 实测 6.2 秒出 4 张 = 0.65 张/秒，与 CSDN 数据吻合）
- 一天 24 小时打满 ≈ **5.6 万张/天**（理论上限，实际打 3～5 折）

> "官方说单卡日产 10 万张"这类宣传：Z-Image 官方论文只说 H800 亚秒级，**没有日产 10 万张的官方说法**，本文未找到该数字的原始出处。第三方实测 batch 吞吐约 0.65 张/秒 → 日产上限约 5.6 万张（100% 打满）。**请把"日产 10 万张"当作未证实宣传。**

## 九、给用户的行动建议

1. **先别买卡。** 用 B 类按执行计费（RunningHub 最贴合国内场景）跑两周，拿到真实用量曲线。
2. **图片（Z-Image）**：月用量 <5000 张 → 直接调 API，别折腾。5000～5 万张 → B 类按执行计费最省心。>5 万张且稳定 → 上 AutoDL/算家云按需卡，用完即关。>40 万张 → 考虑常驻或买卡。
3. **视频（H3）**：自建性价比远超图片（便宜 7～14 倍，盈亏点仅 582 条/月）。但要接受 **1280×704 上限** 和 **5～6 分钟/条** 的速度；**2K 和商用授权必须走官方**。
4. **并发**：不要指望一张卡变出 10 张卡。要吞吐就**一卡一实例 + 外层队列**；要省事就用 RunningHub 的 100 并发共享池（按累计时长计费，不重复收费）。
5. **别忽略维护时间**：每月 2～4 小时（海外实测值）。时间成本高的话，这笔账会吃掉自建的一大半优势。
