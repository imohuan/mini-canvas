# 插件包独立 dev / build：方案调研总览

> 调研对象：`packages/plugins/plugin-node-{text,image}` 要能单独 `pnpm dev`（独立 vite dev 吐入口）与
> `pnpm build`（vite lib 打出可独立加载 js），宿主运行时动态 import 后 `installPlugin`。
> 版本事实：vite **8.0.16**、vue **3.5.34**、typescript **~6.0.2**、`@vue-flow/core` **1.48.2**、
> `@vitejs/plugin-vue` **^6.0.6**（canvas-core-v2）。插件包目前**只有 `typecheck` script，无 dev/build**。
> 结论基于真实读文件；仅给可落地最小配置，不写业务代码。

## 0. 一句话结论

- **插件本身就是一段 `PluginModule = { name, setup(ctx) }`**，宿主侧的装配口已经现成：
  `window.MiniCanvas.installPlugin(mod)` / `reloadPlugin(name, nextMod)`（`createMiniCanvasHost.exposeToWindow`）。
  所以**无论源码 import 还是动态加载打包 js，插件的“落地”都收敛到一个 installPlugin 调用**，无需新增宿主 API。
- dev 态和 build 态分开看：**dev 用 vite dev 源码直连（宿主经 dev 服务的裸入口 import 插件模块），
  build 用 vite lib 打 UMD（或 ES），宿主 `<script>` 或 `import()` 之后装进 window.MiniCanvas**。
- **vue 单例不是靠“打 UMD 时 external 掉 vue”就能自动保证的**——UMD 模式 vite 会用 `globals.vue` 的全局名去取，
  宿主得自己把单个 vue 挂到那个全局名上。真正稳的做法是 **dev/build 两态都只让浏览器里存在一份 vue**（见 `vue-singleton.md`）。

## 1. 关键前提：装配契约已经存在（不用新造）

读 `packages/canvas-core-v2/src/host/createMiniCanvasHost.ts` 与 `demo-web/CanvasDemo.vue`：

- 宿主 `exposeToWindow('MiniCanvas')` 后 `window.MiniCanvas = { installPlugin, uninstallPlugin, reloadPlugin, listPlugins, getContext, getRegistry, getNodeStore, getHost }`（`MiniCanvasApi`）。
- `CanvasDemo.vue`（line 282-288）注释明说：“源码插件 / 打包 js 插件都经 window.MiniCanvas.installPlugin 安装”。
- 插件模块形如 `nodeTextPlugin.ts` 导出的 `nodeTextPlugin: PluginModule`——**默认导出即可被 `installPlugin(mod)` 直接用**。
- content .vue 组件经 `inject(HOST_KEY)` 拿宿主句柄（`TextContent.vue` 样板），不反向依赖 demo。插件 UI 注册进 `nodeRegistry`，
  由宿主 `<VueFlow>`+BaseNode 渲染。**content 组件运行在宿主挂好的那棵 Vue 应用里**——这是 vue 单例必须成立的根因。

> 由此：宿主侧要做的只是一句 `window.MiniCanvas.installPlugin(mod)`。方案的核心全在“怎么把插件以单份 vue 的方式递给宿主”。

## 2. repo 内已有可参照的 build 先例

- `packages/prosemirror-editor-bundle/vite.config.ts` + package.json：已配 **vite lib 模式，formats ['es','umd']，
  rollupOptions.external 掉 vue + 一堆 peer、cssCodeSplit:false、dts 出类型、按 mode 切 iife**。是 lib 打法的完整参照。
- 注意它用的是老栈（vite 6 / plugin-vue 5 / ts 5.7）。**插件包要按新栈 vite 8 / plugin-vue 6 / ts 6 核对配置字段**
  ——vite 8 仍兼容本文给的 lib/external/cssCodeSplit 写法（这些是稳定 API）。
- `canvas-core-v2` 只有 dev（vite dev 服务），**没有 lib build 先例**；但它 `dependencies` 里放了 vue/pinia/@vue-flow/core，
  dev 服务会把它们预构建（optimizeDeps.include）。插件包应 peer、而不应重复装 vue（见下）。

## 3. dev 态：插件自己起 vite dev server

目标：给 `plugin-node-*` 加 `dev` script，起一个独立 vite dev，宿主（浏览器里已开着的画布）**源码直连该 dev 入口**，
改动即 HMR（index.ts 里已有 `import.meta.hot.accept(['./nodeTextPlugin'], …)→window.MiniCanvas.reloadPlugin` 的现成钩子）。

### 最小 vite.config.ts(dev) —— 放插件包根

```ts
// plugin-node-text/vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { fileURLToPath } from 'node:url'

export default defineConfig({
  plugins: [vue()],
  // 插件是"被宿主 import 的库"，不是独立页面 → 不需要 html 入口
  build: { lib: { entry: fileURLToPath(new URL('./src/index.ts', import.meta.url)) } },
  server: {
    port: 5301,            // 每个插件一个固定端口（text=5301, image=5302…），避免撞 canvas-core dev 5199
    strictPort: true,      // 端口被占宁可报错，别悄悄换号把宿主 import 的 URL 打飞
    cors: true,            // ★ 宿主动态 import 跨端口取模块必需（见 dev-linking）
  },
  optimizeDeps: { include: ['vue'] }, // dev 下把 vue 预构建成单份（配合单例，见 vue-singleton.md）
})
```

### 插件包 package.json 补两段

```jsonc
{
  "devDependencies": { "@vitejs/plugin-vue": "^6.0.6" },   // 新加；vite/vue 已在
  "scripts": { "dev": "vite" }                               // 复用 vue 插件起 dev
}
```

要点：**dev 没有 html、不吐“可运行页面”**，它就是被宿主 `import(pluginDevUrl)` 拉的一个 ESM 模块源。
所以 `vite.config` 只需 `lib.entry` 指向 `src/index.ts` + `server.cors:true`。

### 宿主怎么"链接" dev 插件

- 可行：宿主把插件源码 URL 交给 vite dev 服务编译即可，见 `dev-linking.md`。
- 核心是：`@mini-canvas/plugin-node-text` 这个包名在宿主里当前是被 `@mini-canvas/canvas-core-v2` 静态 import 的
  （CanvasDemo line 24）。要让“独立 dev server 版本”被宿主用，是**把宿主的 import 从包名换成 dev server 裸 URL**，
  而不是给宿主加服务器（见 dev-linking.md 的具体跨域/路径坑）。

## 5. 我实际读到的文件清单（供复核）

- `pnpm-workspace.yaml`：workspace 含 `packages/plugins/*`，`allowBuilds.vue-demi=false`（vue-demi 不跑 postinstall，**别让 plugin 依赖 vue-demi**）。
- 插件 `package.json`：deps=`@mini-canvas/canvas-core-v2: workspace:*`，peer=`vue ^3.5.34`，devDeps=`typescript ~6.0.2, vite ^8.0.12, vue ^3.5.34`。**无 build/dev script、无 @vitejs/plugin-vue**（要自己加）。
- 插件 `tsconfig.json`：`moduleResolution: Bundler, isolatedModules, types:[]`，include 只 `src`。
- `canvas-core-v2/package.json`：deps=`@vue-flow/core ^1.48.2, pinia, vue`；devDeps 里 workspace 引用两个插件包（宿主在 dev 期静态 import 插件的原因）。
- `canvas-core-v2/vite.config.ts`：dev 服务 root=demo-web，port 5199。
- 插件 `index.ts`：`export { nodeTextPlugin }`，且带 `if (import.meta.hot) accept(['./nodeTextPlugin']…)→reloadPlugin`（HMR 现成）。
- `src/host/createMiniCanvasHost.ts`、`demo-web/CanvasDemo.vue`：装配/加载契约如上。
- 参照先例：`packages/prosemirror-editor-bundle/{vite.config.ts,package.json}`。

## 6. 建议落地顺序（后续若要实现）

1. 给两插件包加 `@vitejs/plugin-vue` devDep + 上文 dev `vite.config.ts` + `dev` script（dev 先行，成本最低、先打通 vue 单例）。
2. 宿主 demo 把某个插件的 import 换成 dev URL，验证动态 import + installPlugin + HMR。
3. 再补 lib build `vite.config.ts` + `build`/`build:types` script（参照 prosemirror 先例 + lib-build.md）。
4. 产物冒烟：起一个纯静态服务器加载产物 js，宿主 `<script>` 或 `import()` 后 installPlugin。
