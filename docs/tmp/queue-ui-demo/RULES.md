# 队列 + 目标 输入区 UI 规则（从反复纠错里提炼）

> 来源：2026-10-09 与用户逐轮打磨 `docs/tmp/queue-ui-demo/debug.html` 时的全部纠错。
> **这份是"下次别再犯"的清单**：每条都写成「曾经做错 → 正确做法」。
> 可调参考页：`docs/tmp/queue-ui-demo/debug.html`（左侧 UI + 右侧状态控制台）。

---

## 0. 一句话总纲

输入区自上而下是：**消息区 → 聚合容器（目标行 + 队列行）→ 输入框**。
聚合容器**紧贴输入框（零间隔）**，宽度 **90% 居中**，**只有外层容器有圆角，内部行一律方角**。

---

## 1. 布局与几何

| # | ❌ 曾经做错 | ✅ 正确做法 |
|---|---|---|
| 1.1 | 队列宽度 80%，看着别扭 | **90%**，居中 |
| 1.2 | 队列和输入框之间有间隔（10px） | **零间隔**：容器 `margin:0`，与输入框边框**重叠 1px**（`margin-bottom:-1px`），看起来拼成一体 |
| 1.3 | 内部行自己带圆角 | 外层容器 `border-radius:14px`；**内部行 `border-radius:0`**（只有外层有圆角） |
| 1.4 | 容器没有边框 / 只有部分边框 | 容器**四边** `1px solid` 描边 + 圆角 |
| 1.5 | 目标和队列分成两个块 | **聚合成一个容器**，都在输入框**外面**；顺序：目标行 → 队列行 |

## 2. 目标的两个阶段（都要有口径开关）

目标分两个阶段，**UI 不同、位置不同，但两处都要有口径开关**：

| 阶段 | 位置 | 内容 | 右侧按钮 |
|---|---|---|---|
| **未发送** | **输入框内侧顶部** | `⊙ 目标 · 剩余预算 996k` | 口径开关 + 取消 ✕ |
| **已发送** | **聚合容器里的目标行** | `⊙ <目标文案> · 状态 · 第 N 轮 · 剩余预算 996k` | 口径开关 + 暂停/启动 + 结束 ✕ |

- ❌ 曾经：目标放在输入框内部、又给了它一个"目标内容"输入框（与下面输入框重复）。
  ✅ 正确：**目标内容就是输入框里的正文**，标签不重复显示目标正文。
- ❌ 曾经：未发送阶段只显示"预算"，没有口径开关。
  ✅ 正确：**未发送也要有口径开关**（用户口径：不管正在编辑还是已发送运行，都能改口径）。

## 3. 目标标签（未发送）细则

- 标签左侧**只写"目标"两个字**（❌ 曾经把目标文案也塞进标签，和输入框重复）。
- **预算紧跟"目标"之后**（❌ 曾经把它推到最右端）。
- 预算**不要背景、不要边框**（❌ 曾经有白色背景）。
- 右端依次是：口径开关 → 取消 ✕。

## 4. 预算（token 数字）的显示与编辑

### 4.1 单位换算（❌ 曾经直接显示 `1,048,576,000` 这种长串）

按量级换算，**两套单位都实现**，可切换：

| 量级 | 国际 | 中文 |
|---|---|---|
| 10³ | `k` | — |
| 10⁴ | — | `万` |
| 10⁶ | `M` | — |
| 10⁸ | — | `亿` |
| 10⁹ | `B` | — |
| 10¹² | `T` | `万亿` |

- 小于 1000 原样；一位小数，去掉尾随 `.0`。
- 用户输入要**能解析** `50k` / `1M` / `1B` / `5万` / `1亿`；留空 = 不限。

### 4.2 编辑方式：行内 contenteditable（❌ 曾经弹一个对话框）

- **不要弹层**。把数字做成 `contenteditable` 的 span，**点进去就地编辑**，回车/失焦提交，Esc 还原。
- **宽度自适应**：用 contenteditable 天然跟着文字伸缩（❌ 曾经固定宽度）。
- 下划线用 **CSS `text-decoration: underline`**，**不是 `border-bottom`**（❌ 曾经用边框，1px 边框把文字压下去、造成错位）。
- 焦点时下划线变实、变色。

## 5. 口径开关：**只有两个状态**，而且都叫预算

- ❌ 曾经做成三态「预算 / 已用 / 剩余」。
  ✅ 正确：**两态 ——「已用预算」⇄「剩余预算」**。两个都叫"预算"，它决定"你现在看到的这个数算已用还是算剩余"。
- 它是一颗**按钮**，放在**关闭按钮（✕）的左侧**，**样式与关闭按钮一致**（同尺寸、同 hover）。
- 点击后**换图标**：
  - 已用预算 → 实心漏斗
  - 剩余预算 → 空心漏斗
- 切换的同时改**前缀文案**（"已用预算" / "剩余预算"）。
- 预算设为「不限」时，只能看「已用预算」。

## 6. 队列

- 行内操作：**引导是纯图标按钮**（❌ 曾经带"引导"两字，被挤成竖排折行），与删除、⋯ 同排同尺寸。
- **暂停/恢复按钮**（❌ 曾经放在队列头部占一整行）：
  - 位置：**骑在"队列容器"与"输入框"的分界线上**，水平居中，**一半压队列、一半压输入框**。
  - 形式：**图标 + 文字 + 队列条数**；文字前缀带"**队列**"（"队列暂停 3" / "队列恢复 2"），便于和目标的按钮区分。
  - 暂停态整颗按钮换成警示色。
- 队列行的编辑态：弱琥珀底 + "编辑中"徽章，队列整体阻塞。

---

## 7. 「回到底部」按钮

- ❌ 曾经骑在输入框上边框（夹在队列和输入框之间，成了间隔的来源）；也曾贴到左边。
- ✅ 正确：放在**对话内容区（消息区）内部、底部居中**。有滚动条且未滚到底时才出现。

---

## 8. 文字对齐（本轮最痛的坑）

- **根因**：同一行里两段文字**字号不同**（12px vs 11px），字形高度不同，看着就不齐。
- ✅ 规则：**同一行相邻的文字，字号 / 行高 / 盒高 / 内边距必须完全一致**。
- 下划线一类装饰**不要用 `border`**（会改变内容盒、把文字推偏），用 `text-decoration` 或 `box-shadow`。
- 验证方法：用 `Range.getBoundingClientRect()` 量**文字叶子节点**的底边，差 < 1px 才算齐（量盒子会骗人）。

---

## 9. 极端情况防护

- 次要信息（进度条、轮次）**可压缩、可隐藏**；**操作按钮永不被挤走**。
- 超长文本（含无空格长串）**单行省略号截断**，行高不变。
- 面板变窄（窄/极窄）时逐级让位：进度条 → 轮次 → 状态徽章；按钮始终保留。
- **行高必须稳定**（目标行/队列行都 36px 级别）。

---

## 10. 主题与颜色

- 所有 `--ui-*` 变量**亮/暗两套都要有值**（❌ 曾经暗色下用了只有亮色定义的 `--ui-hover-strong`，兜底成浅色 ⇒ hover"发白"）。
- **"不透明底 + hover" 用叠加半透明**（`linear-gradient(半透明,半透明) + 底色`），**不要直接替换背景色**——替换在不透明底上会让暗色发白。
- 颜色/圆角/字号统一走 `docs/design/ui-style-guide.md` 的 token，不自造。

## 11. 我（助手）该有的流程

1. **先量数据再下结论**：对齐/溢出这类问题，用 `getBoundingClientRect` / `Range` 量真实数值，不靠肉眼猜。
2. **一次只改一处、改完立刻验**：改完马上在调页面点一遍（含亮/暗、极端值、窄面板）。
3. **用户说"不对"时先复述他的规则**再动手；反复被纠正的点，回到本文档补一条。
4. **留一个可调试页**：左侧真实 UI、右侧状态开关（本篇 `debug.html` 即模板）。
