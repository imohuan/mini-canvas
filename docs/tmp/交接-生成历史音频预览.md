## 二、当前架构与文件清单

- **MediaViewer.vue**（theme-default/components/ui/）：全屏查看器。props:
  item{name,kind,url,text,list,index} / onDelete / previewComponents。
  树内用 useUiComponent 取 audioPreview/videoPreview/textPreview 渲染；树外（历史弹窗）
  由宿主传 previewComponents（ModalsArea 用 uiComponentOf 从宿主 readyHost.ctx 读）。
  三类媒体包在 .mv-plugin-stage（640×min200 白底圆角，事件全 stop 防拖拽/误关）。
  树外取不到注册件时回落原生 img/video/audio/pre。
- **MediaPreviewOverlay.vue**（plugin-bottom-bar）：底栏素材卡预览，包 MediaViewer，
  删除=断开素材连线（mediaPreview.ts 的 nodeId/owner）。
- **ModalsArea.vue**（ui/areas）：生成历史 = masonry 瀑布流。卡片 DOM 由 JS 手工创建
  （createMasonryElement / buildMediaCard / buildErrorCard，innerHTML 拼接）。
  音频卡优先挂注册件 AudioPreview（createApp 动态挂载），下方 .hist-card-foot 信息条
  （上下布局）。图片/视频/异常卡是 innerHTML 静态结构。
  **关键坑：卡片样式在非 scoped 的第二个 <style> 块**（hist- 前缀）——因为 JS 手工 DOM
  带不上 Vue scoped 的 data-v 属性，scoped 样式对它们全部失效（踩过：信息条 position
  变 static、渐变条消失）。
- **AudioPreview.vue**（plugin-node-audio）：~380 行，从 AudioContent **复制**出来的
  轮播波形播放器（url/name/waveform props，无节点依赖）。**这就是用户指出的设计问题**。
- **AudioContent.vue**（plugin-node-audio，1114 行）：audio 节点内容段。波形模型：
  单层竖条 + is-played 染色；轮播窗口（WINDOW_SECONDS=20，格子锚绝对时间）；
  按需算峰值（audioSource.openAudioSource().peaks + PeakCache）；无音频占位符 + 上传 +
  刷新按钮；nodrag/nopan/nowheel 手势契约（只有按钮/播放头拦画布手势）。
- uiCatalog：canvas-render/src/contracts/uiCatalog.ts（useUiComponent）。

两份必然漂移。**用户明确要求**：抽通用组件（如 AudioWavePlayer.vue），吃
{url, name?, waveform?, compact?}——内含 audio 元素+波形+进度条+播放按钮+时间条；
AudioContent 用它（外面保留空态占位/上传/刷新/节点读写），AudioPreview 直接 = 通用组件
薄壳（**无 url 时什么都不渲染**，没有占位符）。

- AudioContent 的 settings 读取（audioWaveHeight/audioBarMinWidth）、ensureAudioMeta/
  reanalyzeAudio（audioOps.ts）留在 Content；通用组件只管播放与波形展示。

  段剪进通用组件（Content 里删掉）。

- 测试：audioContentRender.test.ts 锁了单层波形/is-played/条宽 CSS 变量；改完必须保持
  通过（渲染入口仍是 AudioContent）。plugin-node-audio 现 94 条全绿。
- 改完跑：pnpm -C packages/plugins/plugin-node-audio test / typecheck；再 build:assets
  + Chrome MCP 实测（见五）。
