# 引擎可抽槽位分析：node-shell / edge / background 技术可行性与卡点

> 基于 `自定义组件契约.md`（实读 .d.ts）逐条分析"把 node 外壳 / 连线 / 背景从宿主抽成主题插件注册组件"的可行性。

---

## 0. 一句话结论

- **node-shell 抽槽：可行且是标准做法**——nodeTypes 契约天然允许"主题插件提供一个总壳组件"，壳内放 Handle/title/toolbar 各段（与现有 BaseNode 一致）。
- **edge 抽槽：可行且成熟**——`:edge-types` 给齐 EdgeProps，主题实现 `<g>` 边即可；把 CustomEdge 从"内置"变"主题注册"成本低。
- **background 抽槽：无注册口，但用"低层 child 叠加组件"可实现**——背景本质是叠加层，`<VueFlow>` 内随便放谁在底层都行，不需要 @vue-flow 提供 background 类型注册。

---

## 1. node-shell（节点外壳）槽位

### 可行性：✅ 强可行（vue-flow 一等公民）

VueFlow 对节点自定义的唯一入口就是 `:node-types`，value 是组件（`NodeComponent`）。要把"外壳(端口/title/toolbar)"整体抽成主题提供：

- 引擎只需注册**一个默认总壳**到所有 type（或让主题传总壳），然后**按 `props.type` + 主题注册段**分发 content/title/工具栏。这正是现有 `CanvasDemo.syncNodeTypes()` 把每 type 都指到 `BaseNode`、BaseNode 再经 `resolveSegment(type,'content')` 解析的做法。
- 主题插件的"外壳组件"就是一个自定义节点组件，需遵循 NodeProps 契约；它根上放 `<Handle>` 完全合法（Handle 真实渲染在节点根内即可被测量）。

### 主题外壳槽位 API 建议（引擎如何把能力交给主题组件）

1. 引擎应把引擎级 props（`selected/dragging/resizing/connectable/zIndex/id/type/data` 等 NodeProps）**原样透传**给主题壳；把节点"段组件"（title/content/toolbar）与"端口声明"作为主题壳的**入参**（props 或 provide）。
2. **端口 id/type/position 是引擎事实，不能由主题任意发明**（连线靠它们寻址）。若主题要自定义端口外观，建议暴露一个"端口描述数组"给主题，主题在对应位置渲染 `<Handle :id :type :position>`。
3. 卡点（引擎侧要收口）：
   - VueFlow 状态 class（`.selected/.dragging/.is-pointer-hovered`）加在 VueFlow 的 `.vue-flow__node` 外框上，**不在**节点组件根上；若主题壳想用"选中即变"的 CSS，得靠 `selected` prop 自加 class（BaseNode 已示范 `.is-selected`），不能依赖框架外框类直接命中子元素（需 :deep）。引擎要在契约文档写清这一条。
   - `useVueFlow()` 无参在组件 setup 用即可；主题壳要在逻辑里改 store（删/增边）应拿到 store 引用而不是自己 createStore（防孤儿 store）。
   - Handle 的真实渲染约束（§见下）。

### 卡点/注意
- 必须保留至少一个真实 `<Handle>` 供测量；纯 CSS 圆球、浮动端口(MovingHandle)是视觉增强，可与真实 Handle 叠加。
- 选中环/阴影/LOD 等"外壳外观"逻辑抽走后，引擎要留出"主题壳 + 段组件"两层，避免外壳逻辑与引擎内核状态耦合太死。

## 2. edge（自定义连线）槽位

### 可行性：✅ 强可行（vue-flow 一等公民，现有 CustomEdge 已是范式）

- 引擎注册 `edgeTypes = { custom: 主题边组件 }`；每条边 `type:'custom'`。主题组件实现为 **SVG `<g>`**，用 `EdgeProps`（sourceX/sourceY/targetX/targetY/sourcePosition/targetPosition/sourceHandleId/targetHandleId/markerStart/markerEnd/id/source/target/selected/animated/data）自绘 path + 箭头 + 热区。
- 现有 `CustomEdge.vue` 就是"完整可抽主题边"的活样板：几何抽到 `edgeGeometry.ts`（纯函数可测），装配在 .vue；选中/流光靠 props + inject 的自有集合，改 inject 为 "读 props.selected + 主题自己订阅内核选中" 即可脱离宿主耦合。
- 引擎把 **EdgeProps 全量交给主题边**，就是给它全部所需（选中/端点/动画/marker/数据）。`props.selected` 已含边自身选中。

### 卡点/注意
1. **marker**：`EdgeProps.markerStart/markerEnd` 是已解析 url 字符串，绑 `:marker-end` 即可，无需主题自建 marker defs。
2. **动画**：`animated` 只是标记，CSS 流光要主题自写；需用**非 scoped style** 覆盖 `.vue-flow__edge.animated path{stroke-dasharray:5}`（CustomEdge.vue:361 已示范）。这是 vue-flow 默认样式与主题自定义边的冲突点，要在主题模板里固定带这个覆盖。
3. label 若走 HTML 层需 `<EdgeLabelRenderer>` + 自己算 labelX/labelY（EdgeTextProps）。可不做，纯 SVG label 也行。
4. 连接拖拽的临时边（connection-line）：用 `FlowSlots['connection-line']` 槽（flow.d.ts:322）可定制拖拽预览线，`ConnectionLineProps` 在 connection.d.ts:62-89（含 sourceNode/sourceHandle/connectionStatus/valid）。若主题想让拖线观感统一，可把此槽也纳入主题。
5. edge 的 `.vue-flow__edge` 外框与节点同理：选中外框类在 SVG `<g class="vue-flow__edge ...">` 上，主题 `<g>` 根用 props.selected 自管。

## 3. background（画布背景）槽位

### 可行性：⚠️ 无注册口，但可用"低层叠加组件"实现

- vue-flow-core **没有** background 类型注册机制，也没有默认背景（`<Background>` 是用户放 `<VueFlow>` 的子叠加层）。
- 因此"主题提供自绘背景"走的通用做法：**引擎留一个"背景槽位" = 在 `<VueFlow>` 内部、viewport 之下渲染主题给的任意组件**（绝对定位铺满、pointer-events:none），而不是期望 vue-flow 去 `:background-types` 分发。
- 主题背景组件要跟随画布，用 `useVueFlow()` 读 `viewport`（`{x,y,zoom}` ref）做平移/缩放（把视口 transform 应用到背景层），或用 `screenToFlowCoordinate/project` 换算；需要"内容网格/缩略骨架跟随节点"时可读 `getNodes()`。
- 若主题只是想复用 vue-flow 自带图案，可选自带 `<Background variant gap size ...>`；要完全自绘就走上面的低层组件，或用 `<Background>` 的 `default`/`pattern` 槽注入自绘图案。

### 卡点/注意
- 叠加层**层级**：要垫在节点/边之下，需 z-index 或 DOM 顺序保证（放 VueFlow 最内层、节点渲染之前/之下）。引擎若提供"背景槽"，要规定该槽渲染在 VueFlow 内部哪个层级（建议与自带 Background 同层：Pane 内、NodeRenderer/EdgeRenderer 之下）。
- `Panel` 位置是固定屏幕角（top-left 等），**不适合做画布平移背景**，只适合放控件；别把它当背景槽位。
- 主题背景不依赖 @vue-flow 类型契约，依赖"引擎自定义槽位 + useVueFlow store"，所以背景槽位的 API 完全由引擎定义（传入 zoom/尺寸/变换，或让主题自取）。

---

## 4. 三种槽位共性：store 访问统一

主题组件（node-shell / edge / background）都要"读当前实例/节点/边/选中/缩放"：
- **组件内**：`const { viewport, getNodes, getEdges, onConnect, getSelectedNodes, removeEdges, ... } = useVueFlow()`（无参 = 注入当前实例）。
- **纯逻辑/服务层**：不要自 `useVueFlow()` 建孤儿 store；引擎应通过 `@pane-ready`(`onPaneReady` 传 `VueFlowStore`) 或模板 ref（`flowRef.value` 暴露 store 上全部 getters/actions）把实例存到内核/服务，再分发给主题逻辑。
- 主题组件之间传事件/数据：优先 VueFlow store 的 `on*`（节点点击/连边等）或引擎内核，避免用全局单例，保证多画布实例互不污染。

## 5. 建议的引擎槽位抽象（草案，供后续设计细化）

| 槽位 | 注册口 | 主题组件收到的 props/上下文 | 备注 |
|---|---|---|---|
| nodeShell | `:node-types`（引擎注册总壳，总壳按 type 再分发主题段） | NodeProps 全集 + 主题"段组件(标题/content/工具栏)" + 端口描述 | Handle 必须真实渲染在壳根内；状态 class 用 selected prop 自管 |
| nodePort | 引擎把端口 id/type/position 交主题壳自渲染 `<Handle>` | `{ id, type, nodeId, position, connectable }` | Handle 契约见 HandleProps |
| edge | `:edge-types` | EdgeProps 全集（sourceX..markerEnd/selected/animated/data） | SVG `<g>`；覆盖 `.vue-flow__edge.animated path` 动画 |
| connectionLine（可选） | `FlowSlots['connection-line']` | ConnectionLineProps | 拖线预览定制 |
| background | 引擎自定义低层叠加槽（非 vue-flow 注册口） | 引擎传入 transform/zoom 或自 useVueFlow() | 无背景类型机制；纯叠加层 |
