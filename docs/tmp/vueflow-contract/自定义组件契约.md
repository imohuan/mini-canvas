## 1. 自定义节点组件 `:node-types`

### 1.1 契约类型

`dist/types/components.d.ts:9-12`

```ts
export type NodeComponent =
  | Component<NodeProps>            // 组件定义
  | DefineComponent<NodeProps, any, any, any, any>
  | GlobalComponentName             // 字符串名（注册到 app 的全局组件，自动按名解析）

export type NodeTypesObject = {
  [key in keyof DefaultNodeTypes]?: NodeComponent
} & Record<string, NodeComponent>   // 任意自定义 type 键
```

**结论：value 是"组件定义"（不是 `{ render }` 包装对象）**，直接给组件构造器（SFC 的 `defineComponent` 返回值）即可。字符串形式则必须是全局注册过的组件名。
默认键来自 `DefaultNodeTypes = { input, output, default }`（components.d.ts:25-27）。传入 `<VueFlow :node-types="map">`（prop 类型 `NodeTypesObject`，见 VueFlow.vue.d.ts:21 与实例字段 line 577）。

### 1.2 自定义节点收到哪些 props

`dist/types/node.d.ts:144-207` `NodeProps`：

```ts
export interface NodeProps<Data, CustomEvents, Type> {
  id: string
  type: Type
  selected: boolean
  connectable: HandleConnectable   // 'single' | boolean | number | (node,connectedEdges)=>boolean
  position: XYPosition             // @deprecated 相对位置；新用 computedPosition
  dimensions: Dimensions
  label?: string | VNode | Component | object   // @deprecated
  isValidTargetPos?: ValidConnectionFunc        // @deprecated
  isValidSourcePos?: ValidConnectionFunc        // @deprecated
  parent?: string                 // @deprecated 用 parentNodeId
  parentNodeId?: string
  dragging: boolean
  resizing: boolean
  zIndex: number
  targetPosition?: Position
  sourcePosition?: Position
  dragHandle?: string
  data: Data                       // 业务 data，NodeProps 泛型默认 Data
  events: NodeEventsOn<CustomEvents>  // @deprecated
}
```

注意 **`dragging`、`selected`、`resizing`、`connectable`、`zIndex` 都是节点级状态 props**，VueFlow 在渲染节点组件时逐一传入。`connectable` 需要节点组件**转发给 Handle** 才生效（见 §2）。

> 完整运行时节点 = `GraphNode`（node.d.ts:125-143），在 `NodeProps` 基础上多了 `computedPosition / handleBounds / dimensions / isParent / selected / resizing / dragging / data / type` 等。**状态 class（如 `.selected`）不靠节点自己加**，见 §1.4。

### 1.3 组件里怎么用 useVueFlow / 拿节点

- 在节点组件 `<script setup>` 里 `const vf = useVueFlow()` 即可拿到当前 store（无参时走 context 注入），`props.id` 即节点 id。
- 便捷数据组合式（契约里被设计成"节点组件专用"）：
  - `useNodeId()`：`InjectionKey<string>`，取当前渲染节点 id（`context/index.d.ts:6`）。
  - `useNodesData(id)` / `useEdgesData(id)`：响应式取该节点/边数据。
  - `useHandleConnections({ id, type, nodeId })` / `useNodeConnections()`：取一个 handle 相连的连接。
  - 也可 `const { getNodes, findNode } = useVueFlow()` 后 `findNode(props.id)`。
- 订阅节点自身事件：`useNodeHooks` / `useEdgeHooks`；或直接用 `vf.onNodeClick(...)` 等（store 上带 `on*`，见 VueFlow.vue.d.ts:317 起）。

### 1.4 节点根的 class / handle 识别（谁加 `.selected`）

关键事实：**`.vue-flow__node.selected`、`.vue-flow__node.dragging` 等状态 class 是 VueFlow 的 `NodeWrapper` / 渲染器在节点**外框** DOM 上加的**，不由节点组件自己管；节点组件自己只管根元素内部的外观。

- 现有 BaseNode 的 `.v2-node.is-selected` 是**自管状态**：BaseNode `defineProps` 收了 `selected`，并透传 `inheritAttrs: false`，然后模板里 `:class="{ 'is-selected': selected }"`（BaseNode.vue:18,153-157）。即**用 `selected` prop 驱动自己的状态 class**，而不是依赖 VueFlow 给加的 `.selected`。
- VueFlow 外框结构：`<div class="vue-flow__node ...">` 包住 node component 根。BaseNode 用 `inheritAttrs:false` 防止 VueFlow 的 attrs 落到根、避免 DOM 嵌套破坏 `.vue-flow__node` 的结构。
- **Handle 识别**：Handle 必须在节点 DOM 内被**真实渲染**，VueFlow 用 ResizeObserver/`useHandle` 测量其相对节点根的偏移（`HandleElement { id, position, type, nodeId, x, y, width, height }`，handle.d.ts:8-13）注册进 `node.handleBounds.source/target`（node.d.ts:19-22）。所以 Handle 必须落在节点根内、且随节点缩放一起；节点壳组件内放 `<Handle>` 是标准做法（§2）。

### 1.5 CanvasDemo 现有用法（佐证）

`CanvasDemo.vue`：
- `nodeTypes` 是**响应式 map**，值全部指向同一个壳组件 `BaseNode`：`for (const t of types) map[t] = BaseNode`（line 78-82）。
- 通过 `:key="nodeEpoch"` 在插件热装/卸后 bump，强制 `<VueFlow>` 子树重挂以用最新注册表。
- 因此"业务 type → 节点"的映射其实收敛在**壳组件内部**（BaseNode 用 inject 的 `NODE_REGISTRY_KEY` + `resolveSegment(type, 'content')` 去解析每 type 的 content 段组件）。这正印证：**nodeTypes 只需一个"总壳"，壳再按 type 分发**，跟"主题插件提供外壳组件注册进 nodeTypes"这一重构目标兼容——主题插件应替换/提供这个总壳组件。

## 2. Handle（端口）契约

### 2.1 props

`dist/types/handle.d.ts:44-59` + `Handle.vue.d.ts`：

```ts
export interface HandleProps {
  id?: string                      // handle 唯一 id（同 node 内区分 source/target 多口）
  type?: HandleType                // 'source' | 'target'（handle.d.ts:7）
  position?: Position              // Position.Left/Top/Right/Bottom（'left'|'top'|'right'|'bottom'）
  isValidConnection?: ValidConnectionFunc
  connectable?: HandleConnectable  // boolean | number | 'single' | func
  connectableStart?: boolean       // 可否作起点
  connectableEnd?: boolean         // 可否作终点
}
```

- `NodeProps.connectable` **需要转发到 Handle 的 `:connectable`** 才有意义（node.d.ts:152 注释）。
- Handle 触发的事件：`@click`、`@pointerdown`（Handle.vue.d.ts 的 emit：`handleClick`、`handlePointerDown`）。

### 2.2 为什么 Handle 必须真实渲染在节点 DOM 内？

Handle 的定位与注册依赖 DOM 实测：它在挂载/尺寸变化时向 store 上报相对**节点根元素**的 `x/y/width/height`（handle.d.ts `HandleElement extends XYPosition, Dimensions`），写入 `node.handleBounds`，VueFlow 由此把边的 source/target 端点钉在 handle 上，且连接拖拽从 handle DOM 起算。handle 不在节点渲染树内 = 测不到位置 = 连不上/端点错位。

### 2.3 可否由"主题外壳组件"放 Handle？

**完全可以，且这正是重构方向**：外壳组件（BaseNode 这类）就是"自定义节点组件"，Handle 作为其**子元素**渲染在壳根内，天然满足"真实渲染在节点 DOM"。所以"外壳组件注册进 nodeTypes"与"壳内放 Handle"不冲突。

需要留意的实现点（现有 BaseNode + MovingHandle 已示范）：
- MovingHandle（canvas-core-v2 现端口组件）内部最终必须**渲染至少一个真实 `<Handle>`**（锚点）供 VueFlow 测量；浮动圆球是视觉层，可多放 `<Handle>`（同 `id` 会合并）。
- BaseNode 里 `MovingHandle` 通过 `id="source"`、`type="source"`、`:position="Position.Right"` 等 props 把 handle 交给端口组件，多个源口用不同 `id`（`source-a`/`source-b`）。
- 端口的 `sourcePosition/targetPosition` 状态可在 node data 或外层设 `sourcePosition/targetPosition`（Node 字段 node.d.ts:40-42），由 NodeProps 透传下来。
- 若外壳允许"主题自定义端口组件"，建议槽位 API 让主题组件拿到 `{ id, type, nodeId, position }` 再内部渲染 `<Handle>`，**Handle 的 `id`/`type`/`position` 是引擎级事实，不能由主题发明**（连线按它寻址）。

## 3. 自定义连线 edge `:edge-types`

### 3.1 契约类型

`dist/types/components.d.ts:13-24`

```ts
export type EdgeComponent =
  | Component<EdgeProps>
  | DefineComponent<EdgeProps, any, any, any, any>

export type EdgeTypesObject = {
  [key in keyof DefaultEdgeTypes]?: EdgeComponent
} & Record<string, EdgeComponent>
export interface DefaultEdgeTypes {
  default: typeof BezierEdge
  straight: typeof StraightEdge
  simplebezier: typeof SimpleBezierEdge
  step: typeof StepEdge
  smoothstep: typeof SmoothStepEdge
}
```

### 3.2 Edge 组件收到的 props

`dist/types/edge.d.ts:171-196` `EdgeProps`：

```ts
export interface EdgeProps<Data, CustomEvents, Type> extends EdgeLabelOptions, EdgePositions {
  id: string
  sourceNode: GraphNode
  targetNode: GraphNode
  source: string
  target: string
  type: Type
  label?: string | VNode | Component<EdgeTextProps> | object
  style?: CSSProperties
  selected?: boolean               // 边是否选中（运行时注入）
  sourcePosition: Position
  targetPosition: Position
  sourceHandleId?: string
  targetHandleId?: string
  animated?: boolean               // edge.animated
  updatable?: boolean
  markerStart: string              // 已是渲染好的 marker url 字符串
  markerEnd: string
  curvature?: number
  interactionWidth?: number
  data: Data
  events: EdgeEventsOn<CustomEvents>
}
// EdgePositions (edge.d.ts:150-155):
export interface EdgePositions {
  sourceX: number; sourceY: number; targetX: number; targetY: number
}
```

- 边根元素应为 **`<g>`（SVG）**，因为 edge 渲染在 `<svg>` 内。
- **marker**：`markerStart/markerEnd` 已是解析好的 `url(#...)` 字符串（EdgeProps 上 String），可直接绑 `:marker-end="markerEnd"`。
- **几何**：端点坐标 `sourceX/sourceY/targetX/targetY` + 两侧 `Position` 已算好；曲线形状可用 `getBezierPath({ sourceX,sourceY,targetX,targetY,sourcePosition,targetPosition })`（dist/index 导出）生成 `d`。
- **label** 渲染在 HTML 层（非 SVG），通常配 `<EdgeLabelRenderer>`（导出组件）+ `BaseEdge` 的 labelX/labelY 计算。
- 复刻现有流光边时可直接照 CustomEdge.vue 的结构：外层 `<g>` + 多条 `<path :d="edgePath">`。

### 3.3 选中/动画/"flow 状态"怎么拿

- 边自身选中：`props.selected`（EdgeProps 运行时注入）。
- 动画：`props.animated`（edge.animated 真值）只是开关标记，**流光是否真正跑动由 `stroke-dasharray + CSS animation` 控制**。CustomEdge.vue 里用 `props.forceFlow || isHighlighted` 决定是否走流光，把 `pathLength="300"` + `@keyframes ef-dash { to { stroke-dashoffset: -100 } }` 写成 CSS，并**用非 scoped `<style>` 覆盖** VueFlow 自带的 `.vue-flow__edge.animated path { stroke-dasharray: 5 }`（CustomEdge.vue:361-366）。这证明：**边组件需自行写选择器/类来达成"选中高亮、相连高亮、流光"**，而不是依赖框架注入样式。
- 其它状态：`props.sourceNode/targetNode`（GraphNode，含 `selected`），可判断端点是否被选。

### 3.4 CanvasDemo / CustomEdge 现状对比

- `CanvasDemo.vue:85`：`const edgeTypes = { custom: CustomEdge }`（普通对象，非响应式），边元素给 `type:'custom'`。
- CustomEdge `defineProps<EdgeProps & CustomEdgeExtraProps>()`，用 `props.sourceX/sourceY/targetX/targetY/sourcePosition/targetPosition/sourceHandleId/targetHandleId/id/source/target/selected` 计算路径与高亮。
- 现状高亮判定不走 `props.selected`（仅作兜底 line 75），而走 inject 的选中集合 `EDGE_SELECTION_KEY`（宿主把内核选中 id 同步进来）。重构为插件槽位后：主题边组件应能**自身决定读 `props.selected` 还是外部注入**——契约给齐了 props，选择权在主题。

## 4. 自定义背景 Background

### 4.1 事实：vue-flow-core 没有"background-types"注册口

- **没有** `:background-types` 之类 prop，也没有把 `<Background>` 自动渲染进 VueFlow。`Background` 由子包/自引组件提供，作为**手动放进 `<VueFlow>` 的子元素（叠加层）**。
- 自带 Background 的 props 只是样式配置（`dist/components/Background/types.d.ts`）：

```ts
export type BackgroundVariant = 'dots' | 'lines'
export interface BackgroundProps {
  id?: string; variant?: 'dots'|'lines'; gap?: number|number[]; size?: number
  lineWidth?: number; color?: string; x?: number; y?: number; offset?: number|[number,number]
}
```

### 4.2 完全自绘背景的三条通用做法

1. **替换叠加层**：不渲染 `<Background>`，而是在 `<VueFlow>` 内放**自己的全屏自定义组件**，`position:absolute; inset:0; pointer-events:none`，画在 viewport/节点之下。这是最彻底、最贴合"主题插件提供背景"的做法——背景本质就是"画布底层一块内容"，没有任何注册口约束，谁都能塞。
2. **用 `<Background>` 的 `default` 槽**：自带 Background 声明了 `default(_:{id:string})` 与 `pattern(_:{})`、`pattern-container` 槽（Background.vue.d.ts 的 slots），可在保留其定位/平移机制前提下自绘 pattern 内容。代价是仍受其布局逻辑。
3. **用 `<Panel position>` 只是固定叠加，不适合当"背景"**（panel.d.ts：`top-left/top-center/...` 六个角），适合放 UI 控件，不适合做跟随画布的底。

> 推荐结论给引擎：背景作为 `<VueFlow>` 的**一个低层 child 叠加组件槽位**（插在 viewport 下面、最底层），由主题插件提供；引擎只负责"决定渲染哪个背景组件 + 传 zoom/尺寸/变换 props"。要跟随画布平移缩放，主题组件可 `useVueFlow()` 读 `viewport`（Ref）做 `background-position/transform`，或直接用 `project()`（zoom.d.ts `Project = (position)=>XYPosition`）。

## 5. store/实例访问（useVueFlow 返回什么）

`composables/useVueFlow.d.ts`：`useVueFlow(id?)` / `useVueFlow(options?)` → **返回一个 `VueFlowStore`**（无 id 且 setup 内调用 = 注入当前实例；组件外调用会新建一个 store 注册进全局 storage，见 §6）。

store 实例字段（来源 `VueFlow.vue.d.ts` 实例侧 + `types/store.d.ts State`；store 结构见 dist/store/{state,getters,actions,hooks}.d.ts）：

- 响应式数据（Ref/ComputedRef）：`nodes`、`edges`、`viewport`（`{x,y,zoom}`）、`dimensions`、`zoomLevel`（经 viewport.zoom）、`connectionLookup`、`nodeLookup`、`edgeLookup`、`nodesSelectionActive`、`getNodeTypes`、`getEdgeTypes`、`getNodes`、`getEdges`、`getNode(id)`、`getEdge(id)`、`getSelectedNodes`、`getSelectedEdges`、`getSelectedElements`、`findNode/findEdge`…
- 方法/事件钩子：`onNodeClick/onNodeDoubleClick/onNodeDrag*/onConnect/onConnectStart/onConnectEnd/onNodesChange/onEdgesChange/onNodeMouse*/onPane*/onSelection*/onMove*/onViewportChange*/onPaneReady/onInit/onError` 等（VueFlow.vue.d.ts:317 起、hooks.d.ts FlowEvents/FlowHooksOn）。
- 操作：`setNodes/setEdges/addNodes/addEdges/removeNodes/removeEdges/updateNode/updateNodeData/updateEdgeData/applyNodeChanges/applyEdgeChanges/addSelectedNodes/removeSelectedNodes/...`、`screenToFlowCoordinate/flowToScreenCoordinate/project`、viewport 辅助 `zoomIn/zoomOut/zoomTo/setViewport/fitView/setCenter/fitBounds`（zoom.d.ts `ViewportFunctions` + `useViewportHelper`）。
- 常量：`flowId/id`、`vueFlowVersion`。
- 注意：`VueFlowStore` 通常由 pinia createStore 生成，内部把 State 字段用 `storeToRefs` 转成 ref。**访问响应式状态要带 `.value`**（如 `vf.viewport.value.zoom`），而方法直接调（BaseNode.vue:30 `vf.viewport.value?.zoom`、CustomEdge.vue:38 `removeEdges([id])`）。

主题插件组件内拿"当前画布实例 / 节点 / 边 / 选中 / 缩放"的推荐姿势：

```ts
const { getNodes, getEdges, onNodeClick, onConnect, getSelectedNodes, viewport, findNode, screenToFlowCoordinate, removeEdges } = useVueFlow()
watch(viewport, (vp) => console.log('zoom', vp.zoom))          // 缩放响应式
onNodeClick(({ node }) => { /* 点节点 */ })                     // 事件订阅
const zoom = () => viewport.value.zoom
```

## 6. 组件外部（纯逻辑 .ts）访问 vue-flow

- `useVueFlow(idOrOpts?)` 是**组件内可用、组件外也可用**的组合式：传入显式 `id` 或 `options` 时会 `createStore`（新建实例并注册进全局 storage），返回该 store。但组件外调用若**不带 id/opts** 且当前没有 VueFlow context，行为是"新建一个实例并注册到 storage"（useVueFlow.d.ts JSDoc 明说）。
- 这意味着：**纯逻辑/服务层要访问"某个已渲染画布"，正确方式不是自己 `useVueFlow()`（会建孤儿 store），而是**让宿主在 `@pane-ready`（`onPaneReady: EventHookTrigger<VueFlowStore>`）或 `@init` 回调里拿到 store 引用，存到服务层**；之后逻辑代码持有该 store 引用即可（不带 context 也能操作，因为已拿到实例）。
- VueFlow.vue.d.ts emits 里 `paneReady`、`init` 都传 `VueFlowStore`（line 250-251 / 345-346，onInit 与 onPaneReady 均注）。
- 模板 ref 姿势：`<VueFlow ref="flowRef">` → `flowRef.value` 暴露 VueFlow.vue.d.ts 的 expose（`id/emits/hooks/nodes/edges/getNodes/getEdges/.../vueFlowRef/viewportRef`），即组件实例上已带 getNodes/removeNodes/setViewport 等，CanvasDemo 层面也可这样取（当前 demo 用 props + 事件，未用 ref）。
- 现有代码佐证（canvas-core-v2）：三个 .vue 全部是**组件内 `useVueFlow()`（无参，走 context）**——
  - `BaseNode.vue:11,27`：`const vf = useVueFlow()`；读 `vf.viewport.value?.zoom`。
  - `CustomEdge.vue:8,38`：`const { removeEdges } = useVueFlow()`。
  - `CanvasDemo.vue`：不调 useVueFlow，纯用 `:nodes/:edges` props + `@connect/@node-click/...` 事件 + 自己的内核 host。
  - 尚无"顶层 store 全局访问"用例；canvas-core-v2 的状态真正源在**自研内核 host**（nodeStore/selection），VueFlow 只是渲染态——这也是为什么要"组件外部也能拿 store"，逻辑统一进内核。
