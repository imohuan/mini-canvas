### 真实 Bug（vitest 未覆盖）
- **现象**：首屏报 `启动失败：[core] Service "image" is not injected`
- **根因**：`CanvasDemo.vue` onMounted 写 `bootCanvas(new LocalStorageAdapter(), { plugins:[nodeImagePlugin] })` 传了**两参**，而 host.bootCanvas 只接受**单参**（adapter 或 BootOptions 对象），第二个 `{plugins}` 被丢弃 → image 插件没装。
- **为何 vitest 没抓到**：测试从不传两参，只有真实页面走 onMounted 才触发。
- **修复**：改单参对象 `bootCanvas({ adapter: new LocalStorageAdapter(), plugins:[nodeImagePlugin] })`。已提交 a5e91e2。修复后 reload 正常 boot，image 节点渲染，无 console 报错。
- vitest 全绿不变：83 passed。

### 未覆盖项：连边（诚实标注）
VueFlow 连线需要真实鼠标指针从 source handle 拖到 target handle。
chrome-devtools MCP 的 drag 工具是「元素拖放」，要求 from/to 都是 a11y 快照里的 uid，
而 VueFlow 的 handle 圆点不出现在快照中（无 uid），合成 PointerEvent 又因 isTrusted=false 不被 VueFlow 响应。
→ 无法用当前 MCP 可靠模拟真实连线。
连线校验（isValidConnection：自连/环/重复/朝向/类型）属于内核 M5，已由
`src/services/__tests__/connection.test.ts` 15 个用例全绿覆盖；UI 层 @connect + isValidConnection 接线源码确认正确。

### 技术备注（chrome-devtools MCP 用法）
- 操作前先 wait_for / take_snapshot 拿最新 uid（uid 会随快照变化）。
- 无右键工具：用 evaluate_script dispatch `new MouseEvent('contextmenu',{bubbles:true,clientX,clientY})` 到 `.vue-flow__pane`。
- a11y 快照比截图更适合确认内容（uid 列表 + 节点/文本/button 状态）。
- take_snapshot 必须传 pageId。
