## 你的原话

> 这边有一个问题，就是你这个UI里面这边有一个问题，你这个 UI 里面有个“向上滚动查看更早对话”，但是我这边好像没有效果 按理说，这个按理说，这个对话它应该是有一个历史记录的

## 要解决的问题

1. 滚到对话顶部时，更早的历史要真的被拉回来并显示在顶上方。
2. 拉到没有更早的历史时，那条「向上滚动查看更早的对话」提示要消失，不能一直挂着骗人。

## 问题原因

- 状态：已确认
- 复现步骤：打开「音频前后空白片段问题」这条会话（45 条转录，一轮里有 7 个工具调用），滚到消息区顶部。
- 证据：直接请求 `GET ...?turnsLimit=30&turnsBefore=4` 返回 `turns: []`、`turnsHaveBefore: true`；修复后同一请求返回 30 条。
  - 会话转录 41–44 号全是 tool / assistant；`agentSessions.ts` 的切页逻辑在这一页窗口里找不到 user 时，把 `start` 一路 `+= 1` 推到 `end`，切出空数组。
  - 前端 `loadEarlierTurns` 拿到空数组时条数不变、`turnsHaveBefore` 仍为 true，滚到顶只会反复重发请求，界面毫无变化。
- 根因：后端的「切点对齐 user 边界」只往前推、没有兜底；前端也没有把「空批次」当成「到底了」。

## 修改方案

- 改哪里：`agentSessions.ts` 的切页；`queue.ts` 的 `loadEarlierTurns`；`sessions.ts` 的首屏分页标记。
- 怎么改：切点查找不越过窗口——窗口里没有 user 就保持窗口起点，绝不返回空页，`turnsHaveBefore` 改成按**实际切点**算（`start > 0`）；前端收到空批次立刻把 `turnsHaveBefore` 置 false 停止重试；首屏转录为空时不标记「还有更早」。
- 为什么这样改：空批次是「到底」的确定信号；按实际切点判断能避免多拉一次；从 tool 中间切开不会产生孤立占位。
- 风险 / 影响面：只在长会话（一轮里工具调用很多、一页窗口里没有 user）时触发；短会话行为不变。
- 验证方式：补后端单测、前端空批次单测，并在真实浏览器里滚到顶看消息数量变化。

## 验收标准

- [x] 后端在窗口里没有 user 边界时不再返回空页
- [x] 前端收到空批次后不再反复请求
