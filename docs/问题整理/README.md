# 问题整理

这里把你提的每一个问题，整理成 AI 能直接照着做的小任务。

技能入口：`.codex/skills/issue-briefing/SKILL.md`

## 怎么用

1. 每个问题一个文件，文件名格式是 `编号-简短标题.md`。
2. 截图和参考图统一放在 `images/`，文件名也带编号。
3. 新问题照 `_模板.md` 的格式写。
4. 先看文件里的「待确认」。还有空白的地方，说明需要你补一句。
5. 确认方向后，再按「验收标准」和「执行指令」改代码。
6. 执行完成后，在当前文档头部改成「已完成」，勾选验收项，填写执行记录。

问题文档和图片都直接放在本目录，不再按日期或批次建子文件夹。新增和更新任务只写根目录的 `01`–`12`。

## 这批要解决什么

这批文档按最新 `task-v1` 结构整理，覆盖设置页、浮层组件、画布下拉、底栏、Agent 面板、快捷键配置，以及项目页插件面板与上下文分层。

最关键的公共改动是 11：把 DropdownMenu、Select、Popover、Tooltip、ContextMenu、Combobox 的箭头、间距和选中样式统一到「外观 → 浮层」配置中，避免继续在 60 多处调用点各写一套偏移。

## 建议顺序

1. 先做 11 的统一浮层配置骨架，确定箭头默认值、间距档位和组件选型。
2. 再修 06 的 Agent 下拉开合；否则 07、08、09、10 里的下拉内容都难以完整目验。
3. 接着处理 07、08、09、10 的模型、技能、MCP 内容与按钮尺寸。
4. 03、12 统一菜单选中和画布行尾图标；这两项会改变多个入口的观感，放在浮层骨架之后验收。
5. 01、02、04、05 是设置页与外壳改动，可与浮层骨架并行，但分别验收。
6. 18 是架构分层改动，放在其它界面问题之后单独做；它会改 Provider 位置、画布服务生命周期与默认主题拆分，先确认再动。
7. 22 先做：图标由 Agent 提供、底栏消费；20 抽出的 ModelPicker 直接带上图标，不用二次返工。
8. 20 再做：抽组件、注册 ui 件、底栏取件、删复制 / 删除。它会改变底栏「有没有动作」，必须排在 21 前面。
9. 21 最后做：底栏显示判定改为「有动作或预设入口」，并让音频等零动作节点也能出底栏。
10. 23 与 22 共用「平台图标」来源，建议 22 先把通用图标件落地，再做 23 的管理弹窗与账号二级菜单。
11. 24 已完成（打包/安装链路的骨架改动），实现与验证记录见该文档的「执行记录」。

优先级：06 和 11 先确定交互与配置契约；其余按影响日常使用的顺序处理。
