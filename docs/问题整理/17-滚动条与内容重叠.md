# 17 · 滚动条与内容重叠

## 你的原话

> 你这里有很多地方都没有使用 ui-development 提到的这个默认滚动条，你现在生成历史界面中和左侧侧边栏里面都已经应用了。……就选中之后，就和你的滚动条重合了。在我们的默认的浏览器行为中，它会单独扩展一个区域显示滚动条，它这个组件的话则是自动进行一个滚动，在容器内部渲染。这个时候就会存在这样的 UI 重合的问题，那么这个就必须要考验你的这个 UI 设计能力了，要如何设计才能美观。
>
> 先修改这几处代码（配 5 张截图：画布列表下拉、TV Director 全局设置、设置弹窗、shadcn 官方示例、资产侧边栏）。

## 要解决的问题

滚动条画在内容上面，和行选中高亮叠在一起。要把滚动条挪到自己的窄通道里（或把容器改成组件库 ScrollArea），让它细、低对比、不再压住行高亮。

## 范围与位置

- 页面：画布列表下拉（左上「画布 N ▾」弹层）、TV Director 全局设置弹窗、偏好设置弹窗（成品设置面板）、左侧「资产」侧边栏树列表

## 问题原因

- 状态：已确认
- 复现步骤：打开画布列表下拉并选中一行，或打开任一弹窗滚动正文；滚动条直接画在行/内容上面。
- 证据：① reka-ui 的 ScrollArea 滚动条是 position: absolute 覆盖层（ScrollAreaScrollbarImpl 内联样式），shadcn 默认 ScrollBar 宽 10px（w-2.5）；② 用户环境 Chrome 用覆盖式滚动条（scrollbar-width: thin 下滚动条画在内容上不占布局）；③ 全局设置与设置弹窗正文是裸 overflow-y: auto，没用 ScrollArea；④ 画布下拉内层滚动区没有给滚动条预留通道。
- 根因：自绘/原生滚动条都是覆盖式渲染，而行选中高亮是整行背景色，两者叠在一起；部分容器又没有走 ScrollArea。

## 修改方案

- 改哪里：见「怎么改」四条，涉及 ScrollPane.vue、DirectorSettingsDialog.vue、两套皮的 SettingsContent.vue 与 useSettingsNavigation.ts、DropdownMenuContent.vue。
- 怎么改：① ScrollPane 底座从 shadcn ScrollArea 改为原生溢出 div + scrollbar-gutter: stable（ScrollArea 的 reka 滑块是绝对定位覆盖层，gutter 在它上面不起作用，Chrome 实测 area=0）；② 全局设置正文滚动 div 换成 ScrollPane（body-class 保留原 px-4 pb-2）；③ 设置弹窗两套皮（packages/ui 与 plugin-theme-default）各加一个轻量 ScrollPane，.psd-body / .asp-body 改为挂它，useSettingsNavigation 的 setScrollEl 改接 scrollElement()；④ 画布下拉内层滚动区在 host.css 里把 auto 改成 stable（专用规则优先级高于工具类）。
- 为什么这样改：滚动条独立通道是浏览器原生行为（图 4 示例）；两处裸滚动统一收到 ScrollPane 后与生成历史/侧边栏一致，也符合 ui-development 技能「滚动容器用 ScrollArea/ScrollPane」的规矩。
- 风险 / 影响面：scrollbar-gutter: stable 让滚动区右侧常驻 6px 通道；设置弹窗滚动元素换 ScrollPane 后 setScrollEl 接法要跟着换，注意测试对源码结构的断言。
- 验证方式：pnpm -C packages/ui typecheck、pnpm -C packages/ui-kit-shadcn typecheck、pnpm -C packages/plugins/plugin-theme-default typecheck，再用 @Chrome 目验亮色/暗色。
