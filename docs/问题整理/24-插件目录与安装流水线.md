## 要解决的问题

插件是独立发布、独立更新的文件，不是界面包的源码依赖。dev 时为了调试，界面直接 import 插件源码；build 时界面包不包含任何插件，全部从 cloud-server 加载。

cloud-server 把全部插件打成独立目录随包发布，前端在首次启动时从这些目录装载；之后插件更新只替换对应目录，界面包不动。

## 问题原因

- 状态：已确认
- 复现步骤：打开 `packages/ui/src/assembly.ts` 与 `packages/ui/src/AppProvider.vue:34`，同一份 `resolveAppPlugins()` 在 dev 与 build 下都会执行；再打开 `packages/cloud-server/src/routes/npmPlugins.ts` 第 293–294 行，看按文件名猜前后端；最后看 `packages/cloud-server/src/static.ts:141` 的候选目录顺序。
- 证据：build 产物 `packages/ui/dist/assets/index-*.js` 里能搜到 `bottom-bar`、`plugin-manager`、`node-video`、`style-library`；30 个插件里有 20 个 `builtin`、10 个 `installable`；`assets/plugins` 只有 `plugin-cloud-client` 一个；`assembly.ts` 里没有任何 `import.meta.env.DEV` 分支；服务端搜 `web.entry` 是 0 处读取。
- 根因：装配清单没有区分 dev 与 build。dev 需要源码热更，build 需要可替换的文件，但两者共用同一份静态 import，导致 build 时插件被编进界面包；安装器又没有读作者声明的入口，只能靠文件名猜，落盘位置还按前后端拆开。

## 修改方案

按四步实施，第 1、2 步可以一起做，第 3 步依赖前两步，第 4 步最后做。

**第 1 步：安装器只认配置**

- 改哪里：`packages/cloud-server/src/routes/npmPlugins.ts` 的 `doInstall`、`packages/cloud-server/src/plugins/catalog.ts` 的 `buildPluginCatalog` 与 `readServerArtifact`。
- 怎么改：读 `plume.web.entry` 与 `plume.server.entry`（后者可选）；两者都没有就回 400 并写明缺哪个字段；`entry` 必须是包内相对路径，拒绝绝对路径与 `..`，扩展名只允许 `.js` / `.mjs`；声明的文件不存在就回 400 并写明缺哪个文件；删掉扫 `dist/*.js` 猜前后端的逻辑。
- 为什么这样改：入口由插件自己声明，安装器只校验，不靠命名巧合。
- 风险 / 影响面：现有插件多数没写 `web.entry`，需要构建脚本统一回填后再改安装器。
- 验证方式：用 `plugin-showcase` 真打 tarball，安装再卸载；另用删掉 `web.entry` 的包确认被拒绝。

**第 2 步：统一目录，并把入口写进构建产物**

- 改哪里：`packages/cloud-server/src/routes/npmPlugins.ts` 的落盘路径、`packages/cloud-server/src/static.ts` 的 `resolvePluginsDir`、`packages/cloud-server/src/server.ts:83` 与 `:155`、`packages/cloud-server/src/serverFramework/pluginLoader.ts`、各插件的 `vite.config.ts` 或构建设置。
- 怎么改：落点统一为 `<数据根>/plugins/<插件名>/`，包名去 scope 后作目录名；目录内保留 `package.json`，前端产物固定 `dist/web.js`，后台产物固定 `dist/server.js`；构建脚本负责把 Vite 产物重命名为 `web.js`，并在 `package.json` 的 `plume.web` 与 `plume.server` 里回填 `entry`，作者不用手写；后台加载器改扫 `<数据根>/plugins/*/dist/server.js`；`resolvePluginsDir` 顺序改成 `<数据根>/plugins` → 包内 `assets/plugins`。
- 为什么这样改：一个插件一个目录，前后端同进同出；入口名称由构建统一决定，不会各家一个样。
- 风险 / 影响面：不兼容旧数据，旧的 `<数据根>/server-plugins` 与旧 `pluginsDir` 副本不再读取；按「全部使用最新逻辑」处理，不做迁移。
- 验证方式：装一个带后台的插件，确认数据根下只有一个目录且同时含 `web.js` 与 `server.js`；重启后后台路由仍在；卸载后目录整体消失。

**第 3 步：build 不内置插件**

- 改哪里：`packages/ui/src/assembly.ts`、`packages/ui/src/AppProvider.vue`、`packages/ui/src/App.vue`、`packages/ui/src/main.ts`、`packages/ui/vite.config.ts`。
- 怎么改：把插件清单拆成两份——dev 清单保留现在的 30 个静态 import；build 清单为空，改由启动时向 cloud-server 拉 `/plugin-catalog.json` 后逐项装载；用 `import.meta.env.DEV` 在装配入口分支，dev 分支保持零网络依赖，build 分支只装数据根里有的插件；build 产物里不能出现任何 `@plume-canvas/plugin-*` 的代码。
- 为什么这样改：dev 保留源码热更体验，build 的界面包与插件解耦，插件更新不用重发界面。
- 风险 / 影响面：build 下如果 cloud-server 没起来或清单为空，画布会缺节点类型。需要保证首启安装先于界面装配完成，或首启时给出明确的加载态。
- 验证方式：在 `packages/ui` 里跑 `vite build`，在产物里搜 `plugin-bottom-bar`、`plugin-node-video` 等应为 0 命中；用 cloud-server 托管打开 build 版，确认插件从清单装进来。

**第 4 步：打包全部插件，首启直接安装**

- 改哪里：`packages/cloud-server/scripts/bundle-assets.mjs`、`packages/cloud-server/src/server.ts`、`packages/plugins/plugin-manager/src/pluginManagerService.ts`、`packages/plugins/plugin-manager/src/catalogTypes.ts`、`packages/ui/src/assembly.ts`。
- 怎么改：cloud-server 打包时把每个插件的产物收进 `packages/cloud-server/assets/plugins/<插件名>/{package.json, dist/web.js, dist/server.js}`，包括没有 `build` 脚本的 6 个（agent、image-grid-split、manager、node-audio、node-rotate、hot-reload，其中 hot-reload 是开发工具，见待确认）；前端首启时读清单，把内置插件装进内核；cloud-client 不依赖 `defaultInstalled`，在启动序列里显式最先安装，因为它一到位后台能力（存档、生成动作、历史、实时同步）才可用。
- 为什么这样改：首装不空窗，之后每个插件可独立替换；cloud-client 是后台能力的入口，不能等用户去面板点安装。
- 风险 / 影响面：`plugin-agent` 的前端产物很大，且带 `agent-server.js` 后台半，首装耗时最明显；首启并发安装需要限流，避免把浏览器或磁盘打满。
- 验证方式：清空 `<数据根>/plugins` 后启动，确认全部内置插件目录被铺入、界面插件可用、cloud-client 已连上后台；重启后不重复安装；删除某个插件目录后重启能恢复。
