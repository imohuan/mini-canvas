## 问题原因

三处，都在真机 + 审计日志里核过：

1. **跨源请求没带登录凭据**。dev 页面在 `localhost:5288`、后台在 `localhost:8865`，属于跨源；
   登录态在 HttpOnly cookie 里，浏览器对跨源 `fetch` 默认不带 cookie。宿主的代发
   （`hostFetch.ts`）和调试的两条口都只带了旧的 `x-admin-token`，所以后台一直看到「没登录」。
   审计日志里对应 `POST /api/task/call origin=http://localhost:5288 token=missing rejected`。
2. **SDK 回调名对不上**。节点页面写的是 `{ log, progress }`，而注入的 `CanvasUI.task`
   只认 `{ onLog, onProgress }` → 不订阅事件、也不等结果，只拿到 `state: "running"`；
   页面接着去读自己的字段，就变成一句 `undefined (reading 'head')`。
3. **沙箱 iframe 里的媒体被来源边界拦掉**。不透明源里的 `<audio src>` 会带
   `Sec-Fetch-Site: cross-site`，原来「cross-site 一律拒」把画布资源的只读媒体也拒了；
   另外资源响应头写成 `Cross-Origin-Resource-Policy: same-site`，不透明源不算同一个 site。

顺带说明绿框：它是**宿主**画的（`plugin-node-ui` 的 `.ui-node.is-interactive`
给了一圈 `--ui-accent` 内描边），不是节点 HTML 的样式；按你的意思没有改动。

## 修改方案

- 改哪里 / 怎么改：
  1. `hostFetch.ts`：所有请求统一带 `credentials: 'include'`；403 文案按后台原文区分
     「去登录」与「恢复通道」，不再一律说「检查管理令牌」。
  2. `useUiDebugWindow.ts`：`debug-accept` 与 `debug-docs` 两条 POST 也带凭据。
  3. `uiData.ts`：`CanvasUI.task` 同时认 `log / progress`；既没订阅又没等结果时抛一句能看懂的话。
  4. `requestTrust.ts`：只对 `GET/HEAD /api/canvases/<id>/resources/<name>` 且
     `Sec-Fetch-Dest` 是 image / audio / video 的请求放行跨站；其余照旧拒。
  5. `inlineAsset.ts`：CORP 改 `cross-origin`（真正挡住脚本执行的是 CSP sandbox + nosniff）。
- 为什么这样改：登录已经搬到 cloud-client 的 cookie 会话；代发请求必须按会话带凭据。
  媒体例外只覆盖「浏览器把公开资源显示出来」这一种，读不到响应内容、改不了任何东西。
- 风险 / 影响面：媒体例外只放宽只读展示，脚本 fetch 的 `Sec-Fetch-Dest` 是 empty，仍然被拒。
- 验证方式：Chrome 实测 + 单测 + 类型检查。
