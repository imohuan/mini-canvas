# 06 · 输入框下拉点击即消失

- 状态：已完成
- 负责人：deepseek-auto

## 你的原话

> 你的输入框底部的这些下拉菜单 都存在问题， 点击 之后 就直接消失了 出发有问题

> 补充（2026-11-03）：不是我点击了其他地方，而是我点击你这个下拉菜单，它立马就隐藏掉了，就闪了一下，它就隐藏掉了。

## 要解决的问题

点击 Agent 输入框底部的下拉按钮时，菜单应当正常展开并保持可见，直到用户选择一项、再点一次按钮、点击菜单外或按 Esc。现在用户刚点这个按钮本身，菜单只闪一下便收起，无法继续操作。

| --- | --- | --- |
| 点击「选择模型」按钮 | 菜单闪一下后消失，`aria-expanded` 仍为 `false` | 菜单稳定展开，`aria-expanded` 为 `true` |

## 问题原因

- 状态：已确认
- 复现步骤：打开任意画布 → 打开 Agent 对话 → 只点击底排「选择模型」或「选择 MCP」按钮本身，不要点别处；菜单只闪一下，随后按钮恢复未展开状态。浏览器实测两个按钮的 `aria-expanded` 都停留在 `false`，页面中没有保留下来的下拉内容。
- 证据（日志 / 截图 / 调用路径）：六个触发按钮都在 `@pointerdown` 调用 `switchComposerMenu(key)`，该函数立即把对应 `open` 设为 `true`。菜单由 Reka 的 `DropdownMenuTrigger` 控制，它随后在原生 `click` 里执行 `onOpenToggle()`；同一次点击于是先开、再关。
- 根因：菜单开合有两个入口：一是 `@pointerdown` 手动翻转，二是 `DropdownMenuTrigger` 的 click 原生翻转。一次用户点击触发两次翻转，表现为菜单闪烁后关闭。
- 修复证据：六个触发按钮只保留 `DropdownMenuTrigger` 的 click。Chrome 实测六个按钮各自首次点击均保留一个菜单、`aria-expanded=true`，再点一次关闭；模型 → 技能一次点击直接切换。Esc 和点菜单外均关闭。

## 修改方案

- 改哪里：`AgentComposer.vue` 的六个下拉触发按钮，以及 `useAgentConversation.ts` 中 `composerMenuOpen` / `setComposerMenuOpen` / `switchComposerMenu` 的开合协调逻辑。
- 怎么改：把 `DropdownMenuTrigger` 的点击作为唯一的开合入口，删除触发按钮上「按下即打开自己」的 `@pointerdown` 行为。切换其它菜单所需的关闭动作放在 pointerdown 上时，只关闭其它菜单，不打开当前菜单；必要时把这几只菜单设为非模态，避免已开菜单的遮罩吞掉下一次点击。
- 为什么这样改：一次点击只应该翻转一次状态。手动打开和原生点击互相抵消，是本次闪退的直接原因；不能靠加延时或强行保持 `open=true` 掩盖。
- 风险 / 影响面：影响六个输入框下拉，不能破坏同一时刻只开一个、点外部关闭、Esc 关闭和键盘导航。需要同时验证从 A 菜单直接切到 B 菜单的一次点击行为。
- 验证方式：在 Chrome 中逐个点击六个按钮，记录 `aria-expanded` 和下拉 DOM；补一条针对「一次点击只翻转一次」的回归测试，再跑 `pnpm -C packages/plugins/plugin-agent test` 与 `pnpm -C packages/plugins/plugin-agent typecheck`。

## 假设与待确认

- 假设：用户说的「这些下拉菜单」指六个输入框底排菜单，而不是菜单里的二级选项。
- 假设：点击后闪一下再消失是开合状态被连续翻转，不是面板被 CSS 遮挡。
- 待确认：修复时是否接受这几只 composer 下拉改为非模态（`modal=false`）以保证从 A 菜单一次点开 B 菜单？若不接受，需要另定切换策略。
