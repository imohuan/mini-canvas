# 插件安装与更新流程修复计划（2026-11-22）

## 用户反馈

1. 插件卡片 UI 丑：「可更新到 v0.1.6」把底部按钮挤变形，文字竖排。
2. 自带 tab 的卡片没有「已更新」状态，希望与其它地方用同一套卡片，只是不显示卸载按钮。
3. NPM 安装报「包里缺少声明的产物：dist/web.js」（npx @plume-canvas/server@latest serve 首启实测）。
4. 启动时要扫描自带插件是否有更新，检测到更新弹通知；每 30 分钟后台静默扫一次。
5. 插件 tab 每次进入都重新拉列表；希望用缓存（30 分钟过期），只有真正搜索才查 NPM。
6. 插件更新完成后弹通知，整个流程闭合。
7. 先本地 pnpm dev + pnpm dev:server 调试，再发布 npm 用 npx 启动复测。

## 根因与改法

### 1. NPM 安装产物校验过严（图 2 的报错）

apps/server/src/routes/npmPlugins.ts 的 doInstall 对声明产物逐个 fs.access，找不到直接 400。
但 apps/server/src/updater/bootstrap.ts 的启动安装已经做了「entry 不存在 → 回退 dist 下唯一 .js」的兜底
（线上旧包 entry 写 dist/web.js、实际文件是 dist/<包名>.js）。两处规则不一致，
导致同一批包启动能装、手动装报错。

改法：把 bootstrap 的 resolveArtifact 兜底逻辑原样提取到共享模块 apps/server/src/updater/artifactResolver.ts，
doInstall 与 bootstrap 共用。entry 命中 → 直接用；未命中 → dist 下唯一非 .map 的 .js 直接用；
多个候选时按 rel.includes(f) 精确名匹配挑（不能简化成「只取唯一候选」——真实包 dist 里
常有 web.js + server.js 多个文件，bootstrap 的 exactName 匹配兜住的就是这种）；都没有才报错。
失败测试先行：npmPluginsRoute.test.ts 加「包里 dist 是 <包名>.js、entry 写 web.js 也能装」的用例。

### 2. 卡片排版（图 1 的挤压）

PluginCard.vue 的 footer 是 flex 两端布局：左侧 footerNote、右侧按钮组。
「更新到 v0.1.6」按钮文字长时把左侧 note 挤成竖排、按钮换行错乱。

改法：footer 改纵向两行 —— 第一行 footerNote（可截断，不换行省略），第二行按钮组右对齐；
按钮组 flex-wrap 加每个按钮 white-space: nowrap，保证按钮文字不竖排。
复核补充：builtin 卡的 footerNote 带 Lock 图标，改两行后图标跟着文字一起在第一行；
busy 时按钮禁用但仍在第二行，footer 不写死 30px min-height；「已更新」徽章复用现有 on tone。

### 3. 自带 tab 的卡片与「已更新」标示

自带卡片现在是空 actions 只读卡片。改法（统一用同一套 PluginCard）：
- 自带插件也能从 NPM 更新报告（/api/updates，builtin 标记）判断有无新版本；
- 有更新 → footerNote 显示「有更新 → vX.Y.Z」，新增「更新」动作（走 /api/npm-plugins/update）；
- 没更新 → 状态徽章保持「自带」；更新完成后徽章变「已更新」。

### 4. 更新通知与定时扫描

服务端已有：启动一次 + 30 分钟定时的 update-report（server.ts ①.6 段）。缺的是前端消费与通知。改法：
- 服务新增 checkUpdatesNotify()：拉 /api/updates 报告，与上次通知过的版本映射（pkg → version，
  存 localStorage，key plugin-manager:notified-updates）比对 —— 用映射而不是集合，
  「插件 A 1.0 → 1.1 → 1.2」两次更新各弹一次；
- 有新版本 → ctx.tryGet('notify').warning 逐条弹「插件 X 有新版本 vX.Y.Z」，
  server 自身有新版也弹一条；通知过的版本记下来，同一版本不重复弹；
- 页面 onMounted 时调一次；页面挂载期间加 30 分钟 setInterval 再拉一次（离开页面清掉），
  「半小时后台静默扫描 + 弹通知」才算真正闭合。数据源只用 /api/updates 报告（轻），
  拉不到就不弹等下一轮，不 fallback 到 checkNpmUpdates()（browse 全量太重）。

### 5. tab 缓存策略（30 分钟）

usePluginManagerPage 目前 onMounted 每次进 tab 都 loadMarket()（browse + installed + report）。改法：
- 引入 localStorage 缓存（key plugin-manager:market-cache，存 marketList/npmInstalled/npmUpdates/savedAt）；
  localStorage 不可用（隐私模式/禁用）时 try/catch 静默降级为「不缓存、每次拉取」
  （参考 pluginManagerService 的 localBackupStorage 模式）；
- 进入 tab 时：缓存未过期（30 分钟）→ 直接用缓存，不发请求；过期 → 后台静默刷新；
- 用户点「搜索」按钮（onNpmSearch）→ 永远走真实请求，不用缓存；
- 安装/更新/卸载成功后 → 强制刷新缓存。
- 复核补充：工具栏现有「刷新」（onRefresh）只重拉 catalog，要同时接到「清 market 缓存 +
  loadMarket(force)」，否则用户以为刷新了市场列表其实没刷。

### 6. 更新完成通知

onNpmUpdate 成功且 updated=true → notify.success('已更新到 vX.Y.Z')；失败 → notify.error。
本地清单的 install/uninstall/reinstall 完成后也补一条成功 toast（顺手闭合）。

### 7. 发布与验证

1. 本地：pnpm -C apps/web dev（5288）+ pnpm -C apps/server dev（PLUME_BACKEND 指向 8865）。
   插件管理页改动在 packages/plugins/plugin-manager，dev 下由 catalogPlugin 从源码现编译，不需单独 watch。
2. 相关测试：pnpm -C packages/plugins/plugin-manager test；pnpm -C apps/server test（npmPluginsRoute /
   npmPluginsDeps / npmClosedLoop / updateChecker）；pnpm -C apps/web typecheck。
3. 发布：git status 里另一任务的未提交 vite 配置改动不纳入提交，提交时精确指定路径。
   pnpm -C apps/server publish 走 prepack（typecheck + bundle + gen:manifest），
   版本从 0.1.14 升到 0.1.15，发布后 npx @plume-canvas/server@latest serve 实测安装。

## 风险

- 产物兜底会让「声明了 web.js 但实际没有」的包也装上：这是 bootstrap 已有语义，两边拉齐不引入新风险。
- tab 缓存可能让「刚在别处装了插件」的用户看到旧列表：提供「刷新」按钮强制绕过缓存。
- 通知去重靠 localStorage：换浏览器或清缓存会再弹一次，可接受。
