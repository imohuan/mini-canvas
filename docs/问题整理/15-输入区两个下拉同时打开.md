# 15 · 输入区两个下拉同时打开

- 状态：已完成
- 负责人：root
- 完成时间：—

## 你的原话

> 2个下拉可以同时打开

## 要解决的问题

Agent 输入区里,模型下拉和比例(参数)下拉同时开着,画面上叠出两个浮层。
期望:同屏只开一个,点第二个时第一个自动收起。

## 范围与位置

- 页面：节点底栏 / Agent 输入区（「豆包 Seedream 4.5」模型下拉与「16:9」参数下拉同排）
- 参考代码：见下三行（多文件）
  - `packages/plugins/plugin-agent/src/components/agent-conversation/useAgentConversation.ts:191` 的 `composerMenuOpen / setComposerMenuOpen` —— 它只互斥**输入区自己的 6 个 DropdownMenu**（plus/mode/auth/model/skill/mcp），见 `COMPOSER_MENU_FLAGS`。
  - `packages/plugins/plugin-bottom-bar/src/node-bottom-bar/BottomBarActions.vue:58` —— 动作下拉是组件库 `Select`；参数下拉是 `ToolParamGroup`（`packages/plugins/plugin-theme-default/src/components/ui/ToolParamGroup.vue:130` 的 Popover）。
  - `packages/canvas-render/src/contracts/dropdownExclusive.ts` —— 全局「同屏只开一个下拉」登记表与广播事件，但 **Select / Popover 两个实现都没有接它**（仓库内 `claimDropdownExclusive` 只有 `packages/ui/src/components/hooks/dropdownExclusive.ts` 一处旧实现，无调用方）。
- 相关资源：用户截图 2026-11-03（模型下拉与比例面板同开）。
- 关联问题：11（浮层统一配置）。

## 问题原因

- 状态:已确认
- 复现步骤:选中一个图片节点 → 底栏点开「豆包 Seedream 4.5」动作下拉 → 再点「16:9」参数下拉 → 两个浮层同时挂着。
- 证据:三个实现各自独立开合 —— 动作下拉是 `Select`(reka SelectRoot 默认 `modal: false`,外点由自身收起),参数面板是 `ToolParamGroup` 内部 `const open = ref(false)` 的 Popover,模型下拉走 `setComposerMenuOpen` 的 6 键互斥表。三套状态互不知情;渲染层提供的 `claimDropdownExclusive` / `DROPDOWN_CLOSE_ALL_EVENT` 没有任何浮层实现接入。
- 根因:「同屏只开一个下拉」的约束被写在三个互不相通的地方,而公共登记表没人用。新的浮层实现(Select/Popover/参数面板)接入时没有接互斥表,规则靠每个实现自觉,必然漏。

## 修改方案

- 改哪里:优先改组件库 `packages/ui-kit-shadcn` 的 `Select` 与 `Popover` 根组件,打开时向渲染层 `claimDropdownExclusive` 登记、关闭/卸载时摘除;收广播 `DROPDOWN_CLOSE_ALL_EVENT` 自动收起。`ToolParamGroup` 改用组件库 Popover 后自动获得同一约束;Agent 输入区 6 个 DropdownMenu 也接到同一张表,替换现有 6 键互斥表。
- 怎么改:在 `ui-kit-shadcn` 新增一个 `popup/exclusive.ts` 小模块(与 `popupConfig.ts` 同级):`claimExclusive(close)` 打开时先关别人再登记自己;`DropdownMenu.vue` / `Select.vue` / `Popover.vue` 三个根组件 watch `open`,打开即 claim、关闭即 release。`setComposerMenuOpen` 的手写互斥可删,交给表。
- 为什么这样改:互斥是「所有浮层」的公共约束,应该住在公共层,而不是每处业务自觉。登记表已存在于渲染层契约(`canvas-render/src/contracts/dropdownExclusive.ts`),组件库直接用它即可,不需要新造一套。
- 风险 / 影响面:所有下拉/弹出面板的开合都会走登记表;子菜单(二级)不能参与互斥(会把父级关掉),要沿用 `SUB_MENU_CLOSE_EVENT` 的豁免逻辑;模态弹窗内的菜单需要豁免(显式跳过)。
- 验证方式:模型下拉 + 参数面板互点互斥;输入区 6 个下拉互点互斥;设置页 Select 与 Popover(取色器)互点互斥;翻转、窄屏、亮暗各看一次;跑 `pnpm -C packages/ui-kit-shadcn test`、`pnpm -C packages/ui test`。

## 验收标准

- [x] 节点底栏:动作下拉、参数面板、模型下拉任意两个,先开的在第二个打开时自动收起
- [x] Agent 输入区下拉互斥仍成立（手写 6 键表保留，与新机制不冲突）
- [x] 设置页的 Select 下拉与 Popover 取色面板互斥（同一套根组件）
- [x] 二级菜单(子菜单)打开不会把父菜单关掉
- [x] 点画布空白处、切换节点等场景,浮层正常收起,无残留

## 不能动

- 不把三个根组件改成模态(`modal: true`),保持非模态交互。

## 假设与待确认
