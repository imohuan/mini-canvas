# 45 · 热重载与可视化节点联调

> 2026-11-25 ~ 26。环境：`npx @plume-canvas/server@latest serve -d C:\Users\Administrator\.plume --port 8865`。
> 画布 `90da8d5cbf06424d`：节点 4 = 图片，节点 6 = 可视化节点，边 `4 -> 6`。

## 一、这一轮到底要验什么

两个插件一起验：

1. **热重载插件**：改插件源码 → watch 构建 → 画布自己换成新版，不用刷新。
2. **可视化节点插件**：界面能显示上游图片，点「生成」能跑后台脚本并把产物写进节点槽位。

结论：两个都通了，但中间撞到四个坑，其中两个是**真的 bug**。

## 二、坑 1：只有 `resourceId` 的上游被显示成「无上游图片」

**现象**：节点明明连着图片节点，右上角却写「无上游图片」。

**根因**：新节点的产物字段只存引用 `<画布id>/<文件名>`，保存时地址（`imageUrl`）会被删掉。
注入给界面的 `__CANVAS_UPSTREAM__` 也只透传了 `resourceId`，于是界面里 `u.url` 是空的，自己判成没素材。

**修法**：`UiContent.vue` 的 `upstream` 计算与 `nodeUiPlugin.ts` 的 `buildNodeContext`，都改成
「没有 url 但有 resourceId → 用 `resourceUrlOfRef` 现算地址」。两处必须同一条规则。

**测试**：`src/__tests__/upstreamInjection.test.ts`（SSR 断言注入项齐全、只有 `resourceId` 时也有可用地址）。

## 三、坑 2：热重载后台半「永远重装失败」

**现象**：调试页点「重装」返回 400，日志里 `[core] Duplicate plugin name: "plugin-node-ui"`。
后台半停在第一次装进去的那份，改了代码也不生效。

**根因**：`plugin-hot-reload/src/server.ts` 的 `installFromFile` 直接 `runtime.install(candidate)`。
内核按**插件名**索引，同名已存在就抛错 —— 而「重装」的语义本来就是替换。

**修法**：装之前先按「产物导出的 name」与「调用方给的 id」各 `runtime.uninstall()` 一次，再 install。
路由从 body 读 `id` 传进去（目录名与运行时名通常不一样，两个都要试）。

**测试**：`serverRoutes.test.ts` 新增「同名已装时是替换」。

## 四、坑 3：重装成功、代码没变（最关键）

**现象**：构建成功、通知弹出、重装返回 200，界面还是旧的。没有任何报错。

**根因**：后台 `/plugins/<插件>/<产物>.js` 读的是**数据根里的安装副本**
（`<数据根>/plugins/plume-canvas__plugin-node-ui/...`），而 watch 构建的是**仓库里的 `dist`**。
两个不是同一个文件。watch 上报后台地址，等于让重装去装那份旧的。

**修法**：watch 构建过之后，自己把 `dist/` 用一个本地静态服务发出来
（默认 `127.0.0.1:5199`，可用 `--serve-port` 改），`front` 指向它。

上报优先级：`--front` > 自己发的 `dist` > 后台 `/plugins` > 清单。

**副作用**：`plugin-bottom-bar` 与 `plugin-node-ui` 各有一份 watch 脚本，两份内容保持一致（已用脚本核对过逐字节相同）。

## 五、坑 4：点「生成」报 403「没有声明脚本」

**现象**：界面显示「失败：后台拒绝（403）：节点 6 没有声明脚本 "pixelize"（已声明：_pixelize）」。

**根因**：两层叠加。

1. 节点声明里只有旧的 `_pixelize`，界面调的是正式脚本 `pixelize`；
2. 自动补声明（`task/declare.ts` 的 `detectScriptCalls`）只认 `{ type: "call", name: "x" }` 这种写法，
   而手册教的是 `CanvasUI.task("x", …)` —— 按手册写的界面**一条声明都补不上**。

**修法**：

- 扫描增加 `TASK_CALL_RE`，认 `CanvasUI.task("名字", …)` 与裸 `task("名字")`；
  仍要求名字在「这台机器上真实存在的脚本」里，噪音进不来。`someTask(` / `other.task(` 不算。
- 403 提示分流：后台说「没有声明脚本」时，不再让人去查登录（以前那句话会把人引到登录面板）。

**测试**：`scriptDeclare.test.ts` 新增 2 条（手册写法、裸 task 与排除项）；
`hostProxy.test.ts` 新增 1 条（声明类 403 不许提登录）。

## 八、经验

1. **「成功」不等于「生效」**：重装返回 200、通知也弹了，产物地址指错就什么都没变，而且没有任何报错。
   验收要落到「浏览器最后加载的那个 URL 是不是刚构建的产物」。
2. **双份脚本要逐字节比对**：两份 watch 只要差一行，就会有一边悄悄不工作。
3. **报错文案要指对方向**：后台明明说「没声明脚本」，前端却提示「检查登录」，会把排查带偏很久。
4. **自动补声明要覆盖手册教的写法**：手册与扫描器是两处代码，改了手册要顺手看扫描器认不认。
