## 你的原话

> 观察我上面的 3 个图片，这边主要是要介绍为什么你这边的可视化节点无法连接到音频节点里面 如图4
> 所以说，你这个地方可视化的输出类型到底是如何决定的？可视化节点就是看它内部是否支持配置输出类型，是否存在输出？如果不存在的话，就不显示右侧的端口。请问这里是否支持？并且检查一下当前图片中的这个节点，它的问题所在。首尾静音裁剪节点

> 补充（2026-11-17）：可以在可视化节点里面添加一个配置，data.xxxxtype = "image"。如果这个值是 null 或者不存在的类型，都作为无输出端口。
> 你的可视化节点不能直接在配置中写死，而是需要交给节点的配置数据来动态显示。
> 这里就会存在几个问题：比如最开始它是图片类型，还有几根连接线连接到其他节点上；但是你后面修改它的类型时，这里就需要自动断开这些不匹配节点类型的连接线。

## 要解决的问题

可视化节点的输出端口要跟着**这个节点自己**的配置走，而不是节点类型写死。改类型时，原来那条已经不匹配的线要自动断开。

## 现在 vs 期望

| | 现在 | 期望 |
| --- | --- | --- |
| 端口类型 | 类型写死 `contentType: 'image'` | 读节点 data，按产出现算 |
| 没有产物时 | 仍显示图片输出口 | 不显示输出口 |
| 改类型 | 旧连线留在画布上（点不动） | 自动断开不匹配的线 |

## 问题原因

1. `plugin-node-ui` 在 `ctx.nodes.register` 里写死 `outputs: [{ port:'source', contentType:'image' }]`。
   「首尾静音裁剪」实际产出的是 mp3，于是与音频节点（只收 text/audio/video）连不上，提示「类型不匹配」。
2. 端口显隐只看类型声明（`!outputs || outputs.length > 0`），与节点数据无关。
3. 改节点数据后没有重新校验既有连线，旧线会留在画布上。

## 修改方案

- 新字段：`data.uiOutputType`（`image` / `video` / `audio` / `text`）。空串 / null / 不认识的词 = **没有输出口**。
- 「端口由节点数据决定」做成数据层的正式能力：
  - `CanvasNodeType.outputsFromData(data)`：算这个节点的输出口；返回空 = 无端口。
  - `CanvasNodeType.producesFromData(data)`：下游 `upstream.media/ofType` 也按节点读产出。
  - `nodeConnectionDef(def, data)` 是唯一判定入口，数据层校验、渲染层端口、右键菜单、多选连线都走它。
- 改类型自动断线：`GraphDocument.updateNode/updateNodes` 之后，把碰到这些节点的边按同一套 `validateConnection` 重新校验，不合规的删掉（与改动同一条撤销）。
- 后台经 MCP / 任务脚本写节点时不走前端：`CanvasDocument.batchNodes` 里加同一口径的 `pruneEdgesForOutputType`。
- 老节点兼容：字段**从没写过**但已有 `uiOutputUrl` 时，按产物扩展名推断一次（`resolveOutputType`）；显式写空仍是无输出。
- 产物落地时自动补类型：界面 `save`、任务脚本 `ctx.save`、页面主动 `CanvasUI.setOutputType(...)` 三条路。

## 验收标准

- [x] `data.uiOutputType = 'audio'` → 右侧有音频输出口，可连音频节点
- [x] 空值 / 不存在的值 → 右侧没有输出口
- [x] 从 image 改成 audio → 原来连到图片节点的那条线自动消失
- [x] 只改无关字段（label 等）→ 连线保留
- [x] 后台经 MCP 改类型 → 同样自动断线
- [x] 老节点（有产物、没配置）→ 仍能按产物类型显示端口
