# 44 · 可视化节点后台函数调用报 403「需要登录」

- 状态：已完成
- 日期：2026-11-25

## 现象

在可视化节点里让 Agent 调后台函数（`_pixelize`）时，像素运算全部跑通，最后一步保存产物报：

> 保存产物失败：需要登录：请在 cloud-client 的登录面板输入密码

## 根因

两件事叠在一起：

1. **MCP 的 `canvas_fn_call` 没有签发任务令牌。** 脚本跑在独立子进程里，只有
   `ctx.taskToken`，没有登录 cookie、也没有管理令牌。`ctx.save` 写
   `POST /api/canvases/:id/resources` 时被管理鉴权拦下（审计里是 `auth-failed / token: missing`）。
   节点界面那条路（`/api/task/call`）一直有签，所以只有 MCP 这条路坏。
2. **`canvas_fn_call` 把产物写进了虚拟画布** `fn-probe-default`。就算令牌补上，
   用户在自己的画布上也看不到结果 —— 产物落在草稿纸上。

附带一条：补依赖声明时只查了「已验证脚本清单」（不含下划线打头的在建脚本），
于是 `_pixelize` 跑成功了，节点上的 `uiScripts` 还是空的。

## 修复

- `canvas_fn_call` 增加必填 `canvasId` / `nodeId`，用**用户正在操作的那个节点**跑脚本；
  启动前把脚本名合并进 `data.uiScripts`（含在建脚本，已有声明不丢）。
- 启动时由宿主签发 `taskTokens.issue(canvasId, nodeId, 超时 + 60 秒)` 并传给 `runScript`，
  `ctx.save` / 节点字段写入靠这个短时令牌过关。
- 删掉虚拟画布（`virtualCanvas.ts`），不再创建 `fn-probe-*`；后台画布列表里对历史
  `fn-probe-` 目录的过滤保留。
- 文档（插件手册 + `apps/docs/plugins/parsed/node-ui/*`）改成「必须传画布与节点」，
  并写明不要用 shell 里的 `curl` 调 `/api/task/call` 去验证（那条要走登录 cookie）。

## 验证

- 插件单测 395 条全绿；新增用例覆盖：缺参报错、真实节点跑、令牌签发、声明合并、
  已声明不重复写、在建脚本补声明、不再建 `fn-probe-*`。
- 服务端新增 `canvasFnCallSave.test.ts`：真插件 + 真服务 + 会 `ctx.save` 的脚本，
  断言资源文件、节点字段与声明都写回，审计里没有 `auth-failed`。
  反向验证：把签发那行临时去掉，该用例精确复现用户的报错原文。
- 真机：8865 上通过 MCP 调 `_pixelize` 返回 `ok:true`，产物落到 `slot-6.png`，
  节点 `resourceId` / `imageUrl` / `uiScripts` 都写回，重启后审计 `auth-failed = 0`；
  浏览器里节点 6 显示像素化结果。

## 补充（同日调整）：只验脚本这条路要留着

第一版把 `canvasId` / `nodeId` 改成了必填，等于把「只想单独测脚本」这条路关了。
用户口径：单测脚本是真实需求，脚本的 `ctx.save` 需要一对画布与节点才能落产物。

现在改成**两种用法**：

| 目的 | 传什么 | 产物落点 |
| --- | --- | --- |
| 只验脚本能不能跑 | 两个都不给 | `fn-probe-default` 草稿画布（`probe` 占位节点） |
| 在用户节点上跑 / 界面开发 | `canvasId` + `nodeId` | 那个节点的槽位 |

- 只给其中一个 = 写错，直接报错，不猜。明确给了节点却找不到时也只报错，不会偷偷换成草稿画布。
- 两条路都由宿主签短时令牌，`ctx.save` 都能成功。
- 草稿画布没有界面，因此只验脚本时不补 `uiScripts` 声明。
- 更快的一条：纯验证脚本本身可以用 `exec_command` 直接 `node` 跑，完全不经过画布；
  但它证明不了「产物能落进节点」，那一步仍要 `canvas_fn_call`。

验证：真机上调「不给画布与节点」返回 `ok:true`、`virtualCanvasId=fn-probe-default`，
产物落在 `fn-probe-default/resources/slot-probe.png`，用户节点 6 的字段与产物都没被动，
审计里 `auth-failed = 0`。

## 补充：文档里「Agent 写不了脚本」的说法已过时

Agent 有 `write_file` / `edit_file`，写 `task-scripts/` 只需用户批准一次。
手册与 `apps/docs` 里那几句「只有用户能加 / 你写不了」已全部改掉，并补上
「先查清单，已经能用的别重写」。
