# 46 · 画布无限请求 + 插件详情白屏（用户 2026-11-26）

## 现象

1. `npx @plume-canvas/server@latest start` 起服务后进入画布，网络面板里同一批资源
   （`18106bc56930dbad.jpeg`、`9903b5c80e4f3a3d.png`、`9923…webp` 缩略图、`/api/actions/labels`）
   成组反复请求，几分钟就积累上千条。
2. 插件管理页点开任意插件的详情，右侧整块变白。

## 根因

### 一、底栏存盘自我触发

`useBottomBarPersistence.persistValues` 每 400ms 把 `barValues / barPrompt / barPromptDoc`
整块写回节点，**不管内容有没有变**。内核每次写都会生成全新的 `data` 对象：

```
写盘 → props.data 换新对象
     → 上游素材 / 正文标签 / 动作文案全部重算
     → 编辑器 emit 一次内容相同的 update
     → 400ms 后再次写盘
```

放大它的还有两处「每次求值都新建数组」的 watch：

- `ImageContent.vue` / `AudioContent.vue` / `useVideoSource.ts` 的
  `watch(() => [resourceId, legacyUrl])` —— 任何一次 data 换新都判成"地址变了"，
  重新 resolve 并给 `<img>/<audio>/<video>` 换 src，浏览器重下原图与缩略图；
- `useActionLabels` 的 `watch(deps.resourceCounts, ..., { deep: true })`，
  且回调里 `lastKey = ''`，让"内容完全一样"的请求每轮都重新发。

实测数据（`59343957e74b4ce9` 画布）：`updateNode` 每 ~430ms 一次不停，
标签刷新函数被调 2000+ 次。

### 二、详情面板住在被卸载的组件里

`PluginManagerPage.vue` 写的是 `<PluginManagerTabs v-if="!s.detailPkg">`，
而 `PluginDetailPanel` 恰好渲染在 `PluginManagerTabs.vue` 内部：
打开详情 → `detailPkg` 有值 → 整个页签组件被卸载 → 详情面板一起消失。

## 修法

1. `useBottomBarPersistence` 新增纯函数 `samePersistPatch`：按字段做顺序无关的内容比对，
   全部相同就跳过写盘。
2. `useActionLabels`：素材数量改成监听签名串，且触发时不再清空 `lastKey`。
3. 图片 / 音频 / 视频的地址解析监听改成字符串签名 `resourceId|legacyUrl`。
4. 详情面板搬到 `PluginManagerPage.vue`，与页签同级；`PluginManagerTabs` 不再接收 `closeDetail`。

## 验证

- `pnpm -C packages/plugins/plugin-bottom-bar test`：584 通过（新增 5 条守门用例）。
- `plugin-bottom-bar / plugin-node-image / plugin-node-audio / plugin-node-video / plugin-manager`
  的 typecheck 全过，`apps/web typecheck` 全过。
- Chrome 实测（localhost:5288，后端 8865，画布 59343957e74b4ce9，选中节点让底栏常驻）：
  - 12 秒内 `updateNode` 0 次、`/api/actions/labels` 0 次、画布资源请求 0 次；
  - 只剩设计内的 8 秒兜底轮询（`/api/actions?ifVersion`、`/revision`）。
- Chrome 实测插件页：点卡片进详情，`.pmp-detail` 正常渲染（658×579，README 可见），
  点「← 返回插件列表」回到 25 张卡片，无白屏。

## 顺带发现（未改）

`/api/actions` 与 `/revision` 仍按 8 秒一次轮询（`cloudClientPollMs` / `revisionPollMs`）。
这是实时通道的兜底设计，不属于本次死循环；如果希望完全静默，可以调大间隔或改成
只在 SSE 断开时轮询。
