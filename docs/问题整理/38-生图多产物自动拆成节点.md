## 要解决的问题

豆包这类网页自动化生图，一次会回 2～8 张图。现在只有第一张写进当前图片节点，后面的全丢了（历史里能看到，画布上没有）。

要的结果：第一张仍然填进原来那个节点；多出来的每一张，自动在原节点旁边新建一个图片节点，并且：

- 新节点的输入连线与原来一致（连进来的参考图、参考文字都接上）；
- 新节点的底栏参数与原来一致（同一个模型、同一个比例等）；
- 新节点的新图马上显示，点开底栏不会重新跑一次。

- 页面：画布上的图片节点 + 底栏「豆包 Seedream 4.5 / 5.0 Lite / 4.0」等生图动作

- 相关资源：对话里的两张截图（平台设置页、任务结果里 4 张以上产物）
- 关联问题：无

## 现在 vs 期望

| | 现在 | 期望 |
| --- | --- | --- |
| 画布节点 | 只填第一张，后面几张不出现 | 第一张填原节点，其余各建一个新图片节点（右侧一行 3 个，排满换行，第二批自动避开第一批） |
| 新节点输入 | 不存在新节点，谈不上 | 复制原节点的入边，参考素材一致 |
| 新节点底栏 | 不存在新节点 | `barValues`、`barPrompt` 与原节点一致，打开就是同一个模型同一套参数 |

| 数量上限 | 无（第一版方案写过 9 个上限） | 不设上限；同一张图重复返回只建一个 |

## 问题原因

- 状态：已确认
- 复现步骤：在图片节点上选「豆包 Seedream 4.5」，输入提示词发送；web2api 跑完后返回多张图。
- 证据：本地画布 `.plume/canvases/59343957e74b4ce9/history.json` 里节点 92 有一条记录 `urls` 共 8 项，第 1 项是 `/api/canvases/…/resources/18106bc56930dbad.jpeg`，第 2～8 项全是 `http://localhost:8033/api/resources/images/doubao/…`。对应代码 `taskManager.ts` 的 `writeMediaFields` 第一行 `const raw = urls?.[0]`，只处理第一张；`finish` 里也只把 `result.urls[0]` 换成同源地址，其余地址原样保留。
- 根因：后台把「一次任务的产物」当成「一个产物」。provider 已经把全部地址放在 `urls` 数组里（`web2api-image.js` 的 `collectUrls`），但落节点的那一步只取数组第一个，也没有新建节点的能力调用。

## 修改方案

- 改哪里：`apps/server/src/tasks/taskManager.ts`（把单产物落地拆成 `localizeArtifact` / `fieldsForArtifact` / `spawnExtraArtifactNodes` 三步，`finish` 改成逐张落地）；测试补在 `apps/server/src/__tests__/taskManager.test.ts`，另建 `apps/server/src/__tests__/multiArtifactNode.test.ts` 走真实 HTTP；验证用的本地 provider 放 `.plume/providers/image-multi-test.js`。
- 怎么改：逐张把产物字节收进本画布资源目录（`saveResource`），先定 `resourceId`、再由它推出同源地址；第 1 张写回原节点（`resourceId`、`imageUrl`、宽高）；其余每张新建一个同类型节点，抄 `barValues` / `barPrompt` / `barPromptDoc`，写自己的资源与宽高，状态标 done 但**不带 taskId**（避免前端对账当成原任务再写一遍），label 交给数据层自动起名；复制原节点的入边（源节点与端口照抄，只把 target 换成新节点）；摆放按「原节点右侧一行 3 个、排满换行、行高按这一行最高那张算、第二批撞到已有节点就整行下移」；只对图片节点拆，视频 / 音频 / 文本不动；不设数量上限，内容哈希相同的重复产物只落一次，单张取字节失败只跳过那张。
- 为什么这样改：产物落地本来就集中在后台这一处，在这里拆节点，网页端、MCP、刷新恢复三条路都自动一致；复制 `barValues` 满足「配置相同」，复制入边满足「输入节点相同」。
- 风险 / 影响面：会改「一次任务产出多个节点」，影响历史条目的 `nodeId` 归属与撤销表现；只对 `nodeTypes: ['image']` 且产物确实是多张的动作生效。
- 验证方式：`apps/server` 跑类型检查与单测；用本地测试 provider 起临时服务，在真实画布里看节点、连线、底栏参数、历史缩略图。

## 验收标准

- [x] 一次返回 8 张时，画布上出现 8 个图片节点（原节点 + 7 个新节点）
- [x] 每个新节点的输入连线与原节点一致，参考素材在底栏能正常显示
- [x] 点开新节点，底栏模型与参数与原节点相同，不会因为缺 `barValues` 回到默认模型
- [x] 历史记录里该次任务的所有缩略图都能打开（地址都是本画布 `/api/canvases/…/resources/…`）
- [x] 只返回 1 张时行为与现在完全一致，不多建节点
- [x] 返回多少张就建多少个节点，不设上限；同一张图重复返回只建一个
- [x] 同一节点连续生成两批时，第二批自动排到下一行，不与第一批重叠
- [x] 竖图、横图混排时按真实卡片尺寸摆放（宽图算宽、竖图算高），节点之间不互相压住
- [x] 宽图明明放得下时，不被避让检查误判成重叠而整行掉到下一行（用户截图报的「图片 19/20 跑到右下角」）
- [x] 用本地测试 provider（`.plume/providers/local-image-multi.js`）在真实画布里跑一遍：多张结果全部落成节点，底栏换成该 provider 的模型即可复验

## 不能动

- 不改 provider 的请求格式与动作 id（旧画布里的 `actionId` 必须继续有效）
- 不改单产物动作（视频、音频、文本）的落地行为
- 不改底栏参数控件、不改历史弹窗布局

## 假设与待确认

- 假设：多出来的图按「原节点右侧、一行 3 个、排满换行」摆放，不自动连线到下游节点。
- 假设：新节点沿用原节点的动作与参数，但**不自动重新生成**，只是显示各自那一张。
- 已确认（2026-11-20）：不设数量上限。
