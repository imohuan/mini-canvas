# 插件开发规范

日期：2026-10-18。适用范围：`packages/plugins/**`、`packages/ui/src` 里以插件形式装配的代码、以及第三方插件。

这份规范解决三件事：插件之间怎么说话、节点数据怎么写、媒体怎么进画布。遇到冲突时，以本规范 + `docs/design/plugin-contracts-proposal.md` 为准；旧教程里没写到的，按本规范补。

## 一、插件边界

### 1.1 只通过 `ctx` 协作

插件之间**不允许** `import` 另一个插件的实现模块。允许的 import 只有：

- `@mini-canvas/kernel` / `canvas-data` / `canvas-render` / `canvas-base` 的公开出口；
- 纯类型（`import type`）——但类型也应优先放在上游公开包，不要长期依赖某个插件的 `src/...` 路径；
- 自己包内的文件。

需要另一个插件的能力时，按这个顺序选：

| 需求 | 用什么 | 例子 |
|---|---|---|
| 按名字取一个会做事的能力 | 服务：`ctx.get('xxx')` / `ctx.tryGet('xxx')` | `ctx.get('doc')`、`ctx.tryGet('nodeBar')` |
| 按种类放/取一串条目 | 注册场：`ctx.registryOf('kind')` | `registryOf('ui')`、`registryOf('node/bar')` |
| 给节点/区域加 UI | `ctx.nodes.register` / `ctx.nodes.attach` | 节点包、装饰按钮 |
| 给选择集加 UI | `ctx.selectionRegion.attach` | 资产上传、引用到 Agent |
| 读当前节点可用的公共能力 | 已实现：`useCapability('node'/'zoom'/'selected'/'tools')`；`selection` 只给选择集条目；提案未实现：`'media'/'upstream'` | 区域组件里 |
| 读写画布数据 | `ctx.get('doc')` | 节点/边/事务/撤销 |

**禁止**：`window.__某插件`、模块级可变单例、直接 import 对方 `src` 文件、把对方的 DOM 类名当 API。

### 1.2 硬依赖与可选依赖

- 没有它插件就跑不起来：写进 `export const inject = ['doc']`，让内核编排 PENDING。
- 有就用、没有就降级：用 `ctx.tryGet`，不要写进 `inject`。
- 降级必须是**看得见**的：组件显示空态/禁用按钮/明确文案；只在控制台 warn 不算完成。

### 1.3 注册即回收

经 `ctx` 的注册（节点、命令、槽、服务、监听、`ctx.effect`）都随插件卸载自动回收。只有自己创建的定时器、连接、DOM 监听、全局单例才需要 `ctx.effect` 返回清理函数。
> **事件名例外**：`registerEventName` 只是登记名字，没有注销口；`ctx.on` 的监听会回收，名字本身不会。

### 1.4 资源地址只经解析入口

> **已实现（2026-10-18）**：`produces/consumes` 已进入 `NodeRegisterDef`，注册时校验三选一；下面的声明可以直接用。

**目标形态**：节点数据、注册场条目、存档、剪贴板载荷里只保存 `resourceId`；地址全部由解析入口现取。

- 渲染/导出/上传前需要地址时，统一调 `ctx.get('resources').resolve(resourceId)`；`useResourceUrl` 是提案 API，尚未实现。
- 解析结果只用于当前渲染/当前请求，不写回 `data`。
- 解析失败时返回 `undefined`，组件显示“资源不可用”；旧地址兼容分支必须集中在一个函数里并打 `// 迁移期` 标记，散落在组件里的回退一律算违规。

> **现状提醒（2026-10-18）**：云端 `putResource` 已改为返回逻辑 ID `<canvasId>/<hashName>`；`resolve` 负责 ID → 地址。
> `restoreNodeMediaUrls` 已不再把解析地址写进**已有持久地址**的字段；只为缺失或失效（`blob:`/`data:`）的旧字段补一份会话内副本。

## 二、节点数据规范

### 2.1 谁是字段的主人

节点类型插件是它 `data` 字段的主人。别的插件**不得**直接写另一个类型节点的业务字段，除非：

1. 该类型公开了对应的服务方法（如 `ImageService.addImageNode`）；或
2. 该类型声明了 `produces/consumes`，消费方通过 `upstream` / `media` 能力读写；或
3. 这是通用字段（`label`、`barPrompt`、`barValues`、`refOrder`），且写在公开规范表里。

**`media` 只是路由**：它把请求转给拥有该类型的插件注册的创建器/写入器，真正落笔的仍是那个插件；调用方不构造 `data`。

> `ImageService.addImageNode` 是**迁移期兼容方法**：参数是 URL，只写 `imageUrl`，不写 `resourceId`。新代码不要照它写。

### 2.2 字段命名

- **节点数据只保存资源引用 `resourceId`，不保存资源 URL**。图片/视频/音频/全景等由资源库持有的字节，节点里只有 `resourceId`（或该类型声明的等价引用字段）。
- 地址是**运行时派生值**：渲染时经 `ctx.get('resources').resolve(resourceId)` 或统一解析钩子取得，用完即弃，不写回节点。
- 外部链接、`data:` 内嵌地址这类**没有资源实体**的地址，只允许作为**旧存档兼容**或节点类型显式声明的 `externalUrlField`；新写入的资源字节一律走资源库，不产生 `xxxUrl`。各类地址能否进 `data` 见契约里的“地址准入表”。
- 业务字段用 `camelCase`：`text`、`label`、`resourceId`、`externalUrl`。
- 尺寸统一写 `node.size`；不要直接拼 `data.cardWidth/cardHeight`。`nodeSizeOf` 读的是旧数据镜像 `data.cardWidth/cardHeight`，只用于**读旧存档/迁移**，不是写入口。
- 运行态写 `data.runState`；不要另造 `status`/`progress` 的平铺字段。
- 编辑所需的作品元信息（原图宽高、时长、裁剪基准）允许进 `data`，但要列入字段表；纯展示派生值（格式化后的“1920×1080”、字数）用 `titleExtra` 现算。
- 缓存类字段（如波形峰值）必须标“可重建”，并说明何时失效；不得把它当唯一数据源。

### 2.3 媒体引用表（目标形态）

| 节点类型 | 持久字段 | 运行时地址来源 | 备注 |
|---|---|---|---|
| `image` | `resourceId` | `resolve(resourceId)` | 上传/裁剪/生成的统一落点 |
| `video` | `resourceId` | `resolve(resourceId)` | 帧图用独立 `frameResourceId`，不挤占主引用 |
| `audio` | `resourceId` | `resolve(resourceId)` | 波形峰值现在写在 `data.audioWaveform`（运行态、可重建）；目标是移出或明确标缓存 |
| `3d-preview` | `resourceId`（或上游传入） | `resolve` / `upstream.media` | 目标字段；现行实现读上游 `imageUrl` |
| `image-compare` | `leftResourceId` / `rightResourceId` | 各自 `resolve` | 目标字段；现行实现读上游 `imageUrl`，自身未存左右 ID |
| `text` | `text` | — | 纯文本；大文本可另存 `resourceId` |

> 迁移期现有 `imageUrl/videoUrl/audioUrl` 仍可读，但它们只作为**旧存档兼容**；新写入一律只写 `resourceId`。
> 读完旧地址后不得再写回新的 `xxxUrl`，否则会把临时地址固化进存档。

新增媒体类型时，先在这张表加一行，再写节点声明与测试；不要只在代码里写字符串。

### 2.4 节点类型声明要写全

**现状可编译（迁移第 1 步之前）**：只有 `inputs/outputs`。先把能跑的写法放前面：

```ts
ctx.nodes.register({
  type: 'image',
  label: '图片',
  size: { w: 320, h: 240 },
  inputs: [{ port: 'target', acceptsTypes: ['text', 'image'] }],
  outputs: [{ port: 'source', contentType: 'image' }],
  in: ImageContent,
})
```

**迁移第 1 步之后（`produces/consumes` 进入 `NodeRegisterDef` 后启用）**：

```ts
ctx.nodes.register({
  type: 'image',
  label: '图片',
  size: { w: 320, h: 240 },
  produces: { image: { kind: 'image', refField: 'resourceId' } },
  consumes: { text: { kind: 'text', valueField: 'text' } },
  inputs: [{ port: 'target', acceptsTypes: ['text', 'image'] }],
  outputs: [{ port: 'source', contentType: 'image' }],
  in: ImageContent,
})
```

- `inputs/outputs` 管“能不能连”；`produces/consumes` 管“连上后读什么”。
- `kind` 词表统一：`image`、`video`、`audio`、`text`、`pano`、`file`；新词先登记再使用。
- `refField`（资源引用）、`valueField`（普通值）、`externalUrlField`（外部地址）三者恰好给一个。
- 没有声明 `produces` 的类型，`upstream.outputs` 为空；这是兼容边界，不是错误。
- 示例只演示字段形状；实际的 `inputs/outputs` 以该节点源码为准（例如图片节点当前也接受 `image` 输入）。

## 三、加媒体（图片/视频/音频）的唯一做法

### 3.1 目标链路

```
字节 → ctx.get('resources').put(blob) → resourceId
     → media.addNode(kind, resourceId, position, { nodeType?, meta? })
     → 对应节点类型创建器只写 resourceId
     → 渲染时 resolve(resourceId) 得到临时地址
```

### 3.2 允许的写法

- 首选：`useCapability<MediaCapability>('media')`（区域组件内）或宿主注入的 `media` 服务（逻辑插件）。
- 次选：`ctx.get('resources').put` + 目标类型的公开服务/创建器。
- 迁移期：`ctx.get('image').addImageNode` 仍可用，但新代码不要新增这种“按插件名调用”的写法。
- 完整签名以 `docs/design/plugin-contracts-proposal.md` 的 `MediaCapability` 为准；这里只写调用顺序。

**调用方向**：`media` 面向“放新节点/写现有节点”，内部转给节点类型创建器；`resources` 面向“存字节/换地址”，只处理资源本身。调用方先 `resources.put` 拿 ID，再用 `media` 落节点；不要反过来让 `media` 自己存字节。

### 3.3 禁止的写法

- 直接 `doc.createNode('image', pos, { imageUrl: blobUrl })`：绕过资源库与图片节点自己的尺寸/缩略图逻辑。
- 把 `blob:` 地址写进节点长期字段：刷新即失效。
- 把 `resolve()` 得到的临时地址写回 `data`：下次刷新会变成失效地址。
- 自己实现“文件类型 → 节点类型”的映射表：应调用 `media.available()` / `media.addNode`。
  > 迁移期兜底：`plugin-file-drop` 在**没有资源服务**时会写 `blob:`（极简宿主/单测路径）；这是已知例外，正常宿主不得走。

## 四、读上游数据

### 4.1 允许的写法

```ts
const upstream = useCapability<UpstreamCapability>('upstream')
const image = upstream.media('image')
const texts = upstream.ofType('text')
```

### 4.2 禁止的写法

- 自己 `doc.getEdges()` 扫全图，再按 `data.imageUrl` 猜类型；
- 把上游节点的整包 `data` 复制到自己节点；
- 在消费方写“如果字段是 imageUrl 或 url 或 src”的兼容分支。

### 4.3 边界情况

- 没有上游：返回空，不抛错；组件显示“把图片节点连进来”。
- 上游节点类型不声明 `produces`：`outputs` 为空，视为不可读；不要偷偷读 `data`。
- 上游被删除：`subscribe` 触发，组件重算；能力实例随组件卸载回收。
- 上游只给 `resourceId`：消费方拿引用，自己 `resolve` 成地址；不要要求上游顺便给 URL。

### 4.4 上游的上游（执行插件）

- 每个上游对象都能继续 `node.upstream()`，不要只读一层；`node.ancestors()` 拿整条链，`depth()` 拿层数。
- 执行插件从末端倒推时用 `upstream.order()`：它返回“最早依赖在前、当前节点最后”的拓扑序。
- 不要自己 DFS/递归；环检测、去重、分叉合并都由 `upstreamGraph` 的纯函数处理。
- 前端用 `doc.getNodes()/getEdges()`，后台用 `CanvasDocument` 的节点/边表，共用同一份 `upstreamGraph` 函数。

## 五、UI 与主题

- 浮层/菜单/面板的圆角、颜色、字号、动效一律用设计 token；见 `docs/design/ui-style-guide.md`。
- 业务插件按名取设计系统件：`useUiComponent('button')`、`useUiComponent('dropdown')`；不要 import 主题包组件。
- 节点区域只用十个区域词：`in/title/out:top/out:bottom/out:left/out:right/on:top/on:bottom/over:inset/over:outset`；不要写老词 `content`、`overlay`。
- 主题单赢家槽（内置枚举 `nodeShell/edge/edgeDefaultType/background/connectionLine`）用 `order` 小的覆盖；`settingsPanel` 是主题插件按字符串注册的槽，不在枚举里。可叠加装饰层用 `occupants` 全量渲染。

## 六、设置与命名

- 设置 key 必须带插件前缀：`web2apiMcpEndpoint`、`imageGenBaseUrl`；不要用 `debug`、`baseUrl` 这种全局裸名。
- 设置分组用“一级/二级”：`布局/自动布局方向`。**槽键是完整分组 key**：二级页要接管内容，写 `settingsGroup/布局/自动布局方向`；只有扁平分组（`Agent`、`插件`、`光标`）才是“一级名 = 完整 key”。
- 新代码的命令 id 用 `插件名:动作`；事件名用 `插件名:事件`；存储 key 用 `插件名:字段`。存量写法有点号/斜杠混用（`image.upload`、`ui/context`），迁移期不改，只对新增生效。

## 七、生命周期与全局状态

- 不在模块顶层创建定时器、EventSource、Vue app；放在 `apply` 里并用 `ctx.effect` 回收。
- 不长期挂 `window` 单例；调试工具可用，但必须提供 `dispose` 并在 `ctx.effect` 里摘除。
- 卸载时要恢复：全局 CSS 变量、`document.body` 类、`documentElement` 样式、全局事件监听。
- 前端插件带后台半时，必须说明“前端卸载 ≠ 后台卸载”，并提供后台卸载入口。

## 八、测试

每个插件至少要有三类测试：

1. **纯逻辑**：几何、解析、过滤、状态机。
2. **单插件装配**：只装它 + 宿主基础服务，能启动、能注册、卸载干净。
3. **协作边界**：装 A + B 时能工作；不装 B 时明确降级；热装 B 后自动恢复。

契约测试优先测“名字/字段/顺序”，不要只测“函数被调用”。例如：

- `produces.image.refField === 'resourceId'`，且 `upstream.media('image').resourceId` 与之一致；
- `ui` 目录声明的名字与消费方 `useUiComponent` 的名字一致；
- `dispose` 后全局监听/单例/样式全部恢复。

## 九、提交前自检

- [ ] 没有 import 其他插件的实现文件。
- [ ] 硬依赖写进 `inject`；可选依赖用 `tryGet` 并有可见降级。
- [ ] 节点类型声明了 `produces/consumes`（如果是数据节点）。
- [ ] 加媒体走 `media`/`resources`，没有直接拼 `imageUrl`。
- [ ] 读上游走 `upstream`，没有扫 `getEdges()` 猜字段。
- [ ] 设置 key、命令 id、事件名都带插件前缀。
- [ ] 定时器、连接、DOM 监听、全局样式都有清理。
- [ ] 有单插件装配测试和“缺协作方”测试。
