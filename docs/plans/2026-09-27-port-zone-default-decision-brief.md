# 端口几何默认值 · 决策材料（执行计划 T10）

日期：2026-09-27 · 类型：决策材料（**只记录，不改代码**）· 状态：**待负责人选定**

## 要决定什么

端口吸附区（浮动端口那只"半圆耳朵"的命中区）的默认几何，取哪个来源为准：

| 字段 | 宿主回落（未装主题插件时） | 主题插件 Config 默认（当前成品应用走这条） |
|---|---|---|
| portZoneWidth（横向宽度） | 86 | **10** |
| portZoneHeightRatio（高度占节点高比例） | 0.8 | **0.55** |
| portZoneArcRatio（半椭圆饱满度） | 1 | **0.8** |

两个来源相差最大 8.6 倍（宽度）。

## 现状：谁在生效

**成品应用（packages/ui）走的是主题插件的值**，不是宿主回落值。

实测（内置浏览器跑 :5288，读 ctx.get("settings") 与真实端口 DOM）：

    settingPortZoneWidth: 10
    settingHeightRatio:   0.55
    settingArcRatio:      0.8
    zoneHeightPx: "110px"      // 200 高节点 × 0.55
    zoneWidthPx:  "54px"       // 横向命中区

原因：`App.vue` 用 `:handle-visual="ui.cfg.handle"` 传入 `DEFAULT_THEME_HANDLE`，
`CanvasHost` 只在父级**没传** `handleVisual` 时才回落 `DEFAULT_HANDLE_VISUAL`（86/0.8/1）。
所以 86/0.8/1 只在自建宿主、未装 theme-default 时生效。

复现：起 `pnpm -C packages/ui dev`，读 `window.MiniCanvasUI.getContext().get("settings")`。

## 影响面（动这里会改变什么）

1. **命中范围**：portZoneWidth 是端口交互区矩形的主尺寸，也是吸附带宽缺省时的兜底
   （BaseNode.vue:637-639）；改它直接改变"鼠标离多近能命中端口"。
2. **可见外观**：zoneHeight = 节点高 × ratio，是那只半圆耳朵的高度；ratio 从 0.55 → 0.8
   会让耳朵明显变高。
3. **存量设置**：settingsPersist 会把用户改过的值落盘。若改默认值，**已保存过的用户不受影响**
   （他们存的是具体值）；只影响"从没调过这一项"的用户。
4. **多选框批量端口**：multi-select 复用同一份 handleParams（SelectionFrame.vue:94），跟着一起变。
5. **调试叠加**：端口调试/吸附调试的 SVG 用同一份几何（useNodeDebugOverlay）。

## 三个方案

### 方案 A（推荐）：以主题值为准，把宿主回落对齐到 10 / 0.55 / 0.8

理由：成品应用与全部 24 个插件的实际观感都以主题值为准，实测已确认。把宿主回落对齐，
消除双源；自建宿主（不装主题插件）从此也得到同一套几何。

代价：自建宿主的命中区从 86 缩到 10（更贴合当前成品观感），需浏览器回归确认拖线仍好命中。
可行性：吸附带另有自己的宽度配置（`DEFAULT_THEME_SNAP_ZONE.width=24`），命中不只靠 portZoneWidth，
故缩小不等于"连不上"。

### 方案 B：以宿主值 86 / 0.8 / 1 为准，把主题 Config 默认改成它

适用情形：如果 10 只是 d550a05 那次改动留下的非预期值、而 86 才是想要的"大命中区"。

代价：会让成品应用的端口耳朵与命中区**当场变大**，属用户可见的行为变化，需回归。
存疑：无迁移记录说明 86 是终值（契约 §11 明确记"d550a05 只改值没写理由"）。

### 方案 C：不改数值，只消除"双源"这个结构问题

做法：让宿主回落默认值从主题 Config 派生（单一来源），或把命中区与可见耳朵拆成两个独立配置项。

适用情形：想先把结构理顺、把"数值该是多少"留到以后。
代价：仍要决定派生方向（即本质仍是 A 或 B），只是延后。

## 选定后的实施前提（不在本票范围）

无论选哪个，真正动几何前必须先做：

1. 读 `docs/tmp/canvas-core-v2-survey/core-node-contract.md`（六件 66 条不变量 / 27 条易碎点，
   其中 §9-1 就是本条）——核心节点件是红线，改动前先对齐契约。
2. 单测：`portZoneGeometry` 之类的纯函数断言 + BaseNode/MovingHandle 渲染断言。
3. 浏览器回归：拖线命中（含多选批量端口）、缩放跟手、端口调试叠加显示正确。
4. 只改"默认值来源"或"默认数值"，不动用户已保存的具体值。
