# plume-canvas UI 编写规范

这份文件只讲「界面怎么写」。组件怎么取、怎么补，见同目录的 `SKILL.md`。

## 一、先分清两类东西

| 类别 | 例子 | 规则 |
| --- | --- | --- |
| 原子件 | `Button`、`Input`、`DropdownMenu`、`Select`、`Popover` | 原样用 shadcn-vue，不改名、不二次封装、不改内部结构 |
| 复合件 | `AppDialog`、`ScrollPane`、`SettingsRow` | 只在确实反复出现同一套组合时才用；用之前先看能不能直接拼原子件 |

判断标准：**如果只是「省一次写代码」，不要新增复合件。** 只有「重复出现、每次都容易写错、且错法一致」时才抽。

## 二、选哪个浮层

| 场景 | 用 |
| --- | --- |
| 一组动作（新建 / 删除 / 更多） | `DropdownMenu` |
| 表单里只选一个值 | `Select` |
| 带复杂内容的弹出面板 | `Popover` |
| 一句短提示 | `Tooltip` |
| 右键菜单 | `ContextMenu` |
| 可搜索的选择 | `Combobox` |

不要用原生 `<select>`，也不要手搓绝对定位菜单。

## 三、同一时刻只能开一个浮层

**规则**：任何下拉 / 选择 / 弹出面板打开时，其它已经开着的浮层必须自动收起。

这条由组件库的根组件统一执行（`packages/ui-kit-shadcn/src/popup/exclusive.ts`），
`DropdownMenu`、`Select`、`Popover`、`Combobox` 都已接入。业务代码**不要再自己写一套互斥表**，
写了两套反而会打架。

例外只有一种：**在父面板里再打开的子浮层**不关父面板（父子豁免靠浮层链判断）。
二级菜单（`DropdownMenuSub`）本身不参与互斥。

写新浮层时，如果它是独立的根组件，必须接 `usePopupExclusive`；否则它就是个漏网的。

## 四、下拉宽度：按内容算，不写死像素

**反面例子**：参数面板写死 `width: 288px`，6 个比例格按 5 列排，第二行只剩一格、
右侧一大片空白 —— 用户看到的是「宽度没有自适应」「高度怎么这样」。

规则：

1. 宽度优先 `width: max-content`，让内容决定。
2. 必须给上下限：`min-width` 保证最窄放得下内容，`max-width` 不超出视口
   （用 `min(<上限>px, calc(100vw - 32px))` 这种写法）。
3. 网格列数按**实际选项数**算，不要固定列数。
   `presetColumns(kind, optionCount)`：比例最多 6 列、按选项数排一行；其它网格 3 列。
4. 靠近屏幕边缘时要能翻转或内收（`collisionPadding` / `avoidCollisions` 默认开着，别手动关）。

## 五、二级菜单（子菜单）必须留 8px

这是最容易做错的一条。

**规则**：父菜单的**可见右边缘** 到 子菜单的**可见左边缘**，必须相距 `8px`。

为什么容易错：reka 的 `sideOffset` 是从**触发行边框**量起的，而触发行缩在父面板的
内部留白里（`p-1.5` = 6px）。所以：

- 写 `sideOffset: 8` → 实际可见缝隙只有 2px；
- 父面板还有外框和圆角 → 实测会变成**负数（子菜单压在父菜单上，重叠 8px）**。

正确做法：挂载后读真实矩形算，别靠猜数字。

```text
可见间距 = (父面板可见边缘 - 触发行边框) + sideOffset
因此     sideOffset = 可见间距目标 + (父面板可见边缘到触发行边框的距离)
```

组件库已把这件事收在 `packages/ui-kit-shadcn/src/popup/useSubMenuGap.ts`，
`DropdownMenuSubContent` 直接用，**调用点不要再手写 `side-offset`**。
设置里的「子菜单间距」改的是目标值，不是这个补偿值。

翻转（子菜单翻到左侧）时用镜像公式，否则左右两侧会得出两个不同的间距。

另外：测量不要依赖 `requestAnimationFrame`。浏览器会暂停后台标签页的 rAF，
窗口在后台时永远量不出来。用 `nextTick` 加重试就行。

## 六、箭头和触发器间距

| 关系 | 默认 | 量法 |
| --- | --- | --- |
| 父菜单 → 子菜单 | 8px | 父面板可见边缘 → 子菜单可见边缘 |
| 带箭头浮层 → 触发器 | 8px | **箭头尖端** → 触发器可见边缘 |
| 无箭头浮层 → 触发器 | 8px | 浮层可见边缘 → 触发器可见边缘 |

箭头显隐、间距档位由「设置 → 外观 → 浮层」统一控制（`--plume-popup-*`）。
调用点不要写死 `arrow` 或 `side-offset`，除非是在做这个配置适配本身。

带箭头的浮层要记得扣掉箭头本身的高度，否则尖端会比配置值远一截。

## 七、滚动容器

任何可能超出容器的列表、正文、抽屉，用 `ScrollArea`（应用外壳里用 `ScrollPane`），
不要写 `overflow-y: auto` 的普通 div。

父容器必须有确定高度并且允许收缩（`min-h-0` / `flex-1`），否则不会滚。

## 八、颜色、圆角、字号

只读 token：`--ui-*`（颜色）、`--plume-*`（圆角 / 字体 / 尺寸 / 浮层）。
不要在页面里写死色值、圆角、字号，也不要用 `:deep()` 改公共组件内部。

`class` 只用来管位置、大小、间距；外观优先用组件的 `variant` / `size`。

## 九、提交前自检

1. 同屏只有一个浮层开着的？点第二个时第一个自动收了？
2. 二级菜单与父菜单可见间距是 8px（不是 2px、也不是重叠）？翻转后重新量一次。
3. 面板宽度是内容决定的，不是写死的？最窄 / 最宽 / 视口边缘三种情况都看过？
4. 网格列数按选项数算的，没有残行？
5. 滚动用的是 `ScrollArea` / `ScrollPane`？
6. 没有自造色值、圆角、字号？
7. 亮色 / 暗色 / 窄窗口都看过？
8. 用 `getBoundingClientRect()` 量，不靠截图目测猜像素。
