# 节点交互区域与连接线拖拽规范

> 本文档定义节点上各交互区域的职责边界，以及拖线（连接线拖拽）从 hover 命中到松手落边的完整机制。
> 目标：让「UI 渲染层」和「数据/能力层（canvas-render）」各司其职，不再互相越界。

---

## 一、节点的三个交互区域

一个节点（卡片）在连接线拖拽场景下，可划分为三个职责不同的区域：

| # | 区域 | 位置 | 连接线拖到这里的表现 | 职责 |
|---|------|------|----------------------|------|
| 1 | **节点区域** | 整张卡片主体（`.v2-node` / `.v2-card` 矩形） | 连接线结束点 = **鼠标位置**（跟鼠标，不吸附到端口） | 作为「卡片命中」目标，松手可连（走类型校验） |
| 2 | **端口区域** | 端口圆点（「+」按钮）及其 hover 跟随的移动范围 | **不参与连接判定** | 唯一用途：鼠标 hover 时让「+」圆形按钮跟随移动 |
| 3 | **吸附区域** | 端口外缘的吸附带（半圆/矩形耳朵） | 连接线结束点 = **该区域所属端口的位置**（吸附对齐端口锚点） | 真正触发「吸附」的区域，松手落边 |

**关键区分**：
- 端口区域 ≠ 吸附区域。端口区域只管「+」按钮跟随，是纯交互 UI；吸附区域才是连接线命中判定的区域。
- 节点区域和吸附区域都支持连接线拖拽，但**结束点不同**：节点区域跟鼠标，吸附区域吸到端口锚点。

---

## 二、3D 效果的触发时机

3D 倾斜（`showConnectFeedback` / `cardTransform`）**只在「吸附区域 + 节点区域」命中、且该连接合法（通过类型校验）时出现**。

- 触发条件：拖线中，且数据层判定当前节点是「合法连接目标」（`hoverNode.status === 'valid'`）。
- **不触发**：物理鼠标 hover（`isHovered`）本身不触发 3D；物理 hover 只负责端口显隐（`shouldShowHandles`）与卡片阴影。
- 命中吸附区域 → 3D 出现（结束点吸到端口）。
- 命中节点区域（body）→ 3D 也出现（结束点跟鼠标）。
- 拖到空白 / 方向不对 / 类型不符 → 不 3D。

**核心原则**：3D 是否显示，只由「数据层合法目标」这一个信号决定，UI 层不自己用物理 hover 去猜。

---

## 三、类型区分（是否支持连接）

「两个节点能否相连」由**后台类型系统**判断，UI 层不重复实现：

- 每个节点类型声明自己的**输入/输出内容类型**（`acceptsTypes` / `contentType`）与端口容量（`capacity`）。
- 拖线落边前，`checkConnection` → `validateConnection` 依据类型定义判断方向（`bad-orientation`）、内容类型（`accepts`）、容量（满额挤最老）。
- 校验结果映射成 `valid` / `invalid`（`reason` 给中文文案），驱动 3D（valid）或非法气泡（invalid）。

## 四、吸附区域的实现机制（emit → render 维护变量 → 松手判边）

吸附区域之所以能「吸」，是因为它把「鼠标命中」这一事实通过事件上报给渲染能力层，由能力层统一判定，而不是 UI 自己算几何。

### 完整链路

1. **前端上报命中（emit）**
   - 吸附带元素（`.v2-snap-zone`，独立于端口按钮跟随区 `.moving-handle-zone`）的 `@mouseenter` 上报 `aim`（`side: 'input' | 'output'`）。
   - 吸附带 `@mouseleave` 即时清空（无 180ms 归位延迟，避免残留误吸附）。
   - 节点区域（卡片）的 `@mouseenter/@mouseleave` 同样上报（`side: 'body'`）。
   - **端口区域（`.moving-handle-zone`）不上报 aim**：它只负责「+」按钮跟随（`@mousemove`），不参与连接判定。

2. **BaseNode 汇总写入 render 变量**
   - BaseNode 里吸附带元素的 `@mouseenter/@mouseleave` 直接维护 `aimPortSide`（input/output），卡片维护 `aimBody`，再通过 `watch` 写入共享状态 `connectionState.aimedTarget`（`AimedTarget = { nodeId, side }`）。
   - 只在拖线期间、且非源节点自身时写入；离开时清空。

3. **render 库维护 `aimedTarget` 变量**
   - `connectionState.aimedTarget` 是能力层维护的响应式变量，语义是「当前鼠标瞄准的目标（节点 + 区域）」。

4. **拖线过程中实时解析**
   - CanvasHost 拖线 `mousemove`（rAF 节流）读 `aimedTarget` → `resolveFromAim`：
     - 命中吸附区域（side=input/output）且校验通过 → 连接线端点**吸到端口锚点**，写 `hoverNode.zone='snap'`。
     - 命中节点区域（side=body）且校验通过 → 端点跟鼠标，写 `hoverNode.zone='body'`。
     - 方向不符 / 校验失败 → 端点跟鼠标，`hoverNode.status='invalid'`。

5. **松手判边**
   - CanvasHost `mouseup` 读 `aimedTarget` → `resolveFromAim` → `decideDropFromHover`：
     - `status === 'valid'` → `checkConnection`（后台类型校验）→ `commitEdge` 建边。
     - 否则松空，不建边。

### 一句话概括

> 吸附区域 hover 时发 `emit` 消息给 render 库；render 库内部维护 `aimedTarget` 变量；在鼠标松开时据此判断是否添加连接线。

---

## 五、分层职责约束（避免再乱）

- **UI 渲染层（BaseNode / MovingHandle）**：只负责「上报事实」——鼠标进了哪个区域（吸附带元素 `.v2-snap-zone` 的 `aim` 事件）、物理 hover（`hover` 事件）。**不自己算几何命中、不自己判断能否连接。** 端口按钮跟随区（`.moving-handle-zone`）只做按钮跟随，不上报 aim。
- **能力层（canvas-render / CanvasHost）**：维护 `aimedTarget` / `hoverNode`，负责「校验（后台类型）+ 吸附锚点 + 落边」。**不自己重算前端 zone 形状。**
- **3D 显示**：UI 层只读 `hoverNode.status === 'valid'` 这一个信号，不混入物理 hover。
