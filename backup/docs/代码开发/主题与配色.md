# 主题与配色 —— 全仓统一约定（`<html class="dark">`）

> 来源：`packages/canvas-render/src/styles/ui-theme.css`（通用 token 唯一真源）、
> `packages/plugins/plugin-theme-default/src/styles/node-theme.css`（`--canvas-node-*` 默认值）、
> `packages/ui/src/app.css`（Tailwind 入口 + `--canvas-node-*` 暗色覆盖）、
> `packages/ui/src/composables/ui.ts`（`applyTheme`）、`packages/ui/index.html`（首屏 class）、
> `packages/canvas-render/src/contracts/themePalette.ts`（**可配置主题色板**：每色亮/暗两格，见 §七）。
> 相关：`docs/design/ui-style-guide.md`（设计 token 规范）、`docs/代码开发/plugins/plugin-theme-default.md`。
>
> 本文是**规范**：写任何 UI 之前先看它。历史改造过程记在 `docs/tmp/plugin-theme-css/research.md`。

## 一句话

主题只有**一个开关**：`<html>` 上有没有 `dark` class（Tailwind v4 / shadcn 的通行做法）。
颜色一律取自 CSS 变量，**不靠 JS 传参、不靠插件配置项**，切主题时零重渲染。

```html
<html lang="zh-CN" class="dark">   <!-- 暗色 -->
<html lang="zh-CN">                <!-- 亮色 -->
```

---

## 一、三族变量，各归各位

| 族 | 定义处 | 谁在用 | 暗色覆盖写在哪 |
|---|---|---|---|
| `--ui-*` `--sf-*` `--ps-*` `--dd-*` | **`packages/canvas-render/src/styles/ui-theme.css`**（唯一真源，随包加载即生效） | 所有浮层、面板、控件、插件 UI | 同文件 `html.dark` 块 |
| `--canvas-node-*` | `plugin-theme-default/src/styles/node-theme.css`（`:root` 亮色默认） | 节点壳 / 端口 / 边 | `packages/ui/src/app.css` 的 `html.dark` 块 |
| 组件私有 `--xx-*` | 组件自己的 `<style scoped>` | 只有自己 | 同 `<style>` 内 `html.dark .your-root` |

**为什么通用 token 放 canvas-render 而不是 canvas-data**：这是渲染层的事，canvas-data 是零 Vue / 零 DOM 的内核；
而且 24 个插件里有 16 个已经依赖 canvas-render，放这里它们自动就能拿到。
放 `@mini-canvas/ui` 不行——插件不在那棵依赖树上，拿不到，只能各自硬编码（这正是改造前的状况）。

## 二、宿主怎么切主题

`packages/ui/src/composables/ui.ts`：

```ts
function applyTheme(v: 'dark' | 'light'): void {
  document.documentElement.classList.toggle('dark', v === 'dark')
  document.documentElement.dataset.canvasTheme = v   // 兼容旧写法
}
```

- `App.vue` 在 `onMounted` 调一次 + `watch(() => s.theme)` 跟着调；
- `index.html` 上预置 `class="dark"`，避免首屏亮→暗闪一下；
- Tailwind 变体声明在**入口** `app.css`：`@custom-variant dark (&:where(.dark, .dark *))`，
  之后 `dark:bg-panel` 这类写法才认这个 class（而不是系统 `prefers-color-scheme`）。

> `data-canvas-theme` 属性只是兼容残留，CSS 里与 `.dark` 写在同一条规则中共享取值，新代码不要依赖它。

## 三、组件 / 插件怎么写（标准姿势）

### 3.1 通用色：直接 `var(--ui-xxx, 浅色兜底)`

```css
.panel {
  background: var(--ui-glass, rgba(255, 255, 255, 0.92));
  border: 1px solid var(--ui-line, rgba(0, 0, 0, 0.08));
  color: var(--ui-ink, #374151);
  box-shadow: var(--ui-shadow-md, 0 20px 40px rgba(0, 0, 0, 0.1));
}
.item:hover { background: var(--ui-hover, rgba(0, 0, 0, 0.05)); }
.item.is-danger { color: var(--ui-danger, #ef4444); }
```

**兜底值写改造前的浅色值**——脱离主题表单独渲染（单测、Storybook、嵌到别的宿主）也不崩。

### 3.2 组件私有色板：默认亮色 + `html.dark` 覆盖

```css
.mini-map-overlay {          /* 默认 = 亮色 */
  --mm-bg: #f8fafc;
  --mm-radius: 12px;
}
html.dark .mini-map-overlay { /* 暗色：注意是 html.dark，不是 .dark */
  --mm-bg: #252525;
  --mm-radius: 0px;
}
.mini-map { background: var(--mm-bg); border-radius: var(--mm-radius); }
```

### 3.3 绝对不要做的事

❌ **不要给单个插件发明 `theme` / `配色` 配置项（"跟随/浅色/深色"这类开关）。**
曾经 mini-map 有个 `miniMapTheme`（跟随/浅色/深色）下拉框——主题明明是全局的，
却降格成"只有小地图才有的开关"，每个插件都得抄一遍 MutationObserver + 调色板 + 内联变量。已删除。

> 注意与 §七 的区别：**按插件自己切主题**是禁止的；**全应用范围改配色**是允许的，
> 且只有一处配置（渲染层色板，`themePalette.ts`）。判断标准：这个配置会不会让两个组件在同一时刻显示不同的主题？
> 会 → 禁止；不会（只是换品牌色，全局一起换）→ 允许。

❌ **不要在 TS 里维护颜色常量表、用 JS 算配色、绑 `:style="rootVars"`。** 切主题要重新打包，且与 CSS 变量平行存在、各写各的值。

❌ **不要写死颜色。** 写死了暗色下就是"白底黑字"。

## 四、四个必踩的坑（都已踩过并修好）

1. **`@custom-variant` 只有 Tailwind 入口才处理。**
   写在 `ui-theme.css` 里会**静默失效**，`dark:` 变体仍认系统偏好。
   必须写在带 `@import "tailwindcss"` 的文件里（这里是 `packages/ui/src/app.css`）。

2. **特异性：写 `html.dark`（0,1,1），不要写 `.dark`（0,1,0）。**
   `.dark` 与 `:root` 同为 0,1,0，`plugin-theme-default/styles/node-theme.css` 后加载就赢——
   第一次改完 `--canvas-node-surface` 在暗色下还是亮色 `#f9fafb`，就是这个原因。
   组件 scoped 规则是 0,2,0，所以覆盖它的分支要用 `html.dark .your-root`（0,2,1）。

3. **`scoped` 样式里别用 `:global(html[...]) .cls`。**
   Vue SFC 编译器会把整个选择器当全局、丢掉 `.cls`，规则退化成裸的 `html[...] { --x: ... }`
   （污染全局且特异性反而更低）。直接写 `html.dark .cls` 就对——scoped 只给**最后一段**加 `data-v-xxx`。

4. **JS 动态建的 DOM 拿不到 CSS 变量。**
   如框选框（`BoxSelectLayer.vue`）是 `document.createElement` 出来的，只能运行时读：
   ```js
   const guide = getComputedStyle(document.documentElement)
     .getPropertyValue('--ui-guide').trim() || '#3b82f6'
   ```
   代价：已建的框在切主题时不会变色。框选是一次性短生命周期交互，可接受；要实时就改监听属性变化 + `style.setProperty`。

## 五、token 清单

`ui-theme.css` 共 **59 个** token，`:root`（亮色）与 `html.dark`（暗色）严格对称。
其中 5 个是**派生值**（`--ui-arrow: var(--ui-glass)`、`--sf-accent`/`--ps-accent` → `var(--ui-accent)`、
`--dd-bg`/`--dd-line`/`--dd-ink` → `var(--ui-panel/-line/-ink)`），暗色块里不必重复列出，自动跟随。

语义分组：

| 组 | token | 用途 |
|---|---|---|
| 面 | `--ui-canvas-bg` `--ui-panel` `--ui-panel-soft` `--ui-panel-active` | 画布底、面板底、次级底、选中态底 |
| 线 | `--ui-line` `--ui-line-soft` | 边框、分隔线 |
| 字 | `--ui-ink` `--ui-ink-dim` `--ui-ink-mute` | 主文字、次要、弱化（见 ui-style-guide §2.1 四档灰阶） |
| 交互层 | `--ui-hover` `--ui-hover-strong` `--ui-hover-soft` `--ui-veil` `--ui-chip` | hover / 选中 / 卡片底；暗色=白色系，亮色=黑色系 |
| 浮层 | `--ui-overlay` `--ui-overlay-solid` `--ui-glass` `--ui-arrow` `--ui-tip` | 毛玻璃面板、箭头、tooltip |
| 遮罩/阴影 | `--ui-scrim` `--ui-scrim-soft` `--ui-shadow-md` `--ui-shadow-lg` | 模态遮罩、两级高度 |
| 品牌色（**每色亮/暗两格，可在设置里改**，见 §七） | `--ui-accent(-hover/-soft)` `--ui-danger(-soft/-veil)` `--ui-warn` | 唯一强调色（青）；删除等破坏性操作；限时折扣等提示文案 |
| 画布内容（**每色亮/暗两格**） | `--ui-edge-rail` `--ui-edge-flow` | 连线导轨色、流光光斑色（CustomEdge 经 `useThemeColor` 读） |
| 画布辅助 | `--ui-guide` `--ui-guide-veil` | 对齐参考线、框选框（**每色亮/暗两格**） |
| 滚动条 | `--ui-scroll-thumb(-hover)` | 全局滚动条 |
| 主按钮 | `--ui-primary-bg(-hover)` `--ui-primary-ink` | 亮色下深底浅字保证对比度 |
| 设置字段 | `--sf-label` `--sf-desc` `--sf-line` `--sf-track` `--sf-thumb` `--sf-accent` `--sf-bubble-*` `--sf-input-*` | `SettingsSchemaField` 消费 |
| 精度滑块 | `--ps-track` `--ps-accent` `--ps-accent-hover` `--ps-thumb` | `PrecisionSlider` 消费 |
| 下拉浮层 | `--dd-bg` `--dd-line` `--dd-ink` | `Dropdown` / `Select` 消费 |

**加新 token 时，`:root` 与 `html.dark` 两侧都要给值**，否则缺失的一侧会静默继承另一侧。

**可配置色例外**：`--ui-accent` 一族、`--ui-danger`、`--ui-warn`、`--ui-edge-rail`、`--ui-edge-flow`、
`--ui-guide` 走**两格制** —— `:root` 写 `var(--uic-<key>-light, 默认)`、`html.dark` 写
`var(--uic-<key>-dark, 默认)`，用户改过的那格以内联变量压过本文件（见 §七）。
它们的 `*-soft` / `*-veil` 派生档必须用 `color-mix(in srgb, var(--主色) N%, transparent)` **现算**，
不能写死 rgba（写死的话用户改了主色，这些派生档还是旧的青绿 —— 就是"改一半"的漂移）。

### `.ntp-root`（控制栏容器，唯一一套规则）

控制栏的**容器**（排一行 + 一块小面板）收成 `ui-theme.css` 里的一个全局类 `.ntp-root`：
`display:flex` / `gap:4px` / `padding:4px` / `radius:10px` / `bg:--ui-overlay-solid` /
`border:1px --ui-line` / `shadow:--ui-shadow-md`。

节点上/下控制栏、多选框上控制栏、分组工具栏**四处共用它**，各自不再写容器 CSS。
放在全局而不是 scoped：scoped 只作用于本组件模板，插件想复用就得各抄一遍 —— 那正是漂移的来源
（改造前 `.it-root`/`.vt-root`/`.group-top-toolbar`/`.selection-group-toolbar` 四份，
底色就已经一处 `--ui-panel`、三处 `--ui-overlay-solid`）。

**它只管容器，不管位置**：贴边距离 / 居中 / 反缩放由各宿主的上/下插槽定位层给。

### 设计系统件按名取（可整体换皮）

插件不要在模板里直接 `import` 按钮/下拉，而是
`const Btn = useUiComponent('button')`（`@mini-canvas/canvas-render`），
模板里 `<component :is="Btn" />`。目录里登记了：`button` / `dropdown` / `select` /
`slider` / `toolParamField` / `color`（登记处 `plugin-theme-default/src/index.ts` 的 `apply`）。

换一套主题插件、或不登记某个名字，所有消费方跟着变、业务插件零改动；
缺名时 `useUiComponent` 会 warn 并返回 `undefined`，所以消费方要写 `|| 'button'` 之类的降级。

`Select` 内部就是 `Dropdown`（`Select.vue` 直接 import `Dropdown.vue`），
所以"下拉"只有一个实现，Options 列表与自定义浮层共用同一套定位/动画。

### 硬编码色由**测试**守（不再靠人工清单）

`packages/ui/src/__tests__/themeColorHygiene.test.ts` 扫描
`packages/plugins` + `packages/canvas-render` + `packages/ui`，把"写死的颜色"钉在 0。
清单（原先是人工表格）会随开发过期，测试不会。

判定口径：

- **合法**：`var(--token, <兜底色>)` 的兜底（脱离主题表单独渲染不崩）；注释里的色值；
  `transparent`/`currentColor` 关键字；有 `html.dark` 块的**组件私有色板**（成对即合规）；
- **违规**：一条声明里直接给颜色字面量（没有 `var()`）、TS/JS 里的颜色字面量、内联 `:style` 绑的颜色；
- **豁免**：精确到行的 `主题色白名单: <原因>` 标记（原因必填）。**样式段里必须用
  `/* … */` 或写在颜色那行正上方 —— CSS 里 `//` 不是注释，会弄坏那条样式。**

豁免的正当理由只有几类：导出图片像素色（画进 canvas，取不到 CSS 变量）、
压在图片像素上的遮罩/描边（需恒定黑白色才有对比）、用户可选的数据色（分组标识色、
类型徽章色）、设置项默认值、恒白高光（`mix-blend-mode: screen`）。

## 七、可配置主题色板（**每个颜色亮/暗各一格**）

> 代码：`packages/canvas-render/src/contracts/themePalette.ts`（token 表 + 派生，纯逻辑）
> ＋ `packages/canvas-render/src/host/themePaletteSettings.ts`（声明与落值）。
> 由宿主 `createMiniCanvasHost` 直接装载 —— **不是插件**，任一宿主都自带。

### 7.1 解决什么问题

两个历史问题，都是"一个颜色伺候两套主题"造成的：

1. 品牌色曾是 `ui-theme.css` 里的死值，改色要动源码 + 重新构建，且没有任何可视化入口；
2. 更根本的：`Config` 的 `color` 字段是**单值**，而"连线颜色"这类语义在亮/暗两套主题下
   本来就该有**两个值**。实测过极端例子 —— 连线默认 `#1f2937` 在亮色画布上对比度约 13:1，
   在暗色画布（默认主题）上只有约 1.3:1，等于看不见。

### 7.2 两格制（核心机制）

每个可配置颜色拆成**两格**，各写一个**不同名字**的内联变量，由 CSS 按主题各挑一个：

```
accentColorLight → --uic-accent-color-light → :root     { --ui-accent: var(--uic-accent-color-light, #0891b2) }
accentColorDark  → --uic-accent-color-dark  → html.dark { --ui-accent: var(--uic-accent-color-dark,  #0891b2) }
```

于是：消费方**照旧只写一次** `var(--ui-accent, 兜底)`，不知道有几套主题；
切主题仍是纯 CSS 命中不同分支，**零 JS、零重渲染**。

为什么两格要用**两个不同名字**的变量：内联样式写在 `<html>` 一个元素上，没有"按主题分支"的余地 ——
同名会被后写的覆盖掉。拆成两个名字，才是纯 CSS 切换。

### 7.3 三层链路（单向，别绕路）

```
① 声明   buildThemeColorConfig()（themePalette.ts）→ 宿主 defineThemePaletteSettings()
                                                   → 内核登记进 settings 单一数据源
                                                   → 设置面板自动渲染取色器
② 落值   用户拖取色器 → settings.onChange → installThemePalette() 把"改过的那几格"
                                          写进 <html> 内联 CSS 变量
③ 消费   任何组件写 var(--ui-accent) / Tailwind 的 text-accent，就跟着变
```

**只写"用户改过的格"**：等于默认值的格**不写内联**，把控制权留给 CSS/主题插件。
内联优先级最高，若把默认值也写上去，主题插件在 CSS 里给的配色就永远被压住。

### 7.4 为什么写内联变量而不是改 CSS 文件

`<html style="--ui-accent: …">` 的内联优先级高于 `ui-theme.css` 与 `app.css` 里任何选择器
（除非对方带 `!important`），所以不需要提高特异性、也不怕加载顺序，一处写入全局生效。

### 7.5 字段与变量对照

分组：亮色格进 `常规/主题配色`，暗色格进 `常规/暗色主题配色`（设置面板里是两个页签，不糊成一坨）。

| token（基名） | 消费变量 | 亮色默认 | 暗色默认 | 中文名 |
|---|---|---|---|---|
| `accentColor` | `--ui-accent` | `#0891b2` | `#0891b2` | 强调色 |
| `accentHoverColor` | `--ui-accent-hover` | `#0e7490` | `#0e7490` | 强调色（悬停） |
| `dangerColor` | `--ui-danger` | `#ef4444` | `#f87171` | 危险色 |
| `warnColor` | `--ui-warn` | `#e3a25f` | `#e3a25f` | 警示色 |
| `edgeRailColor` | `--ui-edge-rail` | `#1f2937` | `#9ca3af` | 连线颜色 |
| `edgeFlowColor` | `--ui-edge-flow` | `#0891b2` | `#22d3ee` | 流光颜色 |
| `guideColor` | `--ui-guide` | `#3b82f6` | `#6366f1` | 参考线颜色 |

加新颜色 = 在 `THEME_COLOR_TOKENS` 加一行 + 在 `ui-theme.css` 两侧各接一次。
漏一侧 = 切主题不变色，`themePalette.test.ts` 会拦住（断言 token 表 ↔ CSS 两侧不漂移）。

### 7.6 为什么只开放这些（不开放背景/面板/文字色）

背景、面板、边框、文字是**结构性**颜色：它们在两套主题里成套联动（改一格会破坏整主题观感），
且属于主题插件该整套决定的东西，不由用户单点改。色板只收"跨主题语义稳定、且用户真的会想改"的颜色。

### 7.7 半透明变体必须`现算`，不能写死

`--ui-accent-soft` / `--ui-danger-soft` / `--ui-danger-veil` 一律用 `color-mix` 从主色派生：

```css
--ui-accent-soft: color-mix(in srgb, var(--ui-accent) 20%, transparent);
--ui-danger-soft: color-mix(in srgb, var(--ui-danger) 14%, transparent);
```

**不要写回 `rgb(8 145 178 / 0.2)`**。写死的话，用户把强调色改成紫色后，
主色变了、选中底/聚焦环还是青的 —— 这就是"改一半"的漂移。

### 7.8 组件怎么用（两种写法，任选）

```vue
<!-- ① Tailwind 工具类（推荐） -->
<button class="bg-accent text-white">主按钮</button>
<span class="text-danger">删除</span>
<div class="border-accent-soft">…</div>

<!-- ② 直接写 CSS 变量（自定义样式里） -->
<style scoped>
.my-thing { color: var(--ui-accent); border: 1px solid var(--ui-danger); }
</style>
```

可用变量：`--ui-accent` `--ui-accent-hover` `--ui-accent-soft` `--ui-danger`
`--ui-danger-soft` `--ui-danger-veil` `--ui-warn`；
对应 Tailwind 类：`accent` `accent-hover` `accent-soft` `brand` `danger` `gold`。

### 7.9 三个必踩的坑

1. **两格必须落到两个不同名字的变量。** 若两格共用一个变量名，写内联时后者覆盖前者，
   切主题永远只有一套值生效（症状：改了暗色那格，亮色也跟着变）。

2. **CSS 里 `//` 不是注释。** 在 `<style>` 段给某行加豁免标记时，`// 主题色白名单: …`
   会被当成声明的一部分**导致该条样式失效**；必须写成 `/* 主题色白名单: … */`，
   或把标记放到颜色那行的**正上方**（扫描器两处都认）。

3. **宿主停用要清干净。** `installThemePalette` 返回的 dispose 会解除订阅并逐个
   `removeProperty`。不清的话颜色还留着，下一个主题会被"幽灵变量"挡住。

### 7.10 实测验证方式

```js
// 浏览器控制台（或 e2e）：等价于在设置面板里拖取色器
const s = window.MiniCanvasUI.getHost().ctx.get('settings')
s.set('accentColorDark', '#7c3aed')   // 只影响暗色
// 立刻可见：--uic-accent-color-dark 变 #7c3aed，暗色下 --ui-accent 跟着变，
// --ui-accent-soft 变成 color-mix(…#7c3aed…)；切到亮色仍用 accentColorLight
s.set('edgeRailColorDark', '#e5e7eb') // 暗色连线变浅灰（默认 #9ca3af 已可读）
```

**JS 通道**（SVG 表现属性 / canvas 2D 这类吃不到 `var()` 的地方）：用
`useThemeColor('edgeRailColor')`（canvas-render 导出）。它同时跟"改设置"与"切主题"两件事，
所以这类消费方不需要自己挂 MutationObserver。

**幽灵变量已清零**：`packages/plugins/**` 里不再有 `var(--fill-subtle,…)` / `var(--text-muted,…)` 这类
指向未定义变量的写法（可用 `git grep -E "var\(--(fill-subtle|text-muted|line-hair)" -- "packages/plugins/**/*.vue"` 复验，应无输出）。
