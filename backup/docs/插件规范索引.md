## 建议阅读顺序

1. 先读《方案》知道目标（哪些是提案、哪些是现状）。
2. 再读《迁移清单》知道步骤与验收。
3. 写代码前读《插件开发规范》的红线与自检。
4. 写节点字段时读《节点数据与上游契约》的声明形状与现行实现对照表。
5. 旧文档与教程按《文档审计》整改，避免同一概念三套说法。

## 三条最容易被忽略的规则

1. 插件之间不 import 实现；要能力就 `ctx.get`/注册场/能力场。
2. 加图片不直接拼 `imageUrl`；走 `media`/`resources`，让图片节点自己写字段。
3. 读上游不扫 `doc.getEdges()`；用 `upstream`，字段由上游节点类型声明。

## id 写法（2026-10-28 起强制）

| 东西 | 写法 | 例子 |
|---|---|---|
| 插件运行时名 | 小写短横线，不带 plugin- 前缀 | `agent`、`node-image` |
| 命令 / 事件 | 插件名:动作 | `agent:open`、`node-image:upload` |
| 槽内条目 | 插件名/条目名 | `agent/nav`、`host/add` |
| 槽名 | 点号分层 | `shell.dock`、`settings.nav` |

判定函数在 `@mini-canvas/kernel` 的 `naming` 模块；唯一例外是 `plugin-manager`（既有存储 key）。
