## 一句话

宿主给每个节点下发"你此刻该画到什么程度"的状态（`data._cullState`），
节点壳（BaseNode 等）**按状态自选绘制策略**：屏内全量画，屏外降级或干脆不渲染——
但**有连线牵扯的屏外节点永远保留壳**，连线因此永不断。

## 为什么不是直接 hidden

VueFlow 的硬规则：**只要边的一端 hidden，整条边不渲染**（EdgeWrapper render null）。
2026-10-15 上线的第一版剔除就是踩了这条——屏内节点的连线，另一端一出屏，线凭空消失。
所以 hidden 从"通用剔除工具"降级为"压缩档专用工具"，且**只允许用在没有任何
跨屏连线牵扯的节点上**（见下文压缩档）。壳常驻的另一个收益：连线端点坐标直接读
真实端口几何，不会漂；节点滚回视野无重挂闪变。

## 状态形状

`nodesFromStore(store, selectedIds?, cullIds?, linkedIds?, compactShells?)`
给每个节点注入 `data._cullState`：

| 状态 | 含义 | DOM | 内容组件 |
|---|---|---|---|
| `'visible'` | 视口（+缓冲带）内 | 壳常驻 | 全量挂载 |
| `'culled'` | 屏外且不在 linkedIds | 壳常驻（压缩档下**零 DOM**） | 不挂载 |
| `'culled-linked'` | 屏外但有连线相连（至少一端屏内） | 壳常驻（骨架） | 不挂载 |
| （不下发） | transient 临时节点 | 壳常驻 | 全量挂载 |

transient（拖线菜单卡等）不下发状态 = 壳读不到字段按 visible 全量处理，
与"临时节点永不剔除"语义等价。linkedIds 由 CanvasHost 按 edgeStore 建
顶点邻接表：**一条边的两端只有一端在视口内时，两端都算 linked**（两端都在外
或都在内的边不牵扯任何人）。

## 壳怎么消费（BaseNode 示例）

```ts
// 读状态（宿主下发；读不到 = visible）
const rawCullState = computed(() => props.data?._cullState)
// 绘制决策在纯函数里（culledRenderingPolicy.ts，可单测）：
// culledPolicy(state, rendering) → { reduced, visibleCard, ghost }
const culledReduced = computed(() => culledPolicy(rawCullState.value, culledRendering.value).reduced)
```

模板里按 `culledReduced` 给内容段 / 控制栏 / 区域条 / 多选标记加 `v-if`
（**不挂载**，不是藏起来——性能回收正在这里），标题条与 MovingHandle（真实
Handle 锚点）**保留**，卡片本体 skeleton 档 `visibility: hidden` 隐身占位、
ghost 档画可见空心框。注意：**MovingHandle 的挂载门不要加剔除条件**——
端口 DOM 常驻是 VueFlow handleBounds 稳定的前提（核心节点契约）。

## 两个设置项（常规/画布）

- **视口外节点绘制**（`culledNodeRendering`，theme-default Config）：
  `skeleton` 骨架（缺省）/ `full` 全量（等同关降级）/ `ghost` 占位框。
  这是壳策略档，改的是"屏外画多深"。
- **屏外壳压缩**（`cullCompactShells`，canvas-render 交互设置，缺省开）：
  开 = 纯 culled 节点 hidden=true，**连壳都不渲染**（1000 节点/屏内 20 场景，
  壳数量 ≈ 屏内数 + 跨线数）；关 = 壳全挂只降内容。屏内节点两种档位下都
  照常渲染，永不被压缩。

两者叠加语义：压缩先决定"有没有壳"，绘制档再决定"有壳的屏外节点画多深"。

## 宿主侧要点（改剔除逻辑前必读）

- 刷新时机两条：视口帧回调（rAF 节流 + cullIds diff 相同则跳过重灌）与
  store 订阅重灌（`syncFromStore` 内先 `refreshCull + rebuildLinkedIds` 再灌节点）。
  设置变更（`visibleCullEnabled / visibleCullBuffer / cullCompactShells`）即时重灌。
- cullIds 语义是**视口内可见集合**（名字来自 computeVisibleIds），
  判断"出屏"是 `!cullIds.has(id)`——别被名字带偏（本仓库已因此返工一次）。
- 缓冲带（`visibleCullBuffer` 缺省 300px）兜住慢速平移的滚回闪变；
  压缩档下快速甩动仍可能闪一帧（hidden → 常驻需要一帧挂载），介意就关压缩。
- 分批挂载（首批 40 + rAF 渐进 30/帧）优先挂可见节点；hidden 节点仍在
  nodes 列表里（VueFlow 内部 store 保留记录、不产 DOM），选中/位置数据不断。

## 验收基线（真机 Chromium 实测过）

1. 屏内节点的连线，另一端出屏后**完整显示**，端点跟真实端口走。
2. 线的一端出屏 → 该端 culled-linked 壳保留；两端都出屏 → 连线 DOM 同步消失。
3. culled 节点子树 8 个 DOM 元素（壳+锚点）vs 可见 24 个——内容组件真摘除了。
4. 压缩档开：屏外无连线节点 DOM 里查不到；pan 回滚壳即时恢复。
