# 插件身份切换手册：自带件 ⇄ 可装卸件（Runbook）

> 适用问题：用户问「某个插件不该自带，我要自己装」／「某个插件应该自带，别让我每次装」／
> 「插件面板里为什么找不到 X」／「为什么它同时出现在『自带』和『本地清单』两个页签」。
>
> 一句话结论：插件身份**由三处声明共同决定**，三处必须一起改，漏一处就静默出错（面板照常工作，
> 只是用户找不到，或者出现两个身份）。判据是 `package.json` 的 `miniCanvas` 段，不是源码。

## 一、两个身份的确切含义

| 身份 | 判据（package.json） | 谁装配它 | 面板里怎么看 | 用户能做什么 |
|---|---|---|---|---|
| **自带件**（builtin） | `miniCanvas.builtin: true` | 成品应用的冷启动清单 `packages/ui/src/assembly.ts` 的 `APP_PLUGINS` | 「设置 → 插件 → 自带」页 | **只读**：没有安装 / 卸载按钮（`pluginManagerService` 的 `install` / `uninstall` / `reinstall` 三条路开头都有 `if (row.entry.builtin === true) return` 兜底） |
| **可装卸件**（installable） | `miniCanvas.installable: true` | 「插件管理」从清单 URL 装进内核 | 「设置 → 插件 → 本地清单」（本地目录）或「市场」（NPM 来源） | 安装 / 卸载 / 重装 |

`builtin` 与 `installable` **语义互斥**：同时写，插件会在两页各出现一次（同一插件两个身份，最难查的一类错）。

两份清单的生成口径是同一套（dev 与生产各一份实现，互相守卫）：

- dev：`packages/ui/catalogPlugin.mjs` 的 `buildCatalog`（vite 插件，只在 `pnpm -C packages/ui dev` 生效）
- 生产：`packages/cloud-server/src/plugins/catalog.ts` 的 `buildPluginCatalog`

两边都只做两件事：声明 `installable` 的**必须**在 `dist/` 里有能装载的产物才列出来；
声明 `builtin` 的直接列（**不要求产物**，因为它由应用源码装配，不经过 URL 加载）。

## 二、改身份要动的三处（漏一处就静默出错）

1. **插件包自己的 `package.json`** —— 身份的唯一事实源。

       包目录/package.json
       {
         "miniCanvas": {
           "title": "组件展厅",
           "description": "一句话说清它干什么（面板显示这两行）",
           "pluginName": "theme-gallery",
           "installable": true
         }
       }

   - `pluginName` 必须等于源码 `export const name` 的值（面板按它认「已装」）。
   - 可装卸件写 `installable: true`；自带件写 `builtin: true`（不要两个都写）。

2. **成品应用的冷启动清单**（只对自带件有意义）—— `packages/ui/src/assembly.ts` 的 `APP_PLUGINS`。
   声明了 `builtin` 就必须**同时**在这里装配，否则是假绿灯：面板显示「已装」，画布上其实没这个能力。
   反过来同样成立：不在 `APP_PLUGINS` 里的插件**不该**声明 `builtin`。

3. **能打出产物**（只对可装卸件有意义）—— 该包要有 `build` 脚本 + `vite.config.ts`，
   且产物必须能被面板装载（见第三节）。

另有一处**不在插件包里**、漏了会「本地能装、一键启动装不上」：
`packages/cloud-server/scripts/build-assets-parallel.mjs` 的 `INSTALLABLE_PLUGIN_DIRS` 目录清单。
它决定「一键启动」的 assets 里带哪些插件的产物；不加进去，后台发出去的清单里就没有它。

## 三、可装卸件的产物规矩

面板装载走两条路，**由清单的 `format` 字段显式决定**（混着猜就会「列出来了却装不上」）：

| format | 加载方式 | 产物要求 | 典型 |
|---|---|---|---|
| `umd`（缺省） | `plugin-manager` 的 `umdLoader`：`<script>` 注入 + 从 window 全局取插件对象 | 文本里有 `.MiniCanvasPluginXxx = {}` 头；依赖靠 window 全局 | 仓库里绝大多数插件 |
| `esm` | 宿主 `manager.install({ url })` → fetch 文本 → `import(data:text/javascript)` | **自包含**：有顶层 `export`，且没有任何裸模块名 `import` | `plugin-cloud-client` |

打包最省事的写法是复用共享表 `packages/plugins/vite-plugin-lib.ts` 的 `pluginLibBuild`：

       // packages/plugins/plugin-xxx/vite.config.ts
       import { defineConfig } from 'vite'
       import vue from '@vitejs/plugin-vue'
       import cssInjectedByJs from 'vite-plugin-css-injected-by-js'
       import { pluginLibBuild } from '../vite-plugin-lib'

       export default defineConfig({
         plugins: [vue(), cssInjectedByJs()],
         build: pluginLibBuild(import.meta.url, { name: 'MiniCanvasPluginXxx' }),
       })

`package.json` 要补 `build: vite build` 脚本与 devDependency `vite-plugin-css-injected-by-js`；
改完依赖记得 `pnpm install --filter <包名>...` 连线，否则 vite 起不来（报 `Cannot find package`）。

哪些依赖必须 external（打进产物会造出第二份运行时）看 `vite-plugin-lib.ts` 的 `HOST_GLOBALS` 表，
ui 侧由 `packages/ui/src/sharedGlobals.ts` 对称地把同一批名字挂到 window。
注意 `HOST_GLOBALS` 里**没有** `@mini-canvas/plugin-*`（插件之间不共享实例）——
若你的插件依赖另一个插件包，默认**内联**是安全的；判断标准只有一个：
那份依赖会不会参与主画布的注册？会，就必须 external 并让宿主提供全局。

## 四、改完怎么验（按代价从低到高，够了就停）

1. **单包测试**（必做，秒级）：

       pnpm -C packages/plugins/<包名> test
       pnpm -C packages/plugins/<包名> typecheck

2. **看清单**：起 `pnpm -C packages/ui dev`，浏览器打开 `http://localhost:5288/plugin-catalog.json`，
   看目标插件在不在、`builtin` 字段是什么 —— 这就是面板会看到的东西。不起浏览器也行，用第六节的一行脚本。

3. **真机点一遍**（只有改了装载路径才需要）：设置 → 插件 → 本地清单 → 安装 → 画布上确认真能用。

只有这一个包相关的小改动，**不要**顺手跑全量 `packages/ui test` / `cloud-server test`（各要十几秒到半分钟）。
全量留给碰了共享层的改动：`catalogPlugin.mjs`、`vite-plugin-lib.ts`、`sharedGlobals.ts`、`pluginManagerService.ts`。

## 五、当前身份快照（2026-10-15 实测）

自带件（16 个，面板「自带」页只读展示）：

    agent / bottom-bar / clipboard / context-menu / edge-cutting / file-drop / group
    multi-select / node-3d-preview / node-audio / node-image / node-text / node-ui / node-video
    theme-default / plugin-manager

可装卸件（14 个，面板「本地清单」页可装卸）：

    align-arrange / align-guide / auto-layout / canvas-export / cloud-client / cursor-effect
    mini-map / node-find / image-compare / style-library / theme-gallery
    tool-image-generation / tool-text-generation / web2api-tools

既没声明 `builtin` 也没声明 `installable` 的（**不会**出现在任何面板页，属正常）：
`plugin-auto-save`、`plugin-history`、`plugin-hot-reload`、`plugin-shortcut-manager`、`plugin-showcase`。

> 组件展厅（theme-gallery）2026-10-14 从自带件改为可装卸件，是这份手册的第一个样例。

## 六、查清单速用脚本

跑在仓库根，输出每个插件的身份与是否已构建（不启动任何服务）：

    node -e "const fs=require('fs'),p=require('path');for(const n of fs.readdirSync('packages/plugins').sort()){const d=p.join('packages/plugins',n);if(!fs.statSync(d).isDirectory())continue;let k={};try{k=JSON.parse(fs.readFileSync(p.join(d,'package.json'),'utf8'))}catch{}const m=k.miniCanvas||{};console.log([n,m.builtin?'builtin':(m.installable?'installable':'-'),m.pluginName||'',fs.existsSync(p.join(d,'dist'))?'dist':'no-dist'].join(' | '))}"

列变成 `installable | 名字 | no-dist` 就是缺产物 —— 面板里不会出现它。

## 七、最容易踩的三个坑

1. **只改了 package.json**：面板分类对了，但可装卸件没有产物 → 清单把它标成没有 dist 直接不列，用户找不到。
2. **只加了装配清单**：声明还是 `installable` 却仍冷启动装配 → 同一插件两个身份，两页各一行。
3. **忘了 `INSTALLABLE_PLUGIN_DIRS`**：dev 下一切正常，一键启动（后台发界面）时清单里没有它 —— 只在生产暴露。

## 八、相关文件（改身份时按这个顺序看）

| 文件 | 作用 |
|---|---|
| `packages/plugins/<包>/package.json` | 身份声明（`builtin` / `installable`）+ `build` 脚本 |
| `packages/plugins/<包>/vite.config.ts` | 打 UMD 产物（可装卸件必需） |
| `packages/plugins/vite-plugin-lib.ts` | external 与全局名唯一事实源（`HOST_GLOBALS`） |
| `packages/ui/src/assembly.ts` | 自带件的冷启动清单 `APP_PLUGINS` |
| `packages/ui/src/sharedGlobals.ts` | 把共享运行时挂 window（与 `HOST_GLOBALS` 对称） |
| `packages/ui/catalogPlugin.mjs` | dev 下的清单与产物路由 |
| `packages/cloud-server/src/plugins/catalog.ts` | 生产下的清单（口径与上一条一致） |
| `packages/cloud-server/scripts/build-assets-parallel.mjs` | 一键启动的构建编排与目录清单 |
| `packages/plugins/plugin-manager/src/pluginManagerService.ts` | 面板的安装 / 卸载 / 重装（自带件的兜底拦截在这里） |
