# mini-canvas v2.0.0

这次重构只做一件事：让「同一份数据只有一个真相，同一个动作只有一个入口」。画布功能没有减少，但插件作者要记的名字少了一半以上。

## 基础服务：14 → 7

| 服务 | 现在负责 |
| --- | --- |
| `tools` | 外部能力注册表 |
| `doc` | 节点、边、事务、撤销、快照、订阅 |
| `selection` | 选中集 |
| `save` | 存储；`save.settings`、`save.autoSave` 是子对象 |
| `resources` | Blob / object URL 生命周期 |
| `view` | 节点几何 + 视口 + 唯一取景算法 `fitTo` |
| `canvas` | 建节点、选中、聚焦、模式、打组、提示、底栏动作、跑命令 |

另保留渲染层辅助服务 `nodeToolbar`（节点上下状态栏的会话与模式），不计入这七名。

## 注册场：17 → 11

保留 `command`、`node/shell`、`node/region`、`node/bar`、`selection/region`、`ui`、`capability`、`tool`、`clipboard/copy`、`clipboard/paste`、`media/creator`。

删掉 `node/type`、`node/creator`、`setting`、`theme`、`slot`，这五个在生产代码里没有任何读取方，真实数据本来就在 `doc`、`SettingsStore`、`ThemeRegistry`、`SlotRegistry` 里。`node/bar-applier` 并进 `node/bar` 的 `appliers/<kind>`。

## 取景：9 份实现 → 1 份

聚焦、定位、编辑态取景、分镜拖拽统一走 `view.fitTo`。差异由参数表达：`padding`、`heightRatio`、`keepZoom`、`zoom`、`onlyIfOutOfView`、`margin`、`includeBars`、`animate`、`durationMs`。

## 迁移对照

| 旧写法 | 现在 |
| --- | --- |
| `ctx.get('nodeLayout')` / `ctx.get('viewport')` | `ctx.get('view')` |
| `ctx.get('tip')` / `ctx.get('notify')` | `ctx.get('canvas').notify(...)` |
| `ctx.get('nodeFactory')` | `ctx.get('canvas').createNode(...)` / `creatableTypes()` |
| `ctx.get('command')` | 注册用 `ctx.commands.register`；执行用 `canvas.runCommand` |
| `ctx.get('nodeRegistry')` / `themeRegistry` | `ctx.nodes` / `ctx.theme`，或 `host.nodeRegistry` / `host.themeRegistry` |
| `ctx.get('settingsPersist')` | `ctx.get('save').settings` |
| `ctx.get('auto-save')` | `ctx.get('save').autoSave` |
| `ctx.get('pluginManager')` | `useCanvasRender().host.manager` |

这些旧名已删除，不会再以别名形式返回。

## 一并修好的问题

- 底栏同一节点重复执行时，旧任务会覆盖新任务的取消句柄。
- 定位节点在「已可见」后仍按 0.45 留白改缩放。
- `canvas.notify` 的 `followPointer` 默认值与文档相反。
- 底栏拖拽提示逐帧累积。
- `fitTo` 的 `margin` 单位按 flow 像素算，与契约要求的屏幕像素不一致。
- 可见剔除拿走 DOM 后真删除节点，实测尺寸残留。
